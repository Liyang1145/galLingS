## 正式与开发运行配置

### 入口与记录

| 入口 | 内容与页面 | 正常游玩记录 | 存储 |
|---|---|---|---|
| `game:dev` | 同一作者转换、原六项菜单，保留开发工具、限时样例和只读通关准备 | `development/normal-entry` | 当前开发浏览器的 IndexedDB |
| `game:build` 的浏览器包 | 严格随包读取，构建时移除开发区 | `game/main` | 当前服务来源的 IndexedDB |
| Windows 游戏宿主 | 只加载 `purpose: "game"` 的包，窗口名“海风与布丁” | `game/main` | 应用本地数据根的 `records/`，普通启动即启用 |
| Android `:rebuild` | 只加载 `purpose: "game"` 的包，启动器名“海风与布丁” | `game/main` | 应用私有 `files/records/`，普通启动即启用 |

`apps/game/src/main.ts` 用同一只读范围对象装配正常进度、周目/结局/CG/已读成果及四组偏好；它们仍各用原独立仓库和键，不因统一范围而合并成一份进度。所有声明初值章节试阅继续使用新内存已读和本页临时设置，不写玩家槽位/成果；限时样例仅在开发入口可达。

开发/正式选择由 `virtual:haifeng-content` 的构建期常量提供，不读取 URL、localStorage、玩家存档或页面开关。两端原生地址登记仅允许本作品 `game/main` 的进度及五种成果/偏好族，不开放开发或预览键。开发记录不复制、迁移或自动读取到正式范围，没有旧档兼容。

### 正式页面

游戏 HTML 中显式 `GAME_DEV_START/END` 区域只供开发入口；`game:build` 在 Vite 页面处理前移除。残缺标记或剩余开发入口使构建拒绝，不靠 CSS 藏按钮。主程序按同一构建期常量只接存在的面板/控件，正式页不构造剧情变量诊断，不开放限时样例、只读聊天准备或样例槽位目录。

存读档的正式目录只列正常游玩范围；选择、分页、原目标捕获、覆盖确认、写入/重试和语音选择流程不改。章节试阅的人工初值说明继续在游玩画面持续显示。六项标题入口、设置、回看、回退和正常退出保留已有机制，本片不为它们增加新能力或决定后置规则。

### 两端与失败边界

Windows 不再依靠 `--rebuild-file-records`，Android 不再读取 `rebuild-file-records` extra；宿主在加载前检查现有原生记录客户端能力并打开 `records/`，页面注入固定文件模式。打开失败不开始游玩，回执异常仍沿原未确认/原载荷重试处理；正式前端发现原生来源缺少文件接线时明确拒绝，不切换 IndexedDB。

普通浏览器仍可使用 IndexedDB，不据此增加网页离线安装/缓存承诺。宿主正常状态不在玩家画面显示文件后端、旧记录或试用说明，实际错误/警告仍可见。

桥 `/3` 中原 `windows-trial/android-trial` 平台标识及 `.rebuild` 应用/模块身份保持，它们是已有内部接口和构建定位，不控制运行档位，也不显示为试用标题。不为改名称重新设计宿主或版本号。

### 产物与兼容影响

游戏清单仍为 `haifeng.game-package/2`，`purpose` 明确改为唯一支持值 `game`。两端准备记录仍分别为 `/2`、`/3`，用途同为 `game`，`storage` 为 `native-files/game`；Android 构建拒绝试用用途或错误存储登记，原生和共享读取器均拒绝此前 `integration-trial` 游戏包。**统一测试时须按当前源码重新构建游戏包并重新准备两端输入**，不复用旧准备目录或已编译宿主。

进度、成果、偏好、预览、内部文件容器及原生桥载荷格式不变，原子提交/校验/CAS 算法不改；只将受限逻辑地址换为正式范围，并使用新的明确目录。没有读取、移动或删除试用文件/浏览器记录；旧作者源、3315 节点/选项/资源身份及素材不改。

“正式运行配置”表示启动档位已接线，不代表作品已签名发布或完整验收。现有安装器/签名/更新安排不由本片决定，也没有启用 CI、push 或发布。

### 当前交付范围

现有 DOM 应用已接随包启动和两端唯一宿主。2026-10-25 先完成[旧链路清理](<migration.md#retired>)，再按用户要求收尾[正式运行配置](<delivery.md#run-profile>)：`game:build` 只输出 `purpose: game` 的包，正常记录统一正式 `game/main`，移除开发 DOM/诊断/样例入口；`game:dev` 继续开发范围。两端默认现有原生文件后端，普通浏览器仍 IndexedDB。

构建入口是 `tools/game/build.ts`，只在显式执行 `npm run game:build` 时工作。它复用同一个分章作者源读取/编译器和唯一 TypeScript 核心；运行端不访问分章作者源、旧播放器、本机 `/@fs/` 资源或 Node 内容工具。

[外观装配](<player.md#appearance>)现从 `content/game-ui/whale.json` 读取原三个鲸鱼 SVG，游戏及已有共享预览继续用同一插件。图形字节进入前端，`content/sources.json.uiSkin` 记录当前定义文件摘要，保留原三个字段；新来源下 `blockSha256` 为按 menu/choice/dialogue 顺序构造的图形对象 `JSON.stringify` 摘要。新构建不再打开旧 HTML，不执行旧页面或复制旧脚本。

[声音收藏及操作栏装饰](<player.md#appearance>)从 `content/game-ui/collection.json` 读取原 11 个图标形状及原 B38 WebP 位置，通过游戏专用虚拟模块内嵌前端；不再解析旧 CSS 或播放器，不替换为剧情当前登记的改版图。`content/sources.json.uiCollection` 改记 `definition` 当前定义摘要、`backdrop` 原图片摘要和 `icons` 图标对象摘要/名称，原 `stylesheet` 及图标旧脚本位置由历史来源取代。

`content/game-ui/origins.json` 保留拆分时的提交、原文件/块及新定义摘要，构建作为 `uiOrigins: {file, sha256, record}` 写入同份来源文件，不重新读取旧文件核对历史。`targets` 是迁移时快照，当前字节由本次 `uiSkin/uiCollection` 登记。来源 JSON 属随包清单覆盖的不透明追溯文件，无运行端字段消费者；其格式标识、游戏包 `/2`、桥 `/3`、剧情修订及持久格式保持。以后外部追溯工具若读取旧 `uiCollection.stylesheet` 须改读 `definition` 和 `uiOrigins`。已有完整产物保留，不需要迁移玩家记录。

解除这三项构建依赖不等于旧链路已退出：原入口/播放器/样式继续保留，原 B38 图片和唯一剧情源仍有真实消费者。这里只说明资源拆分边界，当前构建和验证范围见项目总览。

原[Windows](<delivery.md#native-storage>)及 [Android](<delivery.md#android-storage>) 文件后端继续复用 `assets/native-record-client.json`、共享桥和 TS 适配器；客户端/可选记录协议仍 `/1`，能力文件仍由前端清单登记。本次只将两端启动固定为原生文件，取消试用参数选择；缺失/不匹配能力拒绝，不回落浏览器记录。随包 `/2`、基础桥 `/3`、持久格式不改，未执行构建或准备。

### 两条内容接入

`virtual:haifeng-content` 现在提供异步 `loadContent(signal?)`：

- `game:dev` 保留本地转换器提供的可信数据及开发资源位置，没有改用未校验 JSON。
- `game:build` 的 Vite 插件只接入 `packages/player/src/web/package.ts`。浏览器从当前游戏包目录读取 `game-package.json` 和剧情 JSON，经严格读取器校验后才启用开始与鉴赏入口。

随包加载核对剧情文件的大小、SHA-256、作品、内容修订、资源身份和来源路径；内容修订仍使用 M1 的同一规范化算法，不因安装目录改变。读取失败显示诊断和重新读取入口，不开始会话、不切换解释器，也不联网补资源。

相对位置由清单中的包内路径逐段编码后解析到当前包目录。路径不得含绝对位置、上级跳转、协议、查询、片段或预编码；读取拒绝重定向。加载任务在离开页面或开发热替换时取消，过时启动不接管页面。

图片、语音、音乐和环境声仍由共享表现按需读取；启动时不下载并解码全部素材。运行端启动校验不是全媒体验收，也不是安装时逐文件校验的替代：清单保留每个资源及前端文件的摘要，未来宿主安装与激活流程应消费这份清单。

### 只读完整包核验

`tools/game/package-input.ts` 集中原两端准备已使用的只读边界：严格清单读取、目录摘要、已登记剧情字节、作品/资源身份及同一内容修订算法。`prepare.ts` 继续负责独占输出与复制，原 `repository/sha256` 导出、平台命令和准备格式保持兼容；没有新增游戏包、内容或宿主协议。

核验命令随后逐个读取来源、前端、剧情和全部登记素材，核对实际物理位置、普通文件、字节数及 SHA-256。重复素材位置只读取/统计一项物理文件，不合并或重新分配资源 ID；总字节数包含原清单，溢出安全整数时明确失败。缺失、越出包内、非普通文件或摘要不一致返回带相对文件位置的诊断，首个失败即停止，后续未读文件不冒充已经核验。结束前还会重读原清单，读取期间清单改变则拒绝本次结果。

成功输出仅说明本次逐个读到的登记字节与该清单一致，并列出作品、内容修订、物理文件数/总字节、节点数及资源 ID 数；不保证整个目录在同一时刻的原子快照，也不保证随后没有外部修改。它不检查额外未登记文件、不授予删除权限，也不代替媒体解码、路线、素材授权、签名或安装/平台验收。

Windows/Android 准备仍独立打开原游戏包，并在每次复制前通过同一读取函数重新核对原件；先前命令成功不能让后来复制跳过校验。当前入口只支持固定的本机游戏构建产物，尚未接用户设备上的安装、更新或激活流程，不据此宣布完整离线发行完成。

### 产物结构与身份

未来命令成功后输出 `dist/game/<产物摘要>/`：

```text
index.html
assets/                    Vite 生成的脚本与样式
content/story.json         规范化剧情，保持节点、选项及资源数组顺序
content/sources.json       作者来源、固定选项映射摘要及资源来源元数据
media/<文件摘要>.<扩展名>  随包素材；相同文件可共用位置，资源 ID 保留
game-package.json          完整游戏集成清单
```

当前清单是 `haifeng.game-package/2`，要求 `hostBridge: "haifeng.host-bridge/3"`，唯一用途为 `game`。这是内部接口及正式运行档位，不是作品发行号或验收结论。清单还记录 `shared-web`、作品/修订、剧情/来源/素材/前端、Git/工作区、锁文件和工具版本；目录名是清单摘要。此前 `integration-trial` 用途明确拒绝，必须重新构建并准备，不迁移玩家记录。

音频焦点和状态确认接入后，旧 `/1` 游戏包明确拒绝，须重新 `game:build` 并按对应平台重新准备；不将新宿主与旧准备目录混用。Windows 准备记录使用 `/2`；Android 文件试用装配增加记录桥模板及其摘要，准备记录现为 `haifeng.android-preparation/3`，旧 `/2` 输入须重新准备。两端均登记基础桥协议；规范化剧情、内容修订算法、进度及全局记录格式不因此升级或迁移。

正常退出协调进一步要求桥 `/3`，旧桥 `/2` 的包也须重新构建和准备；保持游戏包清单 `/2`，通过 `hostBridge` 字段明确拒绝接口不匹配。能力与限制见[退出说明](<storage.md#exits>)。

原作者路径留在来源记录中，运行位置单独映射到 `media/`。资源 ID、节点 ID、顺序、变量、选择、结局与停奏不会因为文件装包位置变化而改写。所有登记资源进入本片产物，包括当前鉴赏与后续界面可能消费的资源；制作素材库和历史来源目录不整包复制、不移动或删除。

来源元数据按作者输入保留，并不表示素材授权已核验。没有新增当前设备绝对路径、凭据或私人设置到清单；不复制 `.env`、开发 public 目录、源映射或旧解释器。

### 写入与失败保护

构建先由内容工具读取实际来源文件及摘要，复制时重新核对字节。缺失、越出作品目录、特殊路径或复制期间变化会失败，不从网络替换。

Vite 使用显式配置与相对 `base`，不加载其他 Vite 配置或 `.env`。前端、剧情、来源与资源先写到经过物理路径检查的 `dist/game/.building-*`；全部完成并通过清单结构核对后，再提升为独立产物目录。同一内容修订的并发命令用独占锁目录互斥，已有产物目录明确拒绝覆盖，旧产物保留。

失败清理只针对本次创建的临时目录；递归移除和移动前检查实际绝对路径及输出边界，不接触作者源或原素材。已有锁不会被擅自删除；进程被强制终止留下的锁或临时目录需另外处理，不能声称已经具备自动恢复能力。

这是编写在未来显式构建命令中的保护逻辑，本轮没有执行这些操作或故障验证。

根 `tauri.conf.json` 使用现有宿主身份 `com.gallings.haifeng.rebuild` 及受限能力/CSP，移除 `dist/desktop` 资源映射和旧 NSIS 默认配置，不默认生成安装包。基础 `frontendDist` 仍是明确提示的占位目录，不含游戏清单；仅按基础配置生成的壳不能作为可玩内容启动。实际游戏必须先由 `windows:prepare` 提供完整前端及生成配置，缺失清单/能力仍诊断拒绝，不回读旧来源。

新入口只加载已准备的共享前端，通过 Tauri 本地 HTTPS 资源地址提供包内文件；不启动或探测 Python 服务、不注册旧 `/__host/` 接口、不加载 WASM 解释器，也不在故障时回落旧实现。页面仍使用相同的 TypeScript 剧情核心和共享播放器。

当前采用前端与素材一同嵌入可执行文件的集成路径，用于先接通既有宿主，不作为最终资源分包、安装和分发方式的决定。新窗口拒绝远程页面导航及额外窗口；没有接聊天、旧原生接口或通用原生调用。后续显示扩展仅接布尔全屏目标，见下节。

### 输入准备

`tools/game/windows.ts` 提供 `npm run windows:prepare -- <产物摘要>`，仅接受 `game:build` 输出的摘要目录：

摘要读取、内容修订及登记文件核对集中在 `tools/game/package-input.ts`，`tools/game/prepare.ts` 供两个平台复用输出/复制；Windows 命令、原导出与目录约定保持不变。另有[只读完整包核验](<delivery.md#delivery>)供显式检查已有游戏构建产物，准备仍在复制时重新校验，不能采用先前结果跳过原件读取；本轮均未执行。

1. 严格读取随包清单，核对目录摘要，读取剧情并重现内容修订。
2. 按清单逐个核对前端、剧情、来源及素材文件的大小和 SHA-256；读取位置必须位于该游戏包内。
3. 只复制清单登记文件到独占的 `dist/windows/<产物摘要>/frontend/`，相同素材位置只复制一次；不扫描并带入其他文件。
4. 完整复制后写入 `tauri.rebuild.conf.json` 及 `preparation.json`，记录输入摘要与集成用途。配置只启用 `custom-protocol` 本地前端协议，嵌入已准备内容，关闭安装包生成。

同一目录存在时拒绝覆盖。准备失败保留本次不完整目录和诊断，不自动删除或重新利用；不能把目录存在当成成功。准备成功后也须保持目录原样，后续编译不是对被手改输入的再次安装校验。Tauri 编译还会处理页面注入等内容，输入清单不等同于最终 EXE 的字节清单或签名。

`frontendDist` 使用相对于 `desktop/src-tauri` 的 `../../dist/windows/<摘要>/frontend`，按当前准备目录重现并核对；Tauri 优先将字符串解析为 URL，不能使用 Windows 盘符绝对路径，否则可能只编出没有嵌入资源的壳。配置只存在于忽略的 `dist/`，不得提交。没有改依赖版本或重新解析锁文件，锁文件仅同步移除桌面根包已不用的直接依赖项。准备命令不调用 Cargo、不编译，也不启动游戏。历史绝对前端路径或带 `rebuild-host` 的生成配置须重新准备，不能手改旧快照；准备记录仍为 `/2`，新内容由原配置摘要覆盖。

### 窗口生命周期与会话

`packages/player/src/web/host-bootstrap.js` 是两端原生共用的最小状态桥，当前是 `haifeng.host-bridge/3`，Windows 在原生包含时替换平台标记。它公开 `read()` 快照；原生在页面加载完成、窗口焦点和尺寸变化时报告 `haifeng.host-state/1`，并每秒重采窗口状态。消息含平台、递增序号及暂停状态；初始化时先暂停，收到有效窗口状态后才恢复。失焦或最小化均暂停，原生读取窗口状态失败也报告暂停。

页面返回接收序号，原生校验确认并记录投递诊断；周期重采负责后续重试，销毁时停止任务。页面每秒检查宿主状态，超过 3500 毫秒没有新的有效序号则暂停并关闭声音，等待新快照。重复事件或旧确认不能刷新状态时效；这些参数只用于当前集成实现，没有执行故障或后台节流验证。

原生还在创建窗口前检查嵌入清单的 `haifeng.game-package/2` 及桥协议；不符合则拒绝启动。旧游戏包、准备目录须按新命令重新生成，不能继续复用旧 `/1` 产物。Windows 不经过 Android 焦点请求通道；后续独立输出许可仍与浏览器播放权限/媒体诊断并用，不申请独占焦点。

`apps/game/src/platform/host.ts` 校验桥和消息，桥侧忽略过期消息，读取侧发现缺失或无效消息则显示诊断并暂停；普通浏览器继续使用原有标签页生命周期。状态桥不接收剧情命令或变量，不承担存档操作。

应用把宿主状态接到会话 `host` 原因，网页隐藏仍使用独立 `background` 原因；菜单、回看和媒体暂停也分别保留。读档及回退的准备改用 `operation` 原因，不能因准备结束而解除原生窗口暂停。

会话新增可选 `initialPauses`，只接收当前 `host/background` 状态，在首次呈现前生效。开局、读档或重开时重新采用当前生命周期状态；窗口恢复只更新暂停状态，不进入节点、不补算后台时间、不重置选择计时。

焦点和最小化之外，后续已编写下节的独立休眠/唤醒通知。Windows 声音输出监听及许可/回执已接入装配。

### 系统休眠和唤醒

微软文档规定该登记接口面向 Windows 8 及以上桌面应用；这里记录真实接口能力，并未据此承诺游戏最低系统或通过相应设备验收。动态探测只让缺少能力的系统有明确失败路径，不提供旧系统替代实现。该电源接口的准备格式、随包 `/2` 及基础桥 `/3` 保持；旧宿主已按清理授权删除，仍需在统一测试阶段编译当前宿主源码。

| 系统事件 | 原生状态与交付 |
|---|---|
| 休眠预告 | 记录暂停和新的中断代次，唤醒已有宿主状态线程尽快投递暂停 |
| 自动唤醒 | 保持等待交互恢复，并产生新的中断代次；不能仅因窗口仍为焦点而恢复 |
| 交互恢复通知 | 更新为已恢复，但仍等待本页桥接受该中断代次的暂停回执，以及窗口焦点/最小化条件允许 |
| 紧急恢复、计数耗尽或内部状态异常 | 保持暂停并记录诊断，不能以默认值伪装恢复；须停止后重新启动 |

休眠和唤醒都保留独立代次。即使两个通知之间 WebView 没来得及执行，唤醒后的原生状态仍要求本页桥先接受暂停，不会只看到最终“已醒来”就跳过整次中断。暂停采样与宿主序号分配在同一短锁内完成，旧采样不能取得比后来中断更新的序号；页面继续用原桥拒绝乱序状态。

原每秒状态线程增加通知唤醒，不新建剧情计时器；有效页面的暂停接收回执也可唤醒线程重新采样。回调只更新同步的内存状态并发出唤醒，不等待 WebView、做文件 I/O、自动保存、阻止系统休眠或执行剧情。焦点/最小化与电源条件合成原 `host` 暂停；菜单、后台、回看、操作准备及媒体原因仍由原会话分别持有，不由电源恢复一并清除。

这里确认的是**本页桥已接受暂停状态**，不是保存成功或核心步骤已完成的收据。系统通知与脚本送达的先后、正常休眠剩余时间和媒体接续仍须真实设备验证；未及时收到预告、紧急断电/系统冻结/进程强杀不在正常通知保证内，不以唤醒后的时长倒算、撤销已提交选择或伪造恢复点。本片没有实现新的时钟协议或进程回收恢复。

#### 页面身份和清理

Windows 初始化脚本为每个本地主文档生成私有只读身份，独立于可选全屏/文件记录能力，不进入存储。载入完成后先读取并核对该身份，再登记本次页面代次；读取失败保持未就绪，已有状态线程可继续尝试。每条宿主状态脚本核对原身份，原生回执再核对页面代次/就绪及中断代次，旧页面排队脚本、回执或旧中断不能解除新页面的暂停。缺少可选全屏扩展仍不阻断基础状态。

窗口销毁先停止状态投递、清空页面绑定、标记电源监听停止并唤醒线程；线程退出时注销原登记。回调参数及其空上下文保留进程生命周期，迟到回调不持有窗口、页面或已释放的堆对象。注销未确认时保留系统模块引用到进程结束并报告错误，不卸载仍可能被使用的模块，也不把失败当成正常退出写入许可。登记期间到达的通知不被成功返回时的初始化覆盖。

### 声音输出监听后端

`Monitor::open/inspect/wait` 及释放须在同一专用 MTA 工作线程内执行；原始 COM 指针使监听对象不能跨线程移动。它只查询系统现有的三个播放角色默认端点及活动状态，不激活声音流、采音、修改默认设备或读取玩家数据。可跨线程传递的 `Wake` 只读变化代次、唤醒或取消原监听，不能选择设备或发剧情/存储操作。取消先阻止新回调读取，实际注销仍在原线程执行；许可层持有原页面/请求身份，监听对象不进入 WebView 界面线程。

对外 `Inspection` 只有变化代次、是否存在活动默认播放端点、本次读取是否稳定；稳定要求读取前后未观察到新的相关通知。它既不是浏览器播放许可，也不是某次恢复请求成功的回执，不自动恢复、暂停会话或授予播放。代次耗尽、无效返回、设备读取失败和不支持状态明确报错；缺少某一角色的默认端点只按原 API 的明确“不存在”结果处理，不把其他异常当空列表。多个角色使用同一端点时内部去重，不解析或重造设备身份。

#### 回调和身份

- 默认播放角色变化产生新代次，录音角色变化不采用；当前默认播放端点的状态变化或移除同样产生新代次。新增但未成为默认的设备、普通属性变化不改变播放许可。
- 系统设备 ID 按不透明、完整 UTF-16 原值比较，不解析其结构、按名字/下标匹配或输出给页面/日志。内部字符串以 4096 个 UTF-16 单元为当前实现上限，超限/非法值拒绝，不裁切成另一个身份；没有进入持久记录或产物。
- `IMMNotificationClient` 回调只访问原子状态、借用已发布的不可变身份快照并发出事件唤醒；不等待锁/工作线程，不查询 COM、不创建字符串或注销/释放最终引用。读者计数保护旧快照，替换和等待旧读者完成均在工作线程执行，不让回调等待。
- 每次相关通知递增代次，即使多次通知合并成一次线程唤醒也不会据最终可用状态假定中途没有变化。默认角色的多次回调可以分别递增代次，不将该数字当作设备数量或剧情次数。
- 输出代次的原子更新也无锁唤醒原宿主采样线程；它可先按中断状态投递，不必等声音线程完成 COM 查询。额外唤醒提示不改变电源中断持有，也不是许可/消息身份；原周期采样仍保留。

#### 生命周期与后续接点

回调对象保留独立拥有引用和登记期引用；注销确认后才释放，系统枚举器先于 COM 线程环境释放。注销失败或未确认时标记停止、保留原生对象/信号资源到进程结束，迟到通知不再推进代次；不释放仍可能被系统借用的对象或把异常清理当成许可。系统返回未支持的成功类状态也不冒充已登记。

接口由固定的最小 C ABI 声明接入，没有新增依赖、安装 SDK、生成绑定或变更 Cargo 锁；私有对象/字符串未暴露到通用宿主接口。当前 Rust 文件只有显式构造才会接触系统声音，导入模块不登记监听。源码读取依据为[微软 MMDevice 接口](https://learn.microsoft.com/en-us/windows/win32/api/mmdeviceapi/nn-mmdeviceapi-immnotificationclient)、[登记及引用所有权](https://learn.microsoft.com/en-us/windows/win32/api/mmdeviceapi/nf-mmdeviceapi-immdeviceenumerator-registerendpointnotificationcallback)、[注销及回调约束](https://learn.microsoft.com/en-us/windows/win32/api/mmdeviceapi/nf-mmdeviceapi-immdeviceenumerator-unregisterendpointnotificationcallback)和[微软 SDK 头文件](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/mmdeviceapi.h)，不是代码审查或运行结论。

许可接线见下一节。设备变化不能自动把后来出现的设备视作旧请求目标；本页许可及明确重试复用共享表现和原暂停，不能以此新设解释器、静默写入或决定正式平台默认。

### 声音输出许可与原请求确认

`tools/game/build.ts` 在前端清单收集前写入 `assets/windows-audio-client.json`，格式 `haifeng.windows-audio-client/1`、协议 `haifeng.audio-output/1`，由现有清单摘要覆盖。**新编译 Windows 重构宿主要求它已登记且内容匹配**；旧游戏包须显式重新 `game:build` 和 `windows:prepare`，不静默降级为旧请求通道。随包仍 `/2`、Windows 准备仍 `/2`；Android 可复制该普通文件但不启用 Windows 驱动，其声音通道不改。新前端在没有此扩展的旧 Windows 宿主中保留原基础桥行为，不借此增加通用原生操作。

#### 许可与中断

首次初始化读取稳定且存在活动默认播放端点时，保留原 Windows 的初始获准状态；没有输出或初始监听不可用则报告未获准，主线仍可静音继续。这个原生结果不代替浏览器的播放手势/解码许可，实际播放继续由共享混音器及原“启用声音”操作处理。

已获准播放时观察到输出变化即为 `interrupted`，同时关闭声音许可并合入原 `host` 暂停；窗口焦点、电源、菜单、后台、回看和操作准备仍分别保留。后来出现可用设备不自动授予许可，静音/未请求状态也不会只因插入设备而自动开始播放。现有声音收藏实例按原暂停/许可机制接续，关闭仍取消；没有实例的失败试听及已经跳过的一次性声音不排队补播。

用户显式发起原“启用声音”请求时捕获原页面身份、请求 ID 和已观察输出代次。工作线程处理前/后核对同一页面及当前请求，重读默认输出并确认查询期间稳定且代次仍匹配；任何后来变化均拒绝原授权，不把新设备换成旧请求的目标。无输出或显式重试仍不可用时返回未获准，可静音继续；异常中断尚未确认时不冒充已恢复。

Windows 不取得 Android 式独占焦点租约；本页已确认且未中断的许可不因正常返回标题/关闭已完成试听而无端撤销。离开未完成请求则用原释放意图取消候选许可，页面换代清空原请求并撤销旧页请求带来的许可；新页须重新请求，不以旧页迟到授权接管新页。设备输出选择、录音或系统音量没有开放给页面。

#### 请求、回执及关闭

- 页面最多保留一个原请求，原生只保留当前页最新原载荷及其确认，工作线程队列容量为一。重复同 ID/同载荷只复用原结果；同 ID 不同载荷、旧页/旧请求不采用。后来请求或释放使旧在途结果失效，队列未交付明确返回问题，不自动补发。
- 原生状态含独立序号及变化代次，按本次私有页面身份投递；页面同时拒绝旧序号和倒退代次。原初始化只允许本地顶层来源，严格核对字段、数字、状态及原回执身份，没有端点 ID、路径、设备选择或存储动作。
- 页面只有首次初始化许可或本次原请求/原代次的成功回执才能采用新授权。8 秒等待超时保留限制并允许显式新请求；超时或旧请求迟到的 `granted` 不恢复声音。释放可立即限制本页声音，不需等待原生来撤回播放；原请求目标不因此改绑。
- 应用适配器复用现有 `readAudio`，中断立即参与暂停，未请求/未获准仍可静音推进；Windows 输出诊断与待确认提示通过现有宿主提示区显示。没有改存档、全局成果、偏好、语音恢复选择或有效计时格式。
- 窗口销毁先停止接收/投递，唤醒声音线程，在原线程退出时注销监听并释放正常对象、事件及私有身份；注销未确认保留对象到进程结束。页面关闭取消本页计时/候选请求，旧释放/确认不能重绑新页。正常退出仍只按已有玩家写入协调，不用声音确认授予关窗。

### 内部物理容器与提交

内部文件格式为 `haifeng.native-record-table/1`，包含作品、存储提交代次和各独立逻辑键/值。它是物理提交容器，**不是一个游戏检查点、成果快照或可直接导出的存档**；不能用某个进度槽位的旧值整体覆盖它。内容修订、核心步骤、存档版本、宿主桥 ABI 与本容器代次互不混用。

受信任宿主从已准备清单取得作品身份，固定使用应用本地数据根下的 `records/`，与 `webview/` 分开；不迁移或删除先前试用目录。页面不能指定目录。普通目录/文件、重解析点拒绝、目录独占锁和进程内串行规则保持。

每次提交按以下顺序：

1. 独占/串行范围内重新读取最新容器，核对格式、作品、代次及有界地址。最新提交损坏或不兼容时明确拒绝，**不自动取前一版本、不初始化空表**。
2. 进度仅替换指定地址，其他逻辑记录保持。成果/偏好先比较存储代次；冲突返回当前代次、不写文件，TypeScript 随后重新读取并运行原验证/合并。
3. 在内存中完整编码新容器后才创建独占、不可覆盖的 `pending-…tmp`，完整写入并 `sync_all()`，关闭文件句柄。
4. 使用同目录的 `MoveFileExW` 转为新的 `records-<20位代次>.json`；只设置 `MOVEFILE_WRITE_THROUGH`，不允许跨卷复制/删除或替换已有提交文件。成功返回后才报告提交，原已提交文件在此之前不被删除或重命名。
5. 提交后仅尝试清理已验证属于本作品/格式的较老完整容器，保留当前及上一提交。清理失败作为本次提交警告，不能改报写入失败；未提交临时文件保留并报告数量，不读取其内容作为存档。

读取选择最高提交文件名并核对内部代次；零代次仅是还没有任何提交的初始状态。只有临时文件而没有提交时，逻辑记录仍不存在，但返回未提交文件警告。未知文件、重复记录键、超限和损坏的最新容器都不是“无存档”。

记录载荷用 `RawValue` 保留原 JSON，避免把有效 UTF-16 转义先转换为 Rust 字符串；请求中的原操作也直接从原 JSON 读取，不通过会损失原样数据的中间缓冲。回执先序列化完整 JSON 文本，再作为引号字符串交给页面 `JSON.parse`，不把剧情文本或记录字段拼成可执行 JS。

损坏的单条领域载荷仍保留原值，交给 TypeScript 仓库诊断，不猜字段或清空成果。无键与存在的 JSON `null` 分别返回 `found:false` / `found:true,value:null`。同一后端及页面适配器拒绝已观察的存储代次倒退，CAS 预期大于实际代次也明确报错，不据旧容器覆盖记录。

以上为已编写顺序，未做故障或设备确认。不承诺断电物理落盘、磁盘/文件系统故障修复、网络盘语义、用户手改后的修复或系统回收自动恢复；临时文件和旧容器不是玩家槽位，不能据其存在宣称一次保存成功。

### 接口与试用限额

| 内部方法 | 行为 |
|---|---|
| `open(root, work_id)` | 受信任原生调用打开独立目录并持有独占锁，不读浏览器数据库/旧存档 |
| `read(key)` | 返回存储代次、存在/缺失的原值及临时文件警告，不采用到会话 |
| `scan(prefix, after, limit)` | 仅正式登记进度范围，1～100 条，返回原键/原值/续页地址及警告 |
| `replace_progress(key, value)` | 仅进度替换；核对地址/封装种类，保留其他逻辑记录，完整提交才返回 |
| `compare_exchange(key, expected, value)` | 仅成果/四组偏好；代次冲突不写，成功不执行剧情或合并规则 |

存储代次为 0～JavaScript 安全整数上限，耗尽拒绝。试用限额为单条 JSON 2 MiB、容器 32 MiB、4096 个逻辑地址、目录 4096 个文件；超限明确报错，不截断或清空旧槽位。这是未调优的实现边界，不是正式容量承诺。

错误带 `NATIVE_STORAGE_*` 类别和原因，警告不得由后续桥/UI 静默丢弃。接口不返回真实机器目录、句柄、通用操作或可写记录表；同步磁盘方法不得在 UI 线程直接执行。

### 请求、确认与不确定结果

Windows 主页面固定本页选择及随机身份，通过受限 `__HAIFENG_RECORDS__` 发出 `haifeng.native-record-request/1`。请求含作品、身份、单调 ID 及 `read/scan/replace/cas` 四种操作；没有路径、URL、脚本、删除或其他宿主指令。页面就绪确认核对作品/协议，原生再核对主页面来源、原页面加载代次、身份、ID、字段、容量及后端地址。

独立工作线程一次只执行一个观察到的队首，不在 UI 线程做文件 I/O。相同页面/ID/载荷重投只发送缓存的原回执，编码或投递重试不能重新执行文件操作；旧 ID 或改变载荷拒绝，原页面换代不把回执送给新页面。已经开始的文件操作仍可完成，取消页面只限制后来执行/回执采用，不撤销已开始的事务。

桥最多排队 32 个后续请求，队首等回执 12 秒。超时报告 `NATIVE_STORAGE_UNCONFIRMED`，保留原队首、阻止后续发送，并拒绝尚未发送的排队请求；后续不能越过未确认的原操作。原回执迟到后释放通道、显示需查看或显式重试，已拒绝的 Promise 不再改成成功，也不自动执行已拒绝的后续请求。重复/旧回执不改变当前队首或其错误状态，匹配的新回执才确认本次结果。

**已确认的存储事务失败仍保留旧提交；确认丢失不能当作已保存，也不能声称肯定没有写入。** 无效写入回执同样按未确认处理。原操作暂留内存，退出协调不能据此关闭；显式重试复用原载荷，进度替换幂等、全局事实仍由原批次 ID 去重。存档/成果提示采用“未取得保存确认”，不把通信异常显示成旧槽位肯定没变。

请求上限 3 MiB，单条载荷仍为 2 MiB；目录回执按约 3 MiB 预算收短页，续页定位到最后实际返回地址，不漏过未返回条目。回执再作总量校验。最多 15 条详细警告及一条额外计数说明，避免无界传输；正式页面展示实际警告及通道问题，健康后端不显示来源说明。显示异常不能把原生已确认提交改报失败。

### TypeScript 适配与剩余事项

同一页面只创建一个所选存储，交给现有进度、成果及四种偏好仓库。`NativeRecordStore` 实现原存储接口，严格核对存在标记、回执种类、存储代次、分页顺序与续页；CAS 冲突最多重读 8 次，每次重新执行原领域回调，不能按旧值盲写或由 Rust 重做规则。异常不返回默认空记录，不回落其他源。

页面离开/销毁清理状态监听与后续请求许可，已开始写入继续遵守原归属；存档面板的原操作句柄、关闭显示失效、全局幂等与正常退出等待均复用现有流程。正式落点已接为应用本地 `records/`，IndexedDB 不导入、迁移或覆盖；没有旧档兼容。

Android [文件后端](<delivery.md#android-storage>)已同步接为普通启动默认文件，准备记录 `/3` 核对共享记录桥摘要及正式用途，Windows 准备仍 `/2`。两端均。原试用包须重新构建/准备，不能将能力文件存在当作设备验证。

### 随包媒体范围读取

2026-10-25 从 `25c71dc` 接续。原 `AssetsPathHandler` 调用只接收 URL，没有将请求头交给本体自己的媒体响应。`PackagedMedia.java` 启动时只读当前清单 `resources` 中的物理位置、长度和摘要，固定媒体目录及原摘要形状；同一文件可对应多个资源 ID，但重复物理位置的大小和摘要必须一致。WebView 的流长度探测使用 Java `int`，单个媒体超过 2147483647 字节明确拒绝，不能截断登记长度。它不读取作者源、重新解释剧情或合并资源身份。

本地主入口范围内的 `media/` 请求交给该读取器，未知位置返回本地 404，不再交其他目录处理。完整 GET 返回 200；不带范围的 HEAD 只返回元信息，不发送媒体正文。单段 `bytes=start-end`、`bytes=start-` 及 `bytes=-suffix` 返回 206、准确的 `Content-Range`、`Content-Length` 和 `Accept-Ranges`。端点超过文件尾时截到登记长度；起点越界、零长度后缀及空文件的有效范围返回 416 和 `bytes */长度`。十进制先比较再饱和计算，不能溢出或把逆序两端误当可满足范围；WebView 自己在进入响应流前拒绝的畸形范围仍表现为请求失败。

原生读取器对未知单位、无效/过长或多段范围选择完整 200，不猜第一段；具体 WebView 仍可能先拒绝畸形请求。设备验证发现 WebView 对拦截响应仍会自行解析原 Range、计算长度并定位，因此带 `If-Range` 或带 Range 的 HEAD 明确返回 400，不伪造条件匹配或返回长度错误的完整表示。每份响应继续由 Activity 附加 `no-store/nosniff`，不新增缓存、网络权限或 HTTP 接口版本。

素材从 APK 通过 `AssetManager.open(..., ACCESS_RANDOM)` 读取，既可使用原未压缩项，也可处理压缩项，不要求把素材解包到用户目录。每次请求只持有自己的输入流，先移到范围起点，再限制正文读取；流在首读前向 WebView 提供原表示长度，并确认一次相同起点的原生定位而不再次跳过字节，避免非零范围被重复定位。HEAD 使用无正文的元信息流，避免 WebView 再附加错误的零长度。后续实际读取及跳过不越过本段，没有 Java 层整文件缓冲或临时写入。WebView 关闭正文时释放原流，构造失败也清理；提前结束明确失败，不补零或换源。压缩定位性能仍须真机确认。

这层只提供本地字节，不设置 `currentTime`、重发语音、改变音乐继续/停奏、重入节点或决定剩余有效时间；共享混音器仍独占位置捕获及恢复。登记摘要仅用于检查重复登记一致性，本片不逐请求重新计算媒体摘要，也不将声明长度当作 APK 已校验或解码已通过的证明。

没有改游戏包 `/2`、准备 `/3`、宿主桥 `/3`、存档/成果/偏好格式、默认存储或原 `:app`。只需将本次宿主源码纳入未来统一 APK 构建；本轮没有准备、Gradle、类型检查、测试、模拟器/设备操作或运行验收。

### 生命周期和返回键

两端共用 `packages/player/src/web/host-bootstrap.js`，当前接口是 `haifeng.host-bridge/3`；状态消息仍使用 `haifeng.host-state/1`。桥缓存单调序号的窗口状态，提供本页返回键、受限音频焦点请求及正常退出协调，不暴露文件、网络或剧情指令。游戏清单使用 `haifeng.game-package/2`，原生、页面和 Gradle 准备记录均拒绝旧协议，旧准备目录需要重新生成。

Android 在 `onPause/onResume`、窗口焦点和页面完成时发送当前综合暂停状态。页面启动先暂停；会话通过既有 `initialPauses` 采用当前状态，窗口恢复只解除 `host`，不解除菜单、后台、回看、加载或操作准备的暂停。没有墙钟补算，不重入节点或重放进入动作。

应用返回键处理顺序：

1. 已有退出请求时取消本次票据。
2. 关闭当前对白回看、主页鉴赏或通关后面板；回看只解除自身暂停。
3. 界面隐藏时只恢复显示。
4. 游玩中打开或关闭菜单；原生全屏模式不改变此顺序。
5. 标题页交回原生，沿用旧宿主连按两次退出的试用方式；提示进度须先手动保存。第二次返回先走本次退出票据，已有手动写入及全局事实提交完成才结束 Activity，失败可重试或取消，超时保留应用，见[退出协调](<storage.md#exits>)。

返回键不模拟点击、下一句或选择；原生等待本页处理结果时防止重复请求，回调核对页面代次，旧页面结果不能关闭新页面。缺失或无效处理结果给出提示，不据此退出。当前显式关闭预测返回回调，使用既有 Activity 返回入口；正式手势体验尚未验收。

原生投递现在要求页面返回当前序号，单次最多尝试三次，每次等待 250 毫秒；页面、WebView 实例或当前序号变化时丢弃旧任务。前台每秒发送新快照，暂停时停止周期任务但仍投递暂停消息。连续失败显示原生提示，页面侧每秒检查宿主状态是否超过 3500 毫秒未刷新，超时则暂停并关闭声音；只有新的有效序号才能刷新时效。恢复有效状态只解除宿主自己的暂停，不补算错过的剧情时间。这是内部试用参数，未做后台节流、丢包或系统挂起验证。

### 音频焦点

应用沿用已有播放/启用声音操作，通过只允许本地主框架的消息通道请求焦点。设备验证发现 WebView 开始播放时会用自己的焦点申请打断原生常驻申请，因此 `GameAudioFocus.java` 的原生申请现仅探测许可：API 26 起采用 `AudioFocusRequest`，较低系统采用既有接口，获准后先释放探测申请再发布许可，由 WebView 持有实际播放焦点。通道只识别请求、释放及共享混音器的中断/恢复常量，不接受脚本、变量或路径，没有新增依赖。

未请求或未获准时，共享混音器保持声音关闭；请求被拒给出可重试提示，主线仍可静音继续。不可播放的当前语音不会使自动阅读永远等待；当时不能播放的一次性音效会丢弃，不在稍后获准时补播。持续音轨和当前句重试仍由原混音实现拥有，不重新进入剧情。

共享混音器为自己发起的暂停逐次计数，菜单、后台、许可关闭和销毁不能冒充外部中断；自然结束及媒体错误也不作为焦点丢失。其余未预期的媒体暂停通过本页桥报告原生，沿现有宿主暂停及声音许可通道处理中断，不改变音量比例。原受中断轨道重新实际播放时才报告恢复，原生仍核对前台、窗口和未确认输出中断；永久丢失可点击“启用声音”重试。后台、回标题、页面重载或销毁释放声音会话；返回前台只在此前请求过声音且没有待确认输出中断时重新探测，旧申请回调由代次拒绝。系统临时焦点自动恢复及真实设备中断仍须分别验证。

焦点状态使用独立的 `haifeng.audio-focus/1`，明确区分未请求、已获准、被打断及被拒。声音许可与剧情暂停分别管理；焦点拒绝不是重算剧情或媒体重试的理由。本片只是试用接线，不定义正式读档语音默认方式。

#### 输出变化中断

`GameAudioFocus` 监听 `ACTION_AUDIO_BECOMING_NOISY`。监听只在当前独立 Activity 的控制器存续期间注册，API 33 起明确采用不导出的动态接收器；不扫描设备、不读取设备身份、不请求蓝牙权限或写入玩家记录。未请求声音时忽略此通知，已有输出中断时合并重复通知。

收到通知后使原焦点申请代次失效并释放焦点，声音状态转为已有的 `interrupted`，宿主沿原 `paused` 与声音许可通道暂停。没有新增桥字段、核心命令或暂停原因；共用混音器继续处理已有轨道，既有不可用语音和一次性声音规则保持原样。这里实现的是通知后的暂停接线，不保证消息往返期间所有设备都没有短暂外放，实际行为须真机确认。

输出中断独立于普通临时焦点中断：切后台、返回前台、重新获得窗口焦点或旧焦点回调不能清除它。只有在前台且窗口有焦点时，显式声音请求才确认本次输出变化并重新申请；重新连接设备本身不自动重启声音。重试被系统拒绝时沿用原规则保持无声，主线可静音继续。回标题/页面换代释放该声音会话，之后开局仍须已有显式请求流程。

声音控制器只给 Activity 返回 `status/interrupted` 快照，不持有 WebView、剧情、媒体或存储。所有状态变更在主线程，焦点回调带申请代次，输出通知及回调在关闭后拒绝；页面重置不向即将离开的文档发布新许可。错误页和销毁关闭控制器并注销接收器，不能在旧 Activity 上继续申请。动态监听注册失败时拒绝启用声音并给出提示，可显式重试，不让错误阻断静音主线。

本片没有编译、启动、测试或设备操作。系统是否为具体有线/蓝牙/USB 切换发送通知、各 WebView 自身焦点与原生焦点的交互、电话/锁屏、系统节流和真实播放限制仍需真机确认；不把收到一种通知当作全部输出路由覆盖或声音验收。

。刘海/手势区、系统栏实际布局、后台往返和各 WebView 的显示行为留到统一测试。

### 地址、载荷与内部格式

登记范围与 Windows 正式后端相同：

- `haifeng.save/1` 的当前作品 `game/main` 进度。
- 当前作品 `game/main` 的 `haifeng.player-records/1`。
- 同范围独立的 `haifeng.audio-preferences/1`、`haifeng.reading-preferences/1`、`haifeng.button-preferences/1`、`haifeng.readout-preferences/1`。

没有开发/预览、聊天、缩略图、任意预览或其他作品地址。槽位名称按解码后的 1～128 个 UTF-16 单元校验；字符串拼写兼容 JavaScript `JSON.stringify`，包括孤立代理项转义。Java 字符串自然顺序与 JS 逻辑地址的 UTF-16 排序一致，不以 UTF-8 字节序改排补充字符名称。

内部容器使用已有 `haifeng.native-record-table/1`，仍含作品、存储代次和逻辑键到原 JSON 值的 `entries`。原 JSON 数字、转义和字段次序不重编码为 Java 数值/领域对象，UTF-8 编解码遇无效字节明确报错；独立代理项通过 JSON 转义保留，不允许有损替换字符。此内部容器不是玩家导出格式或跨平台目录导入承诺；两端目录锁/临时文件布局由各自后端拥有。

新写入只校验 JSON 结构、容量、登记地址和封装 `format` 种类；完整检查点、成果、偏好校验/合并继续由原 TS 仓库执行，Java 不执行剧情、合并解锁或计算周目。已有条目的合法 JSON 即便不是合法领域记录也保留原值，交给 TS 仓库诊断，不能初始化覆盖。坏 JSON、重复字段、未知容器字段或越界地址导致容器拒绝，不静默丢字段。

当前限额：单条 JSON 2 MiB，容器 32 MiB，4096 个地址，目录 4096 个文件；JSON 最多 64 层、单对象最多 4096 个成员及一次解析最多一百万个值。超限明确失败，不截断或删旧记录。这是未调优的试用边界，不是正式容量承诺。

### 物理提交与恢复边界

目录独占 `store.lock`，使用文件锁拒绝另一进程；进程内先登记根目录，拒绝同目录第二实例后才打开锁文件，避免另一描述符关闭影响当前进程的 POSIX 锁。关闭描述符成功后才释放进程登记，释放不确定时保留拒绝。实例内部用同一监视器串行读、扫描、替换、CAS 和关闭。根目录和文件通过 `lstat` / `O_NOFOLLOW` 拒绝符号链接，打开后的文件再次核对普通文件属性；目录位置只由受信任原生决定，页面不能提供路径。

每次操作重新读取最高代次容器：新提交为 `records-<20位代次>/record.json`，兼容读取原 `records-<20位代次>.json`。新目录必须只有一个普通 `record.json`，同代次出现两种布局拒绝猜测。核对作品、封装和文件名/内部代次一致；最高容器损坏拒绝，不回落上一版本。只有从未提交的目录才是零代次空表，实例拒绝已观察代次倒退，CAS 预期大于实际代次明确报错，小于实际才是正常冲突。

设备验证发现应用沙箱拒绝原 `link()` 提交，且 SDK 34 不公开原清理及目录打开所用的部分符号。提交现独占创建 `pending-<UUID>.tmp` 目录，在其中完整写入并同步 `record.json`，关闭文件、尝试同步目录后，用公开 `Os.rename()` 在同一父目录发布下一代目录。新提交目录非空，系统不能用另一个目录覆盖已有非空提交，也不能用目录覆盖旧普通文件；不删除原提交以腾出目标，不复制到半成品提交名。目录或文件仍拒绝链接，目录打开后用 `fstat` 确认类型，清理用公开 `Os.remove()`。

新目录发布成功后才视为物理提交完成；随后尝试同步父目录并清理已确认属于本作品/格式的更老容器，保留当前及上一提交。清理旧目录前先把完整目录退到独立 `pending-<UUID>.tmp` 名，再删除载荷及空目录，避免清理中断留下貌似损坏的已提交目录。同步或清理失败只返回警告，不能把已经完成的提交报成失败。未完成临时文件或目录保留数量警告，不读取其载荷作为已保存进度。

Android 此处发布包含完整容器的非空目录，Windows 使用 `MoveFileExW`；内部容器及页面协议版本保持不变。目录同步失败后只能确认文件可读，不能承诺断电持久性。网络盘、损坏修复、手工替换文件、未知文件清理、系统强杀/回收和设备文件系统兼容仍未验收。

### 请求、确认与页面生命周期

当前入口来源固定为 `https://appassets.androidplatform.net/assets/game/index.html`，只观察主框架同页的 `readRequest()`。独立控制器约每 100ms 观察一次，单次页面求值最多等待 1 秒；一次最多一个观察和一个工作任务，页面重载不堆积文件请求。请求最多 3 MiB，严格核对封装、作品、页面身份和安全整数 ID，只接 `read/scan/replace/cas`，不接路径、URL、删除、脚本或通用文件操作。

工作线程保留本页最后一次原请求和回执；相同页面/ID/原载荷只重发缓存回执，重复投递、编码或页面求值失败不能重新执行文件事务。旧 ID、改变载荷或中途换身份拒绝；页面开始加载时使原观察和回执归属失效，原事务已开始则可完成，但旧回执不能采用到新页面。

扫描页按约 3 MiB 收短，续页定位到最后实际返回地址，不漏过后续条目；完整回执上限为请求上限加 64 KiB。最多 15 条详细警告及一条额外计数；结果和警告保持原提交意义。回执先编码完整 JSON，再整体引用为字符串交给 `JSON.parse`，不将记录拼成可执行对象。

共享页面队列沿 Windows 相同规则：最多 32 个后续请求，队首 12 秒未确认报告 `NATIVE_STORAGE_UNCONFIRMED`，保留原队首并阻止后续越过。超时后原回执返回才恢复通道，已拒绝 Promise 不被改成成功，也不自动补发后续操作。重复/旧回执不能污染当前请求；存档/偏好重试固定原载荷，全局批次沿原事实 ID 幂等。

失焦、后台或退出等待不停止文件工作线程；WebView 的后台脚本限制仍可能使回执迟到，不能因此宣称肯定未写入。正常退出复用原 `settle/flush` 和票据，未确认不授权关闭，重复返回只取消退出请求。错误页/Activity 销毁停止观察和后续请求，排完已开始操作后释放目录锁；不强行中断写入或假装撤销已提交事务。
