## 一、显然问题（附具体修法）

### A1. 主曲没有设播放增益，比目标响约 3 LU（影响 833 句）
- 实测：`bgm_emerald_dream_main_v01.mp3` 积分响度 −14.4 LUFS、真峰值 −1.0 dBTP。`assets["bgm_emerald_dream_main_v01"]` 里没有 `playbackGain`（引擎按 1 处理），等效 −14.4。同类曲目（E2、M2、M3、E5、T3、T4、E6、M1）都已经按 `playbackGain` 对齐到 −17.4±0.05。
- 修法：`game.js` → `assets["bgm_emerald_dream_main_v01"]` 新增 `"playbackGain": 0.7079`（−3.0 dB，等效 −17.4）。如果构建时从 `content/assets/audio/bgm_emerald_dream_main_v01.metadata.json` 读增益，要在那里同步。

### A2. E1 增益值不对，另有两首偏离目标
`musicVolume = vbgm × playbackGain`，下表的"等效"就是文件响度加增益后的值。

| 素材 id | 文件 I (LUFS) | 现 `playbackGain` | 等效 | 新值 |
|---|---|---|---|---|
| `bgm_atri_e1_comedy` | −14.4（真峰值 +0.1 dBTP） | 0.99655 | −14.43 | **0.7079** |
| `bgm_atri_e7_reflection` | −12.7 | 0.65539 | −16.37 | **0.5821** |
| `bgm_e4_sunset_wait` | −14.7 | 0.65917 | −18.32 | **0.7328** |
| （参考）`bgm_m1_shallows_day` | −13.7 | 0.6569 | −17.35 | 可不动（0.6531） |

E1 的 0.99655 看起来像是对齐前的旧值。E1 文件本身真峰值是 +0.1 dBTP，降增益后播放不会削波，但原件仍然有轻微过载。

### A3. 配音念出了导演提示：`lines[630]`（`wqr5d8bu`）
- 台词：「放你那儿。反正你那个本子，什么都能存。」
- 在用的是 3.1 版文件 `assets/vo/wqr5d8bu.mp3`，sha 和 `content/audio/voice-over.json` 里的条目一致。清单里这条的 ASR 是「轻描淡写的托付，语气里藏着信任，说，放你那儿……」，`asr_similarity` 0.681，状态 `review`。也就是说，TTS 把 direction 当正文念了出来。
- 修法：
  - 用当前前 200 句那套参数（qwen-audio-3.0-tts-plus 龙璨蕊霜，原调，语速 1.1）重生成 `vo_wqr5d8bu`。只送台词，direction 走指令字段，不要拼进文本。
  - 然后更新 `assets["vo_wqr5d8bu"]` 的 `dur`、`sha256`、`generator`。
  - 重生成之前，可以先把 `lines[630].voice` 设为 `null`，这句会无声，但不会念出提示。

### A4. 浅滩场景用了室内风铃环境：`lines[3298]–[3314]`（`wd2p4jns` 起，17 句，番外二结尾）
- 背景是 `浅滩_上午`，台词写的是"她在浅水区验收今日份的桂花"，但 `ambience` 是 `[{"id":"amb_a11_shell_wind_chimes_v01","gain":0.4}]`。其他 26 句 `浅滩_上午` 用的都是潮声加海鸥。
- 修法：这 17 句的 `ambience` 改为 `[{"id":"amb_a01_waves_normal_v01","gain":0.8},{"id":"amb_a06_seagulls_v01","gain":0.25}]`，和 `lines[180]` 等同场景的写法一致。

### A5. "拍床。两下。"只播了一下：`lines[3273]`（`22ckqhon`）
- 现在只有一个事件 `[{"id":"sfx_tail_soft","gain":0.65}]`。`tail_soft.ogg` 经静音检测确认只含 1 次接触（0.09–0.16 s）。
- 修法：`seEvents` 改为 `[{"id":"sfx_tail_soft","gain":0.65},{"id":"sfx_tail_soft","gain":0.65,"delayMs":450}]`。延迟必须大于 400 ms：`playSe` 会跳过同一 id 在播放 0.4 s 内的重复触发，第 37、275、696 句用的都是 1000 ms 间隔。

### A6. 尾巴类音效偏轻 10–15 dB，压在配乐下基本听不见
- 实测（积分 I / 真峰值）：

  | 素材 | I (LUFS) | 真峰值 (dBTP) |
  |---|---|---|
  | `tail_water_light` | −34.8 | −13.7 |
  | `tail_water_double` | −42.7 | −13.5 |
  | `tail_sand` | −36.5 | −15.2 |
  | `tail_wood` | −38.1 | −14.8 |
  | `tail_wood_leg` | −37.9 | −16.0 |
  | `tail_soft` | −39.9 | −17.8 |
  | `tail_close_door` | −40.2 | −17.5 |

- 对比：其他真实动作声的真峰值在 −1 到 −6 dBTP、I 约 −20。10-18 新交付的 `sfx_tail_pat_*` 已经"峰值对齐"到 −2.9 dBTP。
- 这组用在 50 多处，是全剧最常见的动作声。播放时还要再乘 `vse` 0.55 × 句增益 0.6–0.65，而配乐等效约 −26.5 LUFS，所以实际上听不见。
- 修法：沿用 10-18 新素材的做法，原件不动，生成峰值对齐到 −3 dBTP 的播放副本，替换 `assets/audio/` 下同名 ogg（`dur` 不变）。增益分别是：
  - `tail_water_light` +10.7 dB
  - `tail_water_double` +10.5 dB
  - `tail_sand` +12.2 dB
  - `tail_wood` +11.8 dB
  - `tail_wood_leg` +13.0 dB
  - `tail_soft` +14.8 dB
  - `tail_close_door` +14.5 dB

  命令示例：`ffmpeg -i tail_sand.ogg -af volume=12.2dB -c:a libvorbis -q:a 5 tail_sand.ogg.new`。
- 句里的 `gain`（例如第 136 句故意设成 0.25 的"轻得几乎没有"）保持不变。最终听感按惯例仍由音乐负责人确认。
