## 作者配置与实际覆盖

`packages/player/src/appearance.ts` 的 `readAuthorAppearance(content)` 保持无 DOM，只读唯一作者源已经保留的 `settings.theme/cover`：

| 配置 | 读取及应用 |
|---|---|
| `theme.preset` | 沿用 default、wafu、pastel、scifi、retro、minimal 的原默认值 |
| `box/alpha/text/name/accent` | 主题底板、渐变、文字、名字牌和强调色；色值限 `#rrggbb`，透明度为 0～1 |
| `font/size/radius/layout` | 四种既有系统字体栈、正字号、非负圆角、float/wide 布局；不加载网络字体 |
| `theme.img` | 只能指向登记的背景/角色图片，显式配置但无效则报带来源的错误 |
| `cover.img` | 登记的背景；未设时沿用旧播放器的首个原节点背景，不猜首章节或后续节点 |
| `cover.menu/title/style/ty` | 原位置、标题隐藏、glass/theme 及有限标题纵坐标；无封面时用旧居中标题规则 |

未知字段、枚举、非法数值或资源种类明确拒绝，不把任意字符串当作 CSS、HTML、URL 或脚本。缺省字段采用既有作者默认，不修改 `game.js` 或规范化内容格式。

当前作品的主题是 `#14292b` 底板、0.85 透明度、sans、25px、10px 圆角；封面为资源 `32lrbngt`，标题靠左、纵坐标 135。作者数据的 `cover.menu` 是 left，但原入口随后载入的已采用鲸鱼 UI 及仓库适配将菜单覆盖为右侧，不能只读该字段便把菜单搬左。

新实现沿用这项最终覆盖：主页菜单靠右 66px、底部 85px、宽 362px，每一项向左再错位 18px，间隔 26px；按钮、选择和对白底板使用原鲸鱼皮肤。作者默认字体/字号继续参与对白，名字牌继续采用本句已有的角色颜色；鲸鱼皮肤的固定底色、文字色、边框、名字牌、浮动对白布局等覆盖通用主题项，保持原入口的优先关系。没有让低优先级原主题重新盖住已采用的皮肤。

当前试播包含五个开发入口按钮：第一话、鉴赏、通关后玩法、[声音收藏](audio-library.md)、限时样例；新增收藏沿用右侧逐项 18px 错位，小舞台/竖屏仍使用紧凑菜单。存读档和其他控制仍在独立面板；布局复用不等于完整正式菜单或所有弹层已迁移。`cc857b0` 后接入下文的首立绘避让、两列选择与小舞台对白/选择规则；`cbccf3a` 后接入竖屏分区及小屏标题，`9d0aa78` 后另接[隐藏界面及共享输入](input.md)。仍非全部手机界面，原作品继续保留完整入口。

## 图形的唯一来源与装配

`tools/content/appearance.ts` 的 `readWhaleSkin()` 只从 `海风与布丁/index.html` 的 `WHALE_UI_APPROVED_START/END` 唯一标记区提取 `--whale-menu/choice/dialogue` 的三个既有 base64 SVG。保留原字节，不重画、改尾巴、移植像素或新增人工维护的图形副本。提取过程不执行旧 HTML、CSS 或 JavaScript，也不将旧播放器打入新运行端。

标记/图片重复或缺失、非规范 base64、超限图片、脚本、外链等输入拒绝。原 SVG 内的说明注释及片段引用保留；读取器没有被运行，不能据此声称提取已通过。

`tools/dev/appearance.ts` 提供同一 `virtual:haifeng-appearance` 装配，开发游戏、编辑预览和游戏构建共用。每次命令固定一份皮肤数据，源码改变后应重启命令；没有新增自动监听或运行命令。

`game:build` 在构建时读取一次，将同一份图形注入前端，并在 `content/sources.json` 的 `uiSkin` 记录原文件及标记区摘要。运行端只消费前端内的图形数据，安装后不再读取旧 HTML、制作素材库或 Node；前端文件摘要继续覆盖这些字节。不新增故事资源 ID，不改剧情内容修订算法、存档、成果、偏好或宿主协议。

这也明确留下一个构建消费者：当前旧入口的鲸鱼图形仍是新 UI 装配的来源，后续旧链路退出前须先完成有来源记录的迁移，不能直接删除或假称旧 HTML 已无消费者。

## 共享表现与加载

`web/appearance.ts` 只在给定舞台/场景根上写受限 CSS 变量和数据属性，不影响页面其他编辑控件。`WebPresentation` 可接第七个可选参数 `WhaleArtwork`；应用与编辑预览传入同一图形，均通过同一作者外观读取器。预览不修改主题、作者源或玩家偏好。

标题和选择使用 1280×720 的作者坐标，与背景/人物按同一舞台比例缩放；预览不再以另一套选择字号和 padding 覆盖共享样式。对白基准字号从试播固定 27px 改为作者 `theme.size`，本作品为 25px，再乘当前阅读偏好 `textScale`；小舞台的原可读性下限见下一节，偏好值和存储格式保持原样。

底板沿用既有深海蓝托底与 `clamp(.72, ghost + .37, 1)` 可读性修正；只改变底板，不让文字整体透明。文字过长时在当前对白框中滚动，不裁掉内容。字体或字号变化不重建剧情、重播语音、重算选择或当前有效计时。

标题背景独立按需加载，失败显示本地资源 ID 和“重试本地标题背景”，主线入口仍可使用；没有联网下载或替换封面。重试/离开注销原图片监听并清除源，旧加载不能更新新请求。若作者配置的对白框图片无法加载，归入当前场面阻断诊断并沿同一步骤重试，不重新执行进入动作。没有预解码全部资源。

## 共享选择布局与小舞台

从 `cc857b0` 的干净工作区接续原 `renderChoices()`、`fit()` 与 `game-polish.css` 的实际布局规则。只编写实现、接线及文档，没有执行运行、类型检查、测试、构建或额外审查。

`web/choices.ts` 的 `ChoicePanel(root, choose)` 仅消费 `SessionView` 中核心已经给出的可见选择；`render(view)` 不求值条件、不改变量、不决定超时结果。游戏和编辑预览均经同一面板发送原 `{session, epoch, step}` 与稳定选项 ID，由共享会话串行结算。

| 规则 | 本次接入 |
|---|---|
| 四项以内 | 首个立绘横坐标小于 640 则放右侧，否则放左侧；无立绘沿用左侧。宽 390、侧边距 42、顶端 174，按钮 21px、左对齐、间隔 12，保留原皮肤覆盖 |
| 超过四项 | 顶端 48、左右 48、底部 210 的两列区，沿用原次序；不根据文字或空间重排选择 |
| 高度不足 | 选择列表在限定区域滚动；少量选择也有高度上限，长文字、更多行数或倒计时不会只能落到舞台裁剪外 |
| 倒计时 | 两个入口都显示同一 `choiceRemainingMs` 进度条和辅助说明；面板不另开计时器，不发送超时意图 |
| 暂停及刷新 | 只改按钮禁用状态与进度条，不替换原按钮或重置列表滚动；单纯时间更新保留当前焦点，暂停禁用时的焦点遵循浏览器行为 |
| 新步骤及离开 | 清空旧列表并取消监听；迟到点击同时受面板身份和原会话令牌约束，不转成新步骤的选择 |

选择画布仍是 1280×720，列表放在其中，不把未缩放的页面坐标混入作者坐标。只有列表及其按钮接收指针，画布空白不遮住主线点击；列表本身可接滚动和触摸，顺序及条件隐藏仍由核心决定。隐藏列表不保留可聚焦按钮，不把 `aria-disabled` 代替真实禁用。

`web/stage-layout.ts` 的 `connectStageLayout(stage)` 是游戏/预览共用的 `ResizeObserver` 接线，以舞台内容宽高设置 `--stage-scale`、一个屏幕 CSS 像素对应的作者坐标 `--stage-unit` 和布局属性。横屏按可用宽高容纳完整 1280×720，场景、标题和选择共用比例及居中偏移，不分别取整；暂时不可见的零宽/高舞台不写入无效比例，销毁断开观察并清理所写属性。不访问剧情、媒体或有效计时。

横屏舞台比例小于 0.75 时，沿用原小舞台对白/选择适配：对白底板按实际 140px 高、正文至少 15px、名字至少 14px 呈现；选择顶端为实际 18px、间隔 8px，少量选择宽 300px 并限制在舞台内，按钮至少 40px 高、文字至少 15px。字号更大时继续允许滚动，不改玩家偏好值或重建逐字/语音。

首立绘判断只是旧作品的启发规则，不声称能避开每个角色或所有脸部。竖屏和紧凑标题由下一切片接入，见下节。

## 竖屏分区与小屏标题

从 `cbccf3a` 的干净工作区接续，仍只编写共享布局、作用域样式、接线及文档，未启动、构建、类型检查、测试或视觉验收。没有新布局偏好、存档字段、宿主协议或作者内容修改。

浏览器可用窗口宽高比不超过 `20/23` 时，试播舞台取得较高的显示区域：高度按窗口短视口高度减 32px，旧环境回退到 `vh`，最少 560px，页面可滚动。这是当前开发页的容器安排，不是正式最小分辨率、全屏模式或玩家设备限制。游戏与编辑预览共用该样式，不把整页制作控件放进游戏布局。

共享布局继续按原 `fit()` 的 `高 > 宽 × 1.15` 判断舞台是否进入竖屏；该条件只读容器尺寸，写出的变量不改变容器宽高，避免自己触发尺寸反馈循环。竖屏以宽度确定场面比例，扩大场景/选择画布的显示高度，背景与人物仍只在原 1280×720 场面内呈现，人物位置、大小、图片与演出不重算。

| 区域 | 竖屏规则 |
|---|---|
| 场面 | 放在上方，沿原公式留 0～48px 顶部空间，完整作者场面按宽缩放；氛围、镜头与遮罩仍在场面内 |
| 对白 | 在场面下方留 16px 间隔，按可用空间取 150～240px 高；两侧各 12px，正文可滚动，当前作品默认正文为 `25 × 0.68 = 17px` 再乘玩家字号倍率 |
| 名字牌 | 16px 字、30px 高，保留当前说话人颜色；按原竖屏规则独立于场面缩放 |
| 选择 | 在对白下方单列展示，按钮至少 48px 高、16px 字；不改变选项身份、次序或条件。不足 150px 的选择空间改为覆盖场面/对白上方的可滚动区域，沿原 fallback 保留可访问内容 |
| 选择外观 | 沿原竖屏渐变和边框，横屏继续使用原鲸鱼 SVG；对白采用原仓库竖屏深蓝可读性覆盖，不改图形字节或来源 |
| 标题 | 原封面采用 66% 横向取景和下半部渐暗；标题 30px，菜单沿原竖屏规则居中放下半部，按钮至少 44px。横屏桌面仍是右侧错位，不移动到左侧 |
| 操作 | 当前试播控制继续在舞台外，触摸设备的游玩/预览按钮至少 44px 高；不把旧内嵌操作栏的 104px 空间重复留在舞台内 |

横屏的小舞台标题也沿用原规则：菜单靠右 18px、底部 12px、宽 160px，按钮至少 36px、15px 字，暂取消逐项错位；空间不足时菜单滚动，试播样例说明仍有实际字号。恢复宽屏后回到原右侧错位和作者尺寸，不替换任何按钮或重新加载封面。

旋转或改窗口尺寸只更新 CSS 变量和布局属性，不请求继续、暂停、重建表现或重新开始计时；已有文字、音频、选择监听、滚动位置和步骤身份继续属于同一次呈现。布局没有自己的计时器，也不决定限时结果；后台/宿主暂停继续由既有会话处理。

这不是完整正式 UI 迁移：全部弹层、原舞台内触控操作栏、旋转提示、完整窗口设置和正式菜单仍未接入或验收。[隐藏界面](input.md)已在后续输入切片接到共享表现，[显式全屏](fullscreen.md)复用同一尺寸观察与横竖布局；开发页保留外部按钮和诊断控件，最终界面框架和发行入口保持待定。
