# 共享镜头与转场

从 `8a60973` 接续 M5 演出迁移。本片修正共享 `WebPresentation` 的背景镜头范围、取景与缩放中心关系，分离转场和瞬时特效遮罩；游戏与独立编辑预览共用实现及样式。只编写实现和文档，未启动、类型检查、测试、构建、额外审查或使用子代理，尚未验收。

## 镜头提示

旧 `海风与布丁/player.js` 的 `stageShot()` 将资源 `shot.focus` 用作缩放中心，`view.position` 独立决定背景取景。原镜头缩放限制为 1～1.04，时长限制为 600～3000ms，缓动为 `cubic-bezier(.2,.65,.3,1)`；快进与系统减少动态效果时清除镜头缩放。

共享实现采用上述数值及关系：

| 输入或状态 | 当前行为 |
|---|---|
| `shot.focus` | 非空时须为两个有限数值，直接转换为百分比缩放中心；非法值报告带节点及背景资源 ID 的场面错误，不改成默认焦点 |
| 缺省或空的 `shot.focus` | 不启用镜头；单独存在的 `scale` 不产生缩放 |
| `shot.scale`、`shot.ms` | 读取有限数值并按旧范围限制，缺省沿用既有读取值 1、2200ms |
| `view.position` | 显式值决定取景，未配置时居中；不能用镜头焦点替代背景取景 |
| 正常首次呈现或更换背景 | 当前资源准备完成后执行镜头，不等待动画结束才开始对白或选择有效时间 |
| 同背景的后续呈现、媒体重试或检查点恢复 | 直接显示镜头终点，不重放进入演出，不保存或恢复动画帧 |
| 快进或本次呈现时系统减少动态效果 | 不采用镜头缩放；当前呈现中进入快进也清除缩放，停止快进不在本句中补跑镜头 |

内容内原始资源元数据保持原样，限制只在表现时应用。焦点是否有效在场面提交前判断；错误仍走原媒体问题及当前场面重试，不重新进入剧情。镜头使用独立 `scale`，不改场面坐标、剧情变量、声音或记录格式。

## 独立转场遮罩

转场 `black/flash` 使用 `transition-veil`，按旧 `#veil.go` 的 800ms 从不透明淡出；瞬时 `flash/redflash/blink/quake/whip` 继续使用另一层遮罩，位于转场之上。两者可以在同一节点分别设置颜色及透明度，不再由后设置的特效改掉转场颜色或覆盖同一透明度动画。

“已有场面”独立于背景 ID 记录。没有背景也是有效场面；从无背景切到有背景，仍按实际更换和当前 `trans` 处理。第一次呈现不冒充从旧场面转场，读档/回退及媒体重试继续直接采用稳定场面。

两层动画均归属当前呈现，复用原暂停、恢复、快进及取消通道；菜单或后台暂停动画，换节点/重试/离开取消旧动画并清理遮罩。新增层没有输入处理或剧情回调，不决定点击、超时、声音完成或检查点时机。

## 未覆盖及兼容边界

本片没有修改旧作品、旧播放器、作者源、内容协议、检查点、偏好或宿主桥，也没有新增资源、按钮或依赖。共享 DOM 内部增加一层遮罩，应用和编辑预览不增加公开接口。

旧 `VN_FADE` 对整个旧画面（含对白及弹层）的快照淡出尚未迁移；当前 `fade` 仍是新背景淡入，不能称为完整新旧场面交叉淡化。跨对白连续镜头帧、完整角色动作/氛围曲线及所有界面过渡也未完成等价迁移。当前修改不代表全量演出或视觉验收。

## 留待统一测试

以下只是测试阶段的操作建议，本轮没有执行或生成测试内容：

1. 在游戏和编辑预览中查看带镜头的背景，如 `yvwvivzm`（CG_初登场）；确认取景遵循 `view.position`，镜头缓慢向 `shot.focus` 缩放，同背景下一句不重放进入动作。
2. 在统一测试专用内容中把镜头值设到范围外，检查限制为 1～1.04 和 600～3000ms；再提供非法焦点，检查错误定位以及修正后重试。不要修改权威作者源来制造故障。
3. 镜头或黑场转场中打开菜单、切后台、进入快进和返回标题，检查暂停、清理以及旧呈现不污染新场面；系统减少动态效果时检查没有镜头缩放。
4. 用统一测试专用内容组合无背景→有背景、`black` 转场与 `redflash` 特效，确认转场未被当作首次场面跳过，黑场和红闪分别结束；检查恢复同一节点不重播这两种进入演出。
