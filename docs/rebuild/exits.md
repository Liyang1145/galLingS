# 正常退出前的写入协调

从 `62d4b84` 接续平台生命周期与 M4 记录。当前只编写共享写入跟踪、应用退出面板和两端正常关闭接线；没有安装、测试、类型检查、编译、启动、设备操作、额外审查或子代理，尚未验收。

## 已实现的边界

Windows 关闭按钮与 Android 标题页连按返回退出，现在先请求页面完成已有写入，再根据本次结果关闭。该过程只处理已经发起的手动存档、显式[音量/阅读/按钮声音偏好保存](preferences.md)及待提交全局事实，不另建当前剧情进度，不把全局记录提交当成节点已存档；未点击保存的设置调整也不会自动写入。

用户尚未决定自动检查点触发时机、正式读档语音和自动恢复体验，本片不设置这些默认。强制结束进程、系统回收、崩溃、断电、浏览器标签页关闭、页面重载和宿主投递整体失效均不属于正常退出保证；现有手动档仍是重开后可读取的位置。

## 应用准备过程

共享 `packages/player/src/writes.ts` 提供 `PendingWrites`，只追踪显式写入，不依赖 DOM、宿主或剧情核心，不是持久事务日志：

- 同一槽位尚在写入时拒绝叠加，完成后移除跟踪。
- 失败保留原操作，`settle()` 等待已有写入并报告失败，不把失败吞成成功。
- 玩家显式重试时使用原捕获的入口、槽位名称、检查点及显示时间，或原捕获的音量/阅读/按钮开关修改；[命名槽位](slots.md)选择后来改变也不能重定向原写入，不在重试时读取后来进度或反算变量。偏好保存重试保留失败后新增的未保存调整。
- 捕获或原槽位检查未完成、覆盖确认取消时，本次进度尚未交付写入跟踪；需在稳定位置显式新保存，不凭空重试或把准备当已保存。

从 `3969a6a` 增加显式的 `track()`/`TrackedWrite` 原操作句柄，存档面板可单条重试，退出 `retryFailed()` 仍只处理当前失败实例并沿原 `settle/flush` 流程；它不新建操作身份或让旧句柄指向后来同键保存。面板和退出因此共享同一状态，不重复排队；已完成、仍进行中或被替代的句柄拒绝重试。只读摘要不增加键/检查点/操作，操作 Promise 完成仍不等于全局事实已提交或宿主关闭就绪。详见[存档原重试](saves.md#存档面板的原操作重试)，未运行或验收。

应用退出时先以独立 `exit` 原因暂停当前会话，禁止继续操作。使尚未采用的开局、读档、回退及鉴赏请求过期，关闭[通关后入口](chat.md)并使旧上下文读取失效，解除被取代的 `operation` 原因；退出取消不能误解除菜单、后台或宿主暂停。

从 `af5fa20` 接入[覆盖确认](slots.md#原槽位覆盖确认)后，退出同时取消尚未交付的检查点/原目标检查及确认提示。它们不进入 `PendingWrites`，不阻塞已有写入的 `settle()`，也不被正常退出自动采用；原只读底层可继续清理。已经确认并交付的保存仍完整等待原载荷及全局事实，取消退出不能把旧提示带回或撤销该事务；未运行或竞态验收。

从 `0177602` 接入的[Windows 文件试用](native-storage.md)及从 `7c25552` 接续的[Android 文件试用](android-storage.md)，共用确认丢失语义 `NATIVE_STORAGE_UNCONFIRMED`：可能已经提交，不可显示成肯定未写入，也不授权退出。桥保留原队首并阻止后续越过，原回执迟到后仍需用户显式重试/查看；退出重试继续使用原检查点或原事实批次，由原仓库保证幂等。工作线程不因窗口失焦/后台/退出等待而停止，Android WebView 后台脚本受限仍可能使回执迟到；基础退出票据和取消规则未改，未运行或故障验收。

随后等待已发起的保存，再 `flush()` 全局事实队列，确认无待提交项才报告就绪。退出面板区分等待、失败、重试和取消；没有“写入失败仍假装完成”的关闭路径。取消只是撤回关闭请求，不能撤销已经开始的存储事务。已捕获的数据若继续提交，仍写原入口与原槽位。

终态表现也接续 `exit` 暂停及宿主声音许可。退出期间提交的首次结局回执仍保留成果，但不播放新结局提示，取消退出也不补播；这项反馈取舍不改变退出等待成功/失败的判断。

关闭对白回看时会先取消独立的历史语音试听，正常退出及取消退出都不会自动续播试听；主线的 `history/exit` 暂停原因继续分开管理。试听没有存储写入或全局事实，不加入退出等待队列，也不改手动检查点的主线语音位置。

正常退出就绪后，应用继续保持暂停和输入禁用，直到原生关闭或取消这张请求。窗口关闭前没有再推进、选择或新建事实。浏览器试播仍有 `pagehide` 清理，但不承诺浏览器允许异步等待存储。

玩家可在等待或失败期间取消；页面确认就绪后关闭取消按钮，不再接受玩家撤回，避免旧的就绪响应关闭一个已经恢复游玩的会话。原生超时或关闭失败仍能按票据撤回就绪状态，使页面恢复操作。

## 已有写入的只读状态与界面

从 `58a427c` 接续，`PendingWrites.run(key, operation, label?)` 可捕获一个只用于显示的名称，重试仍沿用同一名称与原操作；未传名称的既有调用继续使用普通保存说明。`view()` 返回冻结的名称、pending/failed 状态和错误文字副本，不返回存储键、闭包、检查点、偏好值或错误对象。`subscribe()` 只通知已有跟踪状态变化，不触发保存或重试；观察者异常不能把提交成功改成失败，摘要也不能代替 `settle()/flush()` 授权关闭。

游戏 `exit-status.ts` 只显示应用提供的当前阶段、只读写入摘要和全局待交付批数。面板将“本页已发起保存”“全局成果提交”“宿主关闭确认”分开；手动槽位名称来自原发起目标，偏好只标明各自类别，不随着后来选名改变。显示的是待处理操作和事实批数，不猜字节进度、百分比或剩余等待时长。全局就绪仍须原 `flush()` 成功且无待提交项，页面准备完成仍继续等待本张原生票据。

界面沿现有海绿色样式，说明/列表可滚动，重试和取消按钮独立留在下方，小高度缩紧留白。退出期间才订阅，取消、原生撤回及页面销毁释放原订阅并失效迟到更新；完成后尚未关闭的页面继续保持原暂停/输入禁用。渲染失败独立显示，不改变写入或退出结果。没有新增强制关闭、自动存档、偏好保存、进度捕获、宿主消息或持久格式；已编写并接入，未启动、类型检查、测试、构建或验收。

## 本次请求与原生关闭

共享桥升级为 `haifeng.host-bridge/3`，新增退出处理器和按正整数标识的退出票据。包清单仍为 `haifeng.game-package/2`，明确登记新桥；Windows 准备记录 `/2`、Android 准备记录 `/3`（额外核对文件记录桥模板）均登记基础桥。旧桥 `/2` 的游戏包和 Android `/2` 准备输入须重新构建或准备，不修改剧情、内容修订算法、进度或全局记录格式。

`beginExit(id)` 对相同请求幂等，返回 `id/status`。处理器异步完成才进入 `ready`；取消通过该请求的 `AbortSignal` 撤回。旧请求、旧页面或旧 WebView 的结果不能用于关闭后来的页面。桥初始的无写入阶段允许退出，内容尚未载入时按钮保持禁用；应用安装正式处理器后，所有正常退出都经上述写入流程。

Windows 拦截 `CloseRequested`，单独任务轮询本次票据，确认 `ready` 后关闭该窗口；相同窗口的重复关闭不会叠加任务。Android 第二次标题页返回启动同样的请求，重复返回改为取消；游玩中返回仍只处理菜单与弹层。

两端等待上限均为 30 秒。超时、无效响应或消息失败保留窗口并尝试取消本次票据；超时不证明存储已失败或完成，也不授权强制关闭。Windows 原生错误当前记入诊断输出，Android 显示本地提示；页面收到取消后恢复本次关闭前的输入和暂停归属。若页面投递本身持续不可用，无法承诺取消及时送达，页面可能仍保持退出暂停。

不调用旧存档接口，不进入另一解释器，不上传玩家数据，没有改变系统退出/强制结束行为。未实现强制关闭时的磁盘日志、正常退出后文件级备份或系统回收后的自动恢复点。

## 统一测试时的情景

沿用 [Windows](windows.md#留待统一测试的命令) 或 [Android](android.md#统一测试阶段入口) 的构建与启动说明，先重新生成符合桥 `/3` 的包。本轮未执行：

1. 发起手动保存后立即关闭窗口，确认先等待保存和全局事实完成；重开读取时仍是本次捕获的位置。
2. 当前节点未手动保存时关闭，确认未自动改写手动槽位；全局成果仍单独提交。
3. 保存或全局记录失败后关闭，窗口保持打开并给出重试/取消；同一批结局事实重试不重复计次。
4. 等待写入时取消退出，继续游玩后原保存完成仍写原检查点，不采用后来变量；菜单/后台暂停仍保留。
5. 连续关闭、返回或取消，及等待期间重建页面，确认旧回调不能关闭新页面；30 秒超时保留窗口。
6. 强制结束进程后只按已提交手动档恢复，不把正常退出流程当成强制结束的数据保证。
7. 显式音量/阅读/按钮开关保存进行中或失败后退出，确认等待/重试同一次修改；取消退出恢复设置控件可用状态，未保存的后续调整不被写回或丢弃。
8. 检查退出三组状态、原槽位/偏好名称和全局事实待交付批数；完成的写入退出跟踪列表，不能把“没有跟踪项”或观察者提示当作全局提交或宿主关闭已完成。重试不改目标，取消/超时后马上再次退出，旧订阅与迟到回执不能改新面板。长名称、长错误、手机与矮横屏保持重试/取消可访问。

这些均为待确认情景，不能据此宣布可靠恢复、全平台存储或 M5 已验收。
