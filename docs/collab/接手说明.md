## 修图做法（已验证有效）

- 模型：Rinko `https://api.rinko.ai/v1/images/edits`，用户指定 `gpt-image-2.5-sunburst`，**不可用 gpt-image-2 代替**，不可用时停下告诉用户；必须 `stream=true`，并发不超过 2。脚本 `tools/hark/rinko_edit.py`，key 由用户提供，不在仓库里。
- 局部修：截取区域放大到生成尺寸，做无 mask 编辑，再按差异区合成回原图（`tools/hark/graykey_composite.py`）。带 mask 的编辑会把整块抹掉。
- 背身尾巴（L12，10-18 定稿）：裙子完整，尾根藏在后摆下，裙边压住尾巴。直接把标注图丢给模型，它会把裙子掀起来露底，不要这样做。（当年按 C05 参考做；现行参考图改为 L01。）
- 立绘透明底：`background=transparent` 直出，或灰底生成再抠图；发丝之间要真正透明，清掉 alpha<16% 的薄雾；检查尾巴有没有跑到两腿之间、有没有切断身后的头发。白底加 rembg 的做法已作废。
- 个别图的指示（C25 不画尾巴、C05/O11 是朋友稿不动、L20/C27 退选、P05 由 S02 取代等）见[交接](handoff/Hark会话交接_20261020.md)第 3 节。

## 推送做法

不要全量 clone（仓库约 2.4GB，GitHub 会报 502，进程也会被 OOM 杀掉）。用 blobless 浅克隆，按路径 `git show <sha>:<path>` 取文件；`tools/hark/commit_tree.py` 用 `mktree --missing` 构树再 `commit-tree`；`tools/hark/push_retry.sh` 在报缺 blob 时按需 fetch 后重推。被拒就基于远端新头重建，不强推。

## 试玩单文件

`python tools/build_playtest_html.py 输出.html`：素材内嵌成 data URI（图缩到 1600/1280 宽），注入对白账本（逐句批注，localStorage 键 `hfbd-ledger:<游戏id>`，可导出 CSV/JSON/MD）。约 160MB，本地导出，不进 Git；用户要时才建。用户在账本里写批注、导出 JSON 发来，意思就是照批注修。
