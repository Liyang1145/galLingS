# Android 试用原生记录后端

2026-10-24 从干净的 `62b9746`（重构：接通 Windows 文件记录试用）接续 Android 物理后端。当前**只编写未接入的后端**，没有在 Activity 创建实例，没有 Android 文件模式/页面桥或存储选择。Android 仍使用原 IndexedDB；没有生成数据目录、执行准备、Gradle、类型检查、测试、设备操作或验收。

本片沿既有主线离线和平台存储边界实施，不决定正式数据落点、默认记录源、迁移、备份/卸载保留、分发、宿主统一、系统回收恢复或缩略图。Windows 显式文件试用见[对应说明](native-storage.md)，不能将其运行参数直接用于 Android。

## 模块和接口

| 位置 | 已编写职责 |
|---|---|
| `mobile/android/rebuild/src/main/java/net/gallings/haifeng/rebuild/NativeRecordStore.java` | 独占目录锁、串行读取/分页、进度替换、成果/偏好 CAS、完整容器提交及警告；不持有 Activity/WebView |
| 同目录 `NativeRecordAddress.java` | 当前作品的受限地址、记录种类及槽位名称边界；逻辑键永不转为文件名 |
| 同目录 `NativeRecordJson.java` | 严格 JSON 边界、重复字段拒绝、原值切片和 UTF-16 字符串转义；不归一化剧情或记录值 |

仅使用 Android 系统 API 与 Java 标准库，不新增依赖、权限、Gradle 参数、页面桥或生成 assets。后端同步方法须由未来原生工作线程调用，不能接到 UI 线程做磁盘操作。

| 方法 | 边界 |
|---|---|
| `open(root, workId)` | 仅受信任原生装配可提供目录和作品；父目录须已存在，根目录为普通目录，实例持有独占文件锁 |
| `read(key)` | 返回存储代次、可缺失的原 JSON 字符串和警告；Java `null` 是无键，字符串 `"null"` 是存在的损坏领域载荷 |
| `scan(prefix, after, limit)` | 只列举登记进度范围，1～100 条，按 UTF-16 单元顺序返回原键/原 JSON 和最后实际返回键的续页地址 |
| `replaceProgress(key, rawValue)` | 仅替换单个登记进度地址，完整提交后返回成功 |
| `compareExchange(key, expected, rawValue)` | 仅成果/四组偏好，比较整个容器存储代次；冲突不写，原 TS 仓库未来重读并合并 |
| `close()` | 与当前同步操作串行，释放目录锁；不能假装撤销已完成的文件提交 |

返回副本及不可变列表，不暴露记录表、真实目录、文件句柄或通用文件操作。错误带 `NATIVE_STORAGE_*` 类别；不以默认空表、旧容器或另一存储源掩盖异常。

## 地址、载荷与内部格式

登记范围与 Windows 试用后端相同：

- `haifeng.save/1` 的当前作品 `development/normal-entry`、`preview/timed-choice:pm8x8v2h` 进度。
- 当前作品 `development/normal-entry` 的 `haifeng.player-records/1`。
- 同范围独立的 `haifeng.audio-preferences/1`、`haifeng.reading-preferences/1`、`haifeng.button-preferences/1`、`haifeng.readout-preferences/1`。

没有正式 `game`、聊天、缩略图、任意预览或其他作品地址。槽位名称按解码后的 1～128 个 UTF-16 单元校验；字符串拼写兼容 JavaScript `JSON.stringify`，包括孤立代理项转义。Java 字符串自然顺序与 JS 逻辑地址的 UTF-16 排序一致，不以 UTF-8 字节序改排补充字符名称。

内部容器使用已有 `haifeng.native-record-table/1`，仍含作品、存储代次和逻辑键到原 JSON 值的 `entries`。原 JSON 数字、转义和字段次序不重编码为 Java 数值/领域对象，UTF-8 编解码遇无效字节明确报错；独立代理项通过 JSON 转义保留，不允许有损替换字符。此内部容器不是玩家导出格式或跨平台目录导入承诺；两端目录锁/临时文件布局由各自后端拥有。

新写入只校验 JSON 结构、容量、登记地址和封装 `format` 种类；完整检查点、成果、偏好校验/合并继续由原 TS 仓库执行，Java 不执行剧情、合并解锁或计算周目。已有条目的合法 JSON 即便不是合法领域记录也保留原值，未来由 TS 仓库诊断，不能初始化覆盖。坏 JSON、重复字段、未知容器字段或越界地址导致容器拒绝，不静默丢字段。

当前限额：单条 JSON 2 MiB，容器 32 MiB，4096 个地址，目录 4096 个文件；JSON 最多 64 层、单对象最多 4096 个成员及一次解析最多一百万个值。超限明确失败，不截断或删旧记录。这是未调优的试用边界，不是正式容量承诺。

## 物理提交与恢复边界

目录独占 `store.lock`，使用文件锁拒绝另一进程；进程内先登记根目录，拒绝同目录第二实例后才打开锁文件，避免另一描述符关闭影响当前进程的 POSIX 锁。关闭描述符成功后才释放进程登记，释放不确定时保留拒绝。实例内部用同一监视器串行读、扫描、替换、CAS 和关闭。根目录和文件通过 `lstat` / `O_NOFOLLOW` 拒绝符号链接，打开后的文件再次核对普通文件属性；目录位置只由受信任原生决定，页面不能提供路径。

每次操作重新读取最高 `records-<20位代次>.json`，核对作品、封装和文件名/内部代次一致。最高容器损坏拒绝，不回落上一版本；只有从未提交的目录才是零代次空表。实例拒绝已观察代次倒退，CAS 预期大于实际代次明确报错，小于实际才是正常冲突。

提交先完整编码新容器，再独占创建 `pending-<UUID>.tmp`，完整写入并同步文件，关闭句柄。在同一目录用系统 `link()` 创建不可覆盖的下一代提交名；目标存在或文件系统不支持时明确失败，**不改用可覆盖的重命名、复制/删除或另一存储源**。原已提交文件在此之前不被删除或重命名。

新提交名创建成功后才视为物理提交完成；随后尝试同步目录、移除本次临时名并清理已确认属于本作品/格式的更老容器，保留当前及上一提交。目录同步、当前临时名或旧容器清理失败只返回警告，不能把已经完成的提交报成失败。未完成临时文件保留数量警告，不读取其载荷作为已保存进度。

Android 此处使用完整文件的硬链接提交，Windows 使用 `MoveFileExW`；这是各自后端的物理实现差异。目录同步失败后只能确认文件可读，不能承诺断电持久性。网络盘、损坏修复、手工替换文件、未知文件清理、系统强杀/回收和设备文件系统兼容仍未验收。

## 下一片与统一测试

下一片可接续显式 Android 文件试用装配与受限页面请求/回执，先沿实际桥和准备接口读取，不直接复用 Windows 注入的 origin/运行参数。保持单一所选源，核对当前包能力、作品、主框架来源、页面代次/身份、单调请求 ID，重复请求只重发原回执，已开始提交不因页面取消而撤销。TS 继续复用现有 `NativeRecordStore` 适配与原领域仓库。

确认丢失必须沿现有 `NATIVE_STORAGE_UNCONFIRMED` 语义：不能宣称已保存或肯定未写入，原队首不能被后续越过，显式重试保留原载荷/事实 ID，正常退出仍等待确认。当前尚未接桥，不能写成这些页面行为已经在 Android 落实。

统一测试预留：独占锁、非法地址、Unicode/孤立代理项、`null`/无键、UTF-16 分页、原样数字/转义、CAS 冲突/代次倒退、容量/结构限额、写入/同步/链接故障、目标冲突、目录同步警告、最新容器损坏、不支持硬链接、清理失败、关闭和重新打开。完成页面接线后再统一覆盖身份/迟到/确认丢失与正常退出。目前全部未执行，不能据源码宣布 Android 平台存储已完成。
