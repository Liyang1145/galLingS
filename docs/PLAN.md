# galLingS 立项 Plan v1.1（详细版）

> 状态：设计阶段，只有 Plan，不含代码。
> 日期：2026-10-10
> 文中的限幅、阈值、延迟等数值均为建议默认值，实现时可调。
> Demo：《海风与布丁》第一话「浅滩上的偶遇」，本人现场演示给立项方，单台笔记本本地运行。

---

## 0. 一句话

galLingS 是一个由**角色卡驱动**、模型以 **agent** 身份接入的 Galgame 后端引擎。

- 剧本决定"发生什么"（节拍）。
- 角色卡决定"谁来演、怎么演"（演绎）。
- 大模型实时演出，可以长出剧本外的分支与结局。
- 确定性引擎负责校验、落账、存档与回放。

核心原则：**模型提议，引擎裁决**。模型从不直接改状态，只能通过工具提交提议，规则层校验后才落账。

## 1. 目标与非目标

### 1.1 本期目标（Demo）
1. 第一话可以完整地纯选项通关（无 AI 也是完整游戏）。
2. AI 模式下，玩家可以自由打字 + 选项，鲸鱼小姐用原作语气接住剧本外的话，尾鳍诚实标记出卖真心。
3. Web 建卡页：一段人设描述 → AI 填卡 → 玩家修改 → 引擎校验 → 用新卡重演第一话同一场。
4. 记忆：灵枢底座 + AGM 补位，可在调试时间轴上看到"她记住了什么、为什么想起它"。
5. 调试时间轴：每一步展示"模型提议 → 引擎裁决"，可回放。

### 1.2 设计原则
- **Demo 最简化，非核心能力只预留接口。**
- 规则写进代码，不靠提示词。
- 鲸鱼小姐的原作台词锁定，不被模型改写。
- 剧本精修中，附录 E 是制作 ID 唯一数据源。

### 1.3 本期非目标（只留接口，见 §14）
生图、Live2D、TTS、剧本外新结局的完整演出、结局后自由聊天、跨局记忆、多协议模型网关（Demo 只接 OpenAI-compatible）、MCP 外部 Agent 端口、Unity/UE 客户端嵌入、LetsGal 剧本 JSON 导入导出。

```
│  Agent 工具层（schema 注册表，Demo 只开内部调用）                    │
│  模型网关（OpenAI-compatible → DeepSeek）                          │

│  OP 解释器 · 状态机（好感/尾鳍/称呼/心情）· 事件日志 · 快照/回放      │
│  AGM 图存储与扩散激活                                               │
└──────────────────────────────────────────────────────────────────┘
```

### 3.1 Python / C++ 分工

| 层 | 语言 | 理由 |
|---|---|---|
| OP 解释器、状态机、事件日志、快照回放 | C++ | 确定性、可移植，以后可单独嵌进客户端 |
| AGM 图存储与扩散激活 | C++ | 热路径；图规模随游玩增长 |
| 导演、守卫、意图分类、提示词组装 | Python | 迭代快，频繁调整 |
| 模型网关、记忆网关（灵枢）、角色卡服务 | Python | 生态（HTTP、MCP、校验库） |
| Web/API | Python（FastAPI + WebSocket） | 本地单机足够 |

C++ 核心对 Python 只暴露纯数据接口（JSON 进、JSON 出），不回调 Python，以保证回放确定性。

## 5. 剧本：双层结构与编译

### 5.1 节拍层（与角色无关）
- 场景、事件、目的（例：初遇 → 冲突 → 软化 → 留下线索）。
- 选项点，以及每个选项的性质：顺毛 / 诚实笨拙 / 作死。
- 好感变化、尾鳍标记、汇合点、存档点、碎片、CG 触发。
- 角色专属物件写成**槽位**：`{珍视之物}`=糍粑、`{禁区}`=尾巴尖、`{饮品}`=酸梅汤·加桂花。

### 5.2 演绎层（与角色相关）
- 鲸鱼小姐：直接使用原剧本台词，锁定。
- 其他卡：模型按卡实时演绎同一节拍，必须命中节拍目的与情绪落点。

### 5.3 第一话体量（v5.0）
- 4 个选项点、10 处好感标记、多处尾鳍标记（本章结算 4 次）。
- CG×1（立绘初登场），存档点「酸梅汤·加桂花」。
- 本章好感结算区间 -17 ~ +23。
- 场景：浅滩 · 正午 → 午后 → 黄昏前 → 黄昏。

### 5.4 编译流程
```
Markdown 剧本 ──解析──> Chapter / Fragment / Block JSON ──降级──> OP 指令流
```
- 识别标记：【场景】【BGM】【立绘差分】【CG预留】、（选项）、⇒、——X线——、——汇合——、◆、※、【碎片】、存档点、旁白/独白/台词三层。
- 每个 Block 带 `beat_id`、`purpose`、`emotion_target`、`slots`、`locked_lines`（仅鲸鱼小姐）。

### 5.5 OP 指令集（Demo 最小集）
| OP | 参数 | 说明 |
|---|---|---|
| `SCENE` | id, bg, time | 切场景 |
| `BGM` | id | 占位，可空 |
| `SAY` | speaker, text, layer(旁白/独白/台词), voice? | voice 为 TTS 预留 |
| `SPRITE` | card, expr, pos | 立绘差分（占位图） |
| `TAIL` | action, count | 诚实信号（鲸鱼小姐=尾鳍） |
| `CHOICE` | options[{id, label, nature}] | 选项点；AI 模式同时开放输入框 |
| `INPUT` | beat_id | 自由输入入口 |
| `AFFECT` | delta, reason | 好感变化（经限幅） |
| `CALL` | name | 称呼变更 |
| `JUMP` / `MERGE` | target | 分支 / 汇合 |
| `SAVEPOINT` | id, name | 存档点 |
| `CG` | id | CG 占位 |
| `FRAGMENT` | id | 碎片收集 |
| `AI_TURN` | beat_id | 交给导演 + 模型演一轮 |
| `END` | ending_id | 结局（只能由导演发出） |

### 5.6 编译校验报告
- 附录 E 的 ID 是否一致；章节号冲突（合伙人、管理员等称号）一律以附录 E 为准并报警。
- 称呼是否越期使用。
- 每章是否以诚实信号收尾。
- 选项密度、单屏台词字数。
- 精修稿每更新一版就重跑一次，作为编剧自动审校。

## 6. 角色卡（参照附录 B）

### 6.1 字段
| 字段 | 内容 | 用途 | 必填 |
|---|---|---|---|
| identity | 名字、种族、身份、**成年锚点** | 合规、开场 | 是 |
| appearance | 部位表、服装、参考图 | 占位图标签；以后生图 | 是 |
| personality | 行为规律、价值底线 | 演绎约束 | 是 |
| speech | 自称、句尾、比喻系统、威胁库、口癖、"禁止写成的样子" | 风格检查 | 是 |
| honesty_signals | 部位 + 动作 → 心动 / 真生气 / 慌乱 | 第二信号通道 | 是 |
| address_system | 她叫玩家 / 玩家叫她、解锁条件、禁用期 | 称呼状态机 | 是 |
| taboo | 逆鳞（只能作剧情事件）、禁语区（不可喜剧化） | 守卫 | 是 |
| red_lines | 内容上限 | 守卫 | 是 |
| hidden_layer | 仅剧情系统可见 | 中后期剧情 | 否 |
| slots | 珍视之物、禁区、喜欢的食物等 | 节拍层替换 | 是 |
| assets | 立绘差分清单（占位/预生成/Live2D） | 演出 | 否 |

### 6.2 建卡流程（Web 建卡页）
1. 玩家粘贴一段人设描述。
2. DeepSeek 按 schema 输出 JSON，自动填满各字段（缺失字段标黄）。
3. 玩家逐字段修改。
4. 引擎校验：必填项、成年锚点、红线、诚实信号至少 3 条、称呼体系完整、槽位全部覆盖第一话所需槽位。
5. 校验通过 → 启用；失败 → 指出字段，不允许启用。
6. 新卡使用通用占位立绘（按情绪选差分标签），不现场生图。

## 7. 角色状态模型（C++ 状态机）

| 通道 | 含义 | 规则 |
|---|---|---|
| 好感度（嘴上） | 显示给玩家 | 单步限幅 ±5；傲娇缓冲：正向变化有一部分延迟到场景结束结算 |
| 诚实信号（真实） | 尾鳍 | 只能由节拍或导演按卡表触发；模型只能提议动作，不能自造新含义 |
| 关系阶段 + 称呼 | 心电图 | 称呼只能按解锁条件推进；越期使用由守卫拦截 |
| 伤口状态 | 生气 / 心死 / 和解 | 生气：称呼不断；心死：称呼除名；和解：称呼复位 |
| 心情 | 短期 | 随场景衰减 |

所有变化写入事件日志：`{turn, source(script|model|director), proposal, verdict, applied}`。

## 8. 导演：骨架 + 生长

每一轮流程：
1. **意图分类**（小模型或同模型低温度）：顺毛 / 诚实笨拙 / 作死 / 剧本外。
2. 能对上原选项 → 走原分支；鲸鱼小姐用锁定原台词。
3. 对不上 → `AI_TURN`：组装上下文（节拍目的、状态、可用称呼、可用差分、记忆召回）→ 模型通过工具演一轮。
4. 收束：导演按张力曲线决定引回下一汇合点，或开新分支。
   - Demo：剧本外输入在第一话内即兴，最多 N 轮后（默认 3）引回最近汇合点。
   - 新分支、新结局：接口与事件格式完整保留，Demo 不开放完整演出。
5. 结局只能由导演发出 `END`。

## 9. 守卫（写进代码）
- 逆鳞"回深海"：只能由导演作为剧情事件触发，一季一次；玩家打字触发不了，模型提议一律驳回。
- 禁语区：走专门处理，禁止喜剧化。
- 价值底线不可演反；悲剧可以写心碎，不能写性格突变。
- 成年锚点与对外红线。
- 风格检查：自称、句尾、禁用写法；不合格重生成，最多 2 次，仍失败则回退到节拍默认台词。
- 称呼越期检测。
- 错误选项触发吐槽/尾击，不 Game Over。

## 10. Agent 工具接口

同一份 schema 注册表生成工具定义。Demo 只在内部以 OpenAI function calling 调用；HTTP / WebSocket / MCP 外部暴露为预留。

| 类别 | 工具 | Demo |
|---|---|---|
| 读 | `get_scene` `get_beat` `get_relation` `get_available_addresses` `get_available_sprites` `recall_memory` `get_next_merge` | 实做 |
| 演出 | `say` `set_sprite` `honesty_signal` `play_sfx` | 实做（sfx 占位） |
| 提议 | `propose_affection` `propose_mood` `propose_branch` `request_ending` | 前两项实做，后两项走驳回/记录 |
| 记忆 | `write_diary` `write_memory` | 实做 |
| 生图 | `generate_image` | 接口预留 |
| 语音 | `speak` | 接口预留 |

每次调用都进入调试时间轴：工具名、参数、引擎裁决、理由。

## 12. 记忆

### 12.1 架构
- **灵枢（dsh-memory）底座**：MCP stdio；原文为真源；写入零 LLM；负责事实、事件、日记、存档落盘。
- **AGM 补位**：灵枢召回前 30 条作为种子，在 AGM 图上扩散激活；最终返回灵枢前 7 条 + AGM 激活最高的新条目 3 条；返回的永远是灵枢原文。
- AGM 图的边来自真实对话共现与时序（每轮玩家输入与角色回复同时激活的记忆条目）。
- 开关：`memory.agm_fill = on/off`。

### 12.2 写入时机
- 每轮：玩家输入与角色台词作为事件写入灵枢。
- 场景结束：`write_diary`（日记 = 记忆压缩，"记错细节，但记得自己"）。
- 存档点：快照 + 灵枢落盘标记。

### 12.3 实测依据（hive-memory-bench，机械层代理口径，k=10）
| 系统 | 证据保留 切A/切B | 另一侧覆盖 切A/切B |
|---|---|---|
| 灵枢 | 33.6% / 32.3% | 9/40 / 8/56 |
| 灵枢 + AGM 补位 | 39.2% / 32.5% | 9/40 / 11/56 |
| 灵枢 + AGM 重排 | 38.9% / 28.3% | 11/40 / 11/56 |
| BM25 参照 | 36.9% / 36.4% | 10/40 / 10/56 |

结论：AGM 帮助小且不显著，补位两切点均不劣于灵枢，故采用补位；纯重排不稳，不采用。加 BM25 式关键词桥的变体也无显著提升。AGM 换句向量、接入真实对话共现边后复测。详见 `docs/memory-bench.md`。

## 15. Demo 演示脚本（约 15 分钟，本人演示）
| 时段 | 内容 | 要展示的点 |
|---|---|---|
| 0–3 分 | 纯选项模式开场，走一个选项点 | 无 AI 也是完整游戏；好感与尾鳍分离 |
| 3–8 分 | 切 AI 模式，自由打字（含剧本外、作死各一句） | 原作语气接住；尾鳍出卖真心；守卫驳回越界提议 |
| 8–12 分 | 打开建卡页，现场写人设 → AI 填卡 → 改 → 启用 → 重演同一场 | 同一剧本换人演；节拍目的不变 |
| 12–15 分 | 调试时间轴 | 提议 → 裁决；她记住了什么、AGM 为什么想起它；可回放 |

## 16. 里程碑与验收

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| M0 剧本与卡 | 编译器；第一话 JSON/OP；鲸鱼小姐卡；校验报告 | 第一话 4 个选项点、10 处好感、存档点全部编译出；校验报告列出附录 E 冲突 |

| M2 AI 模式 | DeepSeek 网关；工具注册表；意图分类；导演 AI_TURN；守卫 | 剧本外输入能接住并在 ≤3 轮引回汇合点；"回深海"相关提议 100% 驳回；风格检查生效 |

## 17. 测试计划
- **回放测试**：固定种子与录制的模型输出，回放事件日志逐字一致。
- **守卫测试**：越界提议样例集（逆鳞、禁语、称呼越期、价值底线反转），全部驳回。
- **风格测试**：鲸鱼小姐的自称、句尾、禁用写法检查。
- **编译测试**：剧本每版重跑，ID 与计数对齐附录 E。
- **记忆测试**：bench 脚本作为回归；游戏内召回样例集。

## 18. 风险

| C++/Python 边界调试成本 | 只传 JSON；C++ 不回调 Python |
