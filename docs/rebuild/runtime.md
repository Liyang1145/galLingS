# 手动试用新剧情核心

新实现位于 `packages/story-runtime/src/index.ts`。它只依赖内容模型和纯计算，不导入旧播放器、Rust、后端、DOM、音频或系统时钟。**代码已编写，未运行、未类型检查、未验收；旧游戏入口未切换。**

## 终端试播

在仓库根，使用[规定的 Node 环境](README.md#真实命令与环境)：

```powershell
npm run story:dev
```

入口读取同一个作者源和 M1 转换实现，资源缺项会报错，不回落到旧解释器。没有浏览器、媒体或开发后端；不会写正式存档/玩家记录，也不会生成内容发行目录。

简短试用：

1. 输入 `walk`，直到出现选项；它只提交核心的“呈现完成/继续”，不自行计算分支。
2. 输入 `save`，再 `choose 1`，查看变量及目标节点。
3. 输入 `again` 重发同一操作，应该拒绝旧步骤；不会再次结算。
4. 输入 `load`，应恢复保存的位置和变量，无进入/结局新事实；这是内存逻辑快照，不包含场景播放位置和选择剩余时间。
5. 在限时选择处可手动 `timeout`，核心选择内容中指定的默认项；终端不实际倒计时。

`next` 在呈现阶段只确认“呈现完成”，下一次才请求继续。`save` 的快照退出后丢失；`walk` 最多 10000 次操作就停止，避免内容无交互循环占住终端。

## 公开接口与状态归属

创建方式为 `createStoryRuntime(content, playerProjection)`，返回 `runtime` 和首次进入的 `initial` 结果。`content` 必须来自当前校验转换器；不接受用类型断言冒充已校验的外部规范化 JSON。

| 接口 | 含义 |
|---|---|
| `view()` | 返回可重读的状态副本；不产生事实，不允许修改内部变量 |
| `dispatch(command)` | 串行消费者提交 `presented/advance/choose/timeout`，每条带当前 `step` |
| `snapshot()` | 导出已执行进入动作的逻辑状态，不包括运行回调、计时器、音频句柄 |
| `restore(unknown)` | 校验作品、格式、修订、节点、变量、只读玩家投影与阶段后整体采用；失败不部分改状态 |

阶段为 `presenting → ready/choosing → 下一节点/ended`。进入动作只在真实进入执行；选项动作在进入目标之前执行。命令采用候选状态计算，成功后才整体替换；内容错误不切换解释器。

每次接受命令或恢复都会换一个步骤编号；旧步骤回调与重复结算被拒绝。编号只保证**当前运行实例**内唯一，M3 游戏会话仍需代次取消，不能让旧运行实例的回调进入新实例。

结果分别提供可重读视图、本次 `entered/chosen/ending` 事实及 `enter/restore` 表现要求。恢复不发进入、选择或结局事实，不调用进入动作。事实尚未持久化，不承诺跨进程或跨存储“恰好一次”。

## 尚未接入的能力

- 没有真实游戏会话、有效计时、菜单/后台暂停、媒体播放或取消句柄。
- 只有逻辑快照，不是 M4 一致游戏检查点；没有持久化、回退历史、缩略图、玩家记录写入或旧档迁移。
- 当前玩家投影由创建者显式传入，快照保存该投影并按原样恢复，以免隐式访问全局记录。何时按真实持久化成果刷新投影仍属于 M4 产品规则，不在这里替用户决定。
- 表现恢复只标记 `restore`，不承诺重播语音、续播音轨或动画帧级恢复。
- 新核心尚未接正式入口、Windows、Android、编辑器或聊天。M0～M2 基础提交不能当作 M3～M7 完成。
