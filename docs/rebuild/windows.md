从 `39499a2` 接续原方案步骤 18。当前只编写 Windows 集成输入准备、独立原生入口和窗口生命周期接线；没有执行安装、准备命令、编译、启动、类型检查、测试、额外审查或子代理，没有生成 EXE 或安装包，尚未验收。

## 显式启用，保留旧入口

复用 `desktop/src-tauri` 的 Tauri 工程，新增 `rebuild-host` Cargo 特性及 `src/rebuild.rs`。默认 `main` 仍采用旧启动路径；开启特性才进入新宿主，且要求配置中的应用标识为 `com.gallings.haifeng.rebuild`，避免仅加特性就误用旧占位页。原 `tauri.conf.json` 不改。

新入口只加载已准备的共享前端，通过 Tauri 本地 HTTPS 资源地址提供包内文件；不启动或探测 Python 服务、不注册旧 `/__host/` 接口、不加载 WASM 解释器，也不在故障时回落旧实现。页面仍使用相同的 TypeScript 剧情核心和共享播放器。

当前采用前端与素材一同嵌入可执行文件的集成路径，用于先接通既有宿主，不作为最终资源分包、安装和分发方式的决定。新窗口拒绝远程页面导航及额外窗口；没有接聊天、旧原生接口或通用原生调用。后续显示扩展仅接布尔全屏目标，见下节。

## 输入准备

`tools/game/windows.ts` 提供 `npm run windows:prepare -- <产物摘要>`，仅接受 `game:build` 输出的摘要目录：

1. 严格读取随包清单，核对目录摘要，读取剧情并重现内容修订。
2. 按清单逐个核对前端、剧情、来源及素材文件的大小和 SHA-256；读取位置必须位于该游戏包内。
3. 只复制清单登记文件到独占的 `dist/windows/<产物摘要>/frontend/`，相同素材位置只复制一次；不扫描并带入其他文件。

同一目录存在时拒绝覆盖。准备失败保留本次不完整目录和诊断，不自动删除或重新利用；不能把目录存在当成成功。准备成功后也须保持目录原样，后续编译不是对被手改输入的再次安装校验。Tauri 编译还会处理页面注入等内容，输入清单不等同于最终 EXE 的字节清单或签名。

生成配置含当前机器的绝对构建路径，仅存在于忽略的 `dist/`，不得提交；正式游戏内容不包含该路径。没有改依赖版本或重新生成锁文件。准备命令不调用 Cargo、不编译，也不启动游戏。

## 窗口生命周期与会话

`packages/player/src/web/host-bootstrap.js` 是两端原生共用的最小状态桥，当前是 `haifeng.host-bridge/3`，Windows 在原生包含时替换平台标记。它公开 `read()` 快照；原生在页面加载完成、窗口焦点和尺寸变化时报告 `haifeng.host-state/1`，并每秒重采窗口状态。消息含平台、递增序号及暂停状态；初始化时先暂停，收到有效窗口状态后才恢复。失焦或最小化均暂停，原生读取窗口状态失败也报告暂停。

页面返回接收序号，原生校验确认并记录投递诊断；周期重采负责后续重试，销毁时停止任务。页面每秒检查宿主状态，超过 3500 毫秒没有新的有效序号则暂停并关闭声音，等待新快照。重复事件或旧确认不能刷新状态时效；这些参数只用于当前集成实现，没有执行故障或后台节流验证。

原生还在创建窗口前检查嵌入清单的 `haifeng.game-package/2` 及桥协议；不符合则拒绝启动。旧游戏包、准备目录须按新命令重新生成，不能继续复用旧 `/1` 产物。Windows 不经过 Android 音频请求通道，继续使用浏览器播放权限与媒体诊断。

`apps/game/src/platform/host.ts` 校验桥和消息，桥侧忽略过期消息，读取侧发现缺失或无效消息则显示诊断并暂停；普通浏览器继续使用原有标签页生命周期。状态桥不接收剧情命令或变量，不承担存档操作。

应用把宿主状态接到会话 `host` 原因，网页隐藏仍使用独立 `background` 原因；菜单、回看和媒体暂停也分别保留。读档及回退的准备改用 `operation` 原因，不能因准备结束而解除原生窗口暂停。

会话新增可选 `initialPauses`，只接收当前 `host/background` 状态，在首次呈现前生效。开局、读档或重开时重新采用当前生命周期状态；窗口恢复只更新暂停状态，不进入节点、不补算后台时间、不重置选择计时。

焦点和最小化之外，后续已编写下节的独立休眠/唤醒通知。Windows 声音输出监听后端已编写但未实例化或接入页面许可，异常退出及系统回收恢复仍未接入，不能据此宣布完整生命周期验收。

## 系统休眠和唤醒

从 `6d38b74` 接续，`src/rebuild_power.rs` 只在 Windows 重构特性路径登记系统电源回调，不接存储、剧情或页面命令。通过固定系统目录的 `powrprof.dll` 动态取得 `PowerRegisterSuspendResumeNotification/PowerUnregisterSuspendResumeNotification`，不新增 Rust 依赖或静态导入这些电源函数；系统模块、导出或登记不可用时明确拒绝本次重构宿主启动，不冒充已经监听。

微软文档规定该登记接口面向 Windows 8 及以上桌面应用；这里记录真实接口能力，并未据此承诺游戏最低系统或通过相应设备验收。动态探测只让缺少能力的系统有明确失败路径，不提供旧系统替代实现。旧默认宿主、配置、依赖锁、准备格式、随包 `/2` 及基础桥 `/3` 均保持；需在统一测试阶段编译当前宿主源码。

| 系统事件 | 原生状态与交付 |
|---|---|
| 休眠预告 | 记录暂停和新的中断代次，唤醒已有宿主状态线程尽快投递暂停 |
| 自动唤醒 | 保持等待交互恢复，并产生新的中断代次；不能仅因窗口仍为焦点而恢复 |
| 交互恢复通知 | 更新为已恢复，但仍等待本页桥接受该中断代次的暂停回执，以及窗口焦点/最小化条件允许 |
| 紧急恢复、计数耗尽或内部状态异常 | 保持暂停并记录诊断，不能以默认值伪装恢复；须停止后重新启动 |

休眠和唤醒都保留独立代次。即使两个通知之间 WebView 没来得及执行，唤醒后的原生状态仍要求本页桥先接受暂停，不会只看到最终“已醒来”就跳过整次中断。暂停采样与宿主序号分配在同一短锁内完成，旧采样不能取得比后来中断更新的序号；页面继续用原桥拒绝乱序状态。

原每秒状态线程增加通知唤醒，不新建剧情计时器；有效页面的暂停接收回执也可唤醒线程重新采样。回调只更新同步的内存状态并发出唤醒，不等待 WebView、做文件 I/O、自动保存、阻止系统休眠或执行剧情。焦点/最小化与电源条件合成原 `host` 暂停；菜单、后台、回看、操作准备及媒体原因仍由原会话分别持有，不由电源恢复一并清除。

这里确认的是**本页桥已接受暂停状态**，不是保存成功或核心步骤已完成的收据。系统通知与脚本送达的先后、正常休眠剩余时间和媒体接续仍须真实设备验证；未及时收到预告、紧急断电/系统冻结/进程强杀不在正常通知保证内，不以唤醒后的时长倒算、撤销已提交选择或伪造恢复点。本片没有实现新的时钟协议或进程回收恢复。

### 页面身份和清理

Windows 初始化脚本为每个本地主文档生成私有只读身份，独立于可选全屏/文件记录能力，不进入存储。载入完成后先读取并核对该身份，再登记本次页面代次；读取失败保持未就绪，已有状态线程可继续尝试。每条宿主状态脚本核对原身份，原生回执再核对页面代次/就绪及中断代次，旧页面排队脚本、回执或旧中断不能解除新页面的暂停。缺少可选全屏扩展仍不阻断基础状态。

窗口销毁先停止状态投递、清空页面绑定、标记电源监听停止并唤醒线程；线程退出时注销原登记。回调参数及其空上下文保留进程生命周期，迟到回调不持有窗口、页面或已释放的堆对象。注销未确认时保留系统模块引用到进程结束并报告错误，不卸载仍可能被使用的模块，也不把失败当成正常退出写入许可。登记期间到达的通知不被成功返回时的初始化覆盖。

## 声音输出监听后端

从 `aa9beca` 接续，新增 `src/rebuild_audio_devices.rs`，只编写 MMDevice 通知和默认播放端点读取。模块已登记到 Windows 重构特性范围，**尚未实例化、创建线程或接入声音许可/页面桥**；普通启动行为没有由此切换。本片未查询本机设备、编译、运行、测试或验收，不表示输出设备中断已生效。

`Monitor::open/inspect/wait` 及释放须在同一专用 MTA 工作线程内执行；原始 COM 指针使监听对象不能跨线程移动。它只查询系统现有的三个播放角色默认端点及活动状态，不激活声音流、采音、修改默认设备或读取玩家数据。可跨线程传递的 `Wake` 仅唤醒该原线程，不能选择设备或发剧情/存储操作。后续许可层须自行持有线程、取消和原页面/请求身份，不能直接把监听对象搬到 WebView 界面线程。

对外 `Inspection` 只有变化代次、是否存在活动默认播放端点、本次读取是否稳定；稳定要求读取前后未观察到新的相关通知。它既不是浏览器播放许可，也不是某次恢复请求成功的回执，不自动恢复、暂停会话或授予播放。代次耗尽、无效返回、设备读取失败和不支持状态明确报错；缺少某一角色的默认端点只按原 API 的明确“不存在”结果处理，不把其他异常当空列表。多个角色使用同一端点时内部去重，不解析或重造设备身份。

### 回调和身份

- 默认播放角色变化产生新代次，录音角色变化不采用；当前默认播放端点的状态变化或移除同样产生新代次。新增但未成为默认的设备、普通属性变化不改变播放许可。
- 系统设备 ID 按不透明、完整 UTF-16 原值比较，不解析其结构、按名字/下标匹配或输出给页面/日志。内部字符串以 4096 个 UTF-16 单元为当前实现上限，超限/非法值拒绝，不裁切成另一个身份；没有进入持久记录或产物。
- `IMMNotificationClient` 回调只访问原子状态、借用已发布的不可变身份快照并发出事件唤醒；不等待锁/工作线程，不查询 COM、不创建字符串或注销/释放最终引用。读者计数保护旧快照，替换和等待旧读者完成均在工作线程执行，不让回调等待。
- 每次相关通知递增代次，即使多次通知合并成一次线程唤醒也不会据最终可用状态假定中途没有变化。默认角色的多次回调可以分别递增代次，不将该数字当作设备数量或剧情次数。

### 生命周期与后续接点

回调对象保留独立拥有引用和登记期引用；注销确认后才释放，系统枚举器先于 COM 线程环境释放。注销失败或未确认时标记停止、保留原生对象/信号资源到进程结束，迟到通知不再推进代次；不释放仍可能被系统借用的对象或把异常清理当成许可。系统返回未支持的成功类状态也不冒充已登记。

接口由固定的最小 C ABI 声明接入，没有新增依赖、安装 SDK、生成绑定或变更 Cargo 锁；私有对象/字符串未暴露到通用宿主接口。当前 Rust 文件只有显式构造才会接触系统声音，导入模块不登记监听。源码读取依据为[微软 MMDevice 接口](https://learn.microsoft.com/en-us/windows/win32/api/mmdeviceapi/nn-mmdeviceapi-immnotificationclient)、[登记及引用所有权](https://learn.microsoft.com/en-us/windows/win32/api/mmdeviceapi/nf-mmdeviceapi-immdeviceenumerator-registerendpointnotificationcallback)、[注销及回调约束](https://learn.microsoft.com/en-us/windows/win32/api/mmdeviceapi/nf-mmdeviceapi-immdeviceenumerator-unregisterendpointnotificationcallback)和[微软 SDK 头文件](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/mmdeviceapi.h)，不是代码审查或运行结论。

下一片须把监听放入专用线程，并接原“启用声音”通道的 Windows 请求/回执、原页面和变化代次保护。设备变化不能自动把后来出现的设备视作旧请求目标；先处理本页许可及明确重试，再复用共享表现和原暂停，不能以此新设解释器、静默写入或决定正式平台默认。

留待统一测试：实际默认播放角色切换、已用端点移除/停用、录音端点/无关设备变化、多个角色共用端点及快速切换；身份超限/状态异常、登记失败、查询期间变化、并发回调/快照替换、线程退出和注销失败的原生资源生命周期。所有这些情景未执行；后端读取稳定不等于 Windows/WebView 实际能播放或全生命周期验收。
