# 编辑器的检查点初始条件预览

这是 M6 的预览恢复切片，对应原设计第 13.1 节。已经编写并接入[独立编辑页](editor.md)，未启动、类型检查、测试、构建或验收。恢复复用原 M4 检查点和共享会话，不另写编辑器剧情解释器，也不改变正式玩家的读档规则。

## 当前操作

沿用仓库根 `npm run editor:dev`，没有新增命令、服务端 API 或依赖。“检查点初始条件预览”位于制作区，留在预览全屏/游玩快捷键范围外，不套游戏按钮声音。

1. 正常开局或从所选节点预览。场面就绪、文字完整且处于非结局 `ready/choosing` 时，可以点击“捕获当前预览检查点”；限时选择可先暂停再捕获。
2. 捕获由 `GameSession.captureCheckpoint(token)` 在同一队列中完成，得到当时已经生效的变量、目标场景、计时及声音位置。继续预览不会更新这个分离副本。
3. 可以导出最近一次已校验的检查点 JSON。它只供制作预览，不是第二作者源、整套工程或正式玩家进度槽位；没有主动写入数据库或作者文件。
4. 从本机选择此前导出的 JSON，先在本页读取 UTF-8 与文件头，不执行或上传文件。此时明确标为待校验，不启动预览，不以“文件已读”冒充可恢复；最近一次已完整校验的数据仍可导出。
5. 每次显式选择本句静音、重播或尝试续播，再点击“从待用检查点继续预览”。先通过原编辑 API 转换当前草稿，然后在浏览器对检查点完整校验，成功后才取消旧预览、建立新的共享会话。

转换请求仍只发送原有 `haifeng.author-text-patch/1`，不包含检查点、文件内容或玩家资料。导入只选取本机文件；导出请求浏览器下载，没有共享、上传或自动写回动作。刷新、关闭或热替换会丢失本页保留的检查点，需要提前导出。

## 独立封装与身份

`apps/editor/src/checkpoint.ts` 定义内部 `haifeng.editor-checkpoint/1`：

| 字段 | 含义 |
|---|---|
| `format` | 明确的编辑器预览命名空间 |
| `workId` | 作品身份 |
| `contentRevision` | 未改临时入口前的规范化草稿修订 |
| `selectedEntry` | 正常开局为 `null`，所选节点预览为原临时入口的稳定节点 ID |
| `checkpoint` | 原 `haifeng.game-checkpoint/1`，沿用同一核心/媒体/计时校验 |

`readPreviewCheckpointInput` 只读取严格文件头，未知字段、格式或非法身份拒绝；检查点体继续保持 `unknown`。`inspectPreviewCheckpoint(content, input)` 核对作品和**完全相同的当前草稿修订**，按原临时入口构造相同预览内容，再调用 `inspectGameCheckpoint` 完整校验、`prepareGameRestore` 准备实际恢复状态。封装保留原捕获数据，预览初始条件显示准备后的计时及关闭自动/快进的状态。没有改写快照修订、按节点下标猜位置或跳过动作/计时校验。

所选节点预览原有的 `editor-preview:<起点>:<内容修订>` 临时身份沿用，封装另存其起点；从这个检查点继续不重新进入临时起点。当前编辑列表选中哪一项不改变文件中的原预览身份，也不改变真正恢复的节点。

文字草稿变化也会改变内容修订。当前入口拒绝跨修订恢复，不将旧检查点自动套进新对白、演出或路线。可以采用匹配草稿再重新预览，或从新草稿继续并捕获新检查点。本片不决定正式存档兼容、作者源迁移或跨修订编辑预览策略。

文件最多 4 MiB；UTF-8、JSON、封装、修订、变量、阶段、选项、场景停奏、音轨身份和计时均须通过各自读取器。只接该预览封装，不接受 `haifeng.save/1` 游戏槽位、裸旧档或不带来源身份的逻辑快照。即使数据可恢复，也只说明结构合法，不证明它来自实际完整路线；人工或改写文件的初始条件不能冒充路线验收。

## 恢复与隔离

`EditorPreview.start` 现在显式区分正常入口、所选节点和检查点三种启动方式。检查点及本次语音方式在取消旧预览前准备；格式、版本或状态校验失败时，当前预览及草稿保留。通过校验后，仍由 `createGameSession({ resume: { checkpoint, voice } })` 恢复，不先开局再跳转。

页面持续显示检查点恢复模式、恢复节点、保存时玩家投影及本次语音方式；展开预览状态可查看初始变量、计时、声音及当前变量。只使用检查点保存时的 `周目/结局数` 作为这次隔离预览的显式初始条件，不读正式玩家全局记录，也不把它写回任何成果。这不改变正式游戏读档使用当前已提交全局投影的既有规则。

共享恢复关闭自动/快进，保留必要的剩余有效等待，恢复稳定目标场景和完整文字；不重新执行进入动作、一次性进入音效或结局事实。声音仍按每次明确的 `silent/replay/resume` 处理，缺少可续播位置时沿用共享诊断，不补造零位置。已读从新预览的空内存集合开始，检查点不导入已读、对白回看、偏好或聊天。

捕获核对原会话和呈现代次。面板的文件读取/捕获另有代次，停止、换预览、草稿变化、作者操作、清除及离开会拒绝迟到结果；不可中止的浏览器文件读取结束后也不能覆盖后来选择。取消读取不改变当前草稿或旧预览。销毁时取消监听并释放待用项、已校验项与预览内容引用。

文件头读取成功只更换待校验项。完整校验成功或捕获成功才替换最近已校验项；读取或校验失败不能丢掉它。可以导出最近已校验项后重新选择，清除按钮则明确清除本页的全部检查点数据。这里没有多槽位管理、自动保存、正式玩家存储接入或新旧档迁移。

## 留待统一测试

本轮没有执行以下操作：

1. 正常开局完整显示对白后捕获，记下节点及变量；继续几句，选择本次语音方式恢复，核对保存状态且不重复进入动作。再试从所选节点预览捕获，当前编辑列表切到其他节点后恢复仍采用原检查点身份。
2. 在 `pm8x8v2h` 限时预览中等几秒、暂停、捕获，再选择进入后续节点。恢复检查点应使用原变量与剩余时间，点击/超时仍只结算一次，不补成 15 秒。
3. 导出、停止或刷新编辑页，在同一修订导入；文件头读取不应改变预览，选择语音并继续后才采用。查看浏览器请求，检查点内容不得进入编辑 API 请求或玩家存储。
4. 修改一个对白后尝试恢复旧检查点，应该明确拒绝修订不同并保留现有预览；换作品、错误临时入口、非法变量/媒体/剩余时间和未知字段分别拒绝，不静默修复。
5. 试用静音、重播和活动语音续播；背景音乐继续/停奏及环境声符合保存场景，恢复不重放一次性进入声音。后台和媒体失败仍由共享会话暂停或重试，不增加变量。
6. 捕获或读取文件时停止、换预览、改草稿、清除或关闭；旧结果不得覆盖新选择。输入非 UTF-8、损坏 JSON、游戏槽位或超限文件时，已有已校验数据仍可导出。
7. 回到正常游戏查看玩家槽位、全局解锁和偏好，制作操作不得改变它们。预览检查点内的玩家投影只用于这次明确标注的初始条件，不作为通关或路线验收证据。
