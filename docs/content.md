## 分章作者格式与写回

### 去哪里修改

| 文件 | 负责什么 | 编辑注意 |
|---|---|---|
| `content/story/project.json` | 作品身份、标题、正式起点、章节身份和文件顺序 | `chapters` 数组决定全作顺序，不按目录/文件名排序 |
| `content/story/chapters/chapter-01.json` ～ `chapter-16.json` | 十六话正文 | 每章独立；`nodes` 数组决定章内顺序 |
| `content/story/chapters/extra-01.json`、`extra-02.json` | 两篇番外 | 与正文使用相同格式，可以跨文件引用节点 |
| `content/story/chapters/opening.json` | 正式开局之前的两个原节点 | 保留原身份和位置，章节标题为空，不作为正常开局 |
| `content/story/variables.json` | 变量名称、类型和初始值 | 使用明确的 `name/type/initial`，数值初值不再包成字符串 |
| `content/story/settings.json` | 作者声音、阅读、封面、主题等默认 | 不属于玩家偏好或进度；原设置及绑定保留 |
| `content/story/resources/backgrounds.json`、`characters.json` | 背景、立绘登记 | 资源键等于资源 ID；这里只登记，不搬动素材 |
| `content/story/resources/music.json`、`sounds.json`、`voices.json` | 音乐、音效、语音登记 | 原种类、增益、制作及收藏元数据保留 |
| `content/story/resources/index.json` | 全部资源身份的原始顺序 | 必须恰好覆盖五种分类，不能遗漏或重复 |
| `content/story/origins.json` | 原作品元数据、迁移来源和节点映射 | 不是日常对白文件；保留来源记录，不重新生成基线 |

当前为 19 组、3315 个节点、1115 个资源身份和 167 个选项身份。资源原文件仍在 `海风与布丁/assets/` 等既有位置，`A素材库/`、母版、WAV 与授权/生产证据没有删改。

### 修改一章的对白

打开所属章节 JSON，按稳定节点 `id` 找到 `speaker/text`，只修改需要的字符串即可。章节不是运行存档，文件名、数组下标或台词文字都不是节点身份。

章节根具有 `format: "haifeng.author-chapter/1"`、稳定 `id`、`title` 和 `nodes`。`title` 是原章节标记，编译时只放在本章首节点；节点中不再重复保存 `chapter` 字段。空标题用于没有章节标记的开局节点组。

节点仍使用可直接创作的 `speaker/text/bg/sprites/set/choices/jump/jumpIf/bgm` 等字段；`set/cond/jumpIf` 是受限表达式文本，不要求作者写表达式树。场面、演出、等待、原音乐继续/停奏和全部来源提示仍使用现有编译语义，不重新设计游戏规则。

`choices` 和 `sprites` 当前必须是明确数组，空内容写 `[]`；不是任意字段都允许省略。未知节点/选项/立绘/音效字段会明确报错，不能靠保存静默丢弃。JSON 重复对象键也拒绝。

已有独立对白编辑仍只开放原节点中已经存在的 `speaker/text` 字符串。此次只适配其源读写，没有恢复完整制作编辑器开发，也没有开放选项、演出、变量或资源写入 API。

### 修改顺序、选择与跨章跳转

- 正常起点由作品清单 `entryNodeId` 明确指定，当前仍为 `fhww88n3`，不因目录顺序改变而重新猜测。
- 同章最后一个节点仍可顺序走到下一章首节点。拆分文件不会自动插入结局或结束。
- `jump` 与选项 `target` 直接写目标节点 ID，可跨章节；旧标签仍保留为定位文字，但不再参与目标身份解析。
- 空的选项目标仍表示全作顺序中的下一个节点，不是下一个文件名或局部下标。
- 每个选项明确保存固定 `id`，迁入的是原 `choice-000001` 等身份。改文字或移动选项不重算 ID，也不再依赖原文匹配基线。
- `ctime` 继续使用作者秒数；`cdef` 改为本节点的默认选项 ID。默认项不存在、不是本节点选项或无倒计时却给出默认项都会报错。
- 不能复用已有节点/选项/资源身份表达另一项内容；新增内容需要新的唯一身份。
- 章节文件名与章节 ID 只接受小写字母、数字和连字符，文件须直接位于 `chapters/` 下。改名时须同步作品清单，不用路径跳转引用外部文件。

### 共享读取与来源定位

```text
content/story/project.json + 登记的分章/变量/设置/资源/来源
  → tools/content/source.ts：严格读取、路径边界、原文件集合摘要
  → tools/content/compile.ts：表达式、节点身份与流转编译
  → tools/content/build.ts：实际素材读取与内容修订
  → 游戏构建 / 开发页 / 终端 / 编辑候选预览及保存
  → 同一个 TypeScript 剧情核心
```

构建只将合成的 `haifeng.story/1` 发给运行端。分章作者文件、旧解释器和 Python 投影不进入游戏运行依赖，正式离线约束不变。

诊断记录真实章节文件与章内 `nodes.<下标>`；稳定节点 ID 单独保留。索引只用于定位，不用于恢复存档或补分配身份。资源诊断指向所属分类文件。

作者摘要现在是**完整登记文件集合**的摘要：按相对文件名排序，为每个文件记录原字节 SHA-256，再用共享规范化表示计算 SHA-256。修改任意登记章节、设置、变量、资源清单或来源都使旧草稿基线失效；只核对作品清单 mtime 不足以判定最新。

来源清单不读取未登记的临时文件，也不把备份作为第二作者源。作者总字节上限为 16 MiB；JSON 有深度/字段数量限制，链接、越界、未知格式与重复身份明确拒绝。

### 保存涉及多个章节的对白草稿

现有补丁仍为 `haifeng.author-text-patch/1`，其 `sourceSha256` 现在绑定整个作者文件集合。请求仍只有节点身份、字段、原值和新值，不能指定磁盘路径。

1. 取得固定 `content/story/.author-lock/` 合作锁，重新读取全部登记源，核对原摘要与每个原字符串。
2. 只在涉及章节中替换准确字符串 token，其余内容/格式保留；未涉及章节不写回。
3. 候选复用同一编译及素材检查；先准备全部变更章节的原文件备份、候选和事务记录，再替换任何正式章节。
4. 原文件备份与事务说明留在 `content/story/.author-backups/<本次事务 ID>/`，候选及活动记录位于 `.author-lock/`。原文件集合摘要和各替换文件的前后摘要均登记。
5. 替换前重读全部源，逐文件重查原字节和候选，替换后核对完整新源摘要。成功才释放自己的锁；失败或中断保留恢复材料，不自动继续下一次写入。

所有共享源读取在锁存在时拒绝继续，因此合作写入期间不会把半替换的章节集交给构建或预览。**这不是跨文件原子 rename，也不保证对抗绕过合作锁的外部编辑器或断电时的磁盘持久性。** 网络失败仍不代表肯定未写入；页面须保留草稿并重新读取确认。

#### 处理未完成的作者事务

不要直接删除锁然后继续构建，也不要在章节之间猜测采用哪一份：

1. 先停止所有作者写入，查看锁内 `transaction.json` 与对应备份目录的同名记录。准备尚未完成时可能只有 `owner` 或部分候选，尚不能据此声称有正式文件被替换。
2. 有完整记录时，根据 `replacements` 的相对文件与前后摘要判断各正式章节处于原版、候选版还是外部第三种状态。原版备份只包含本次会改的章节，不能整目录覆盖作者源。
3. 明确选择恢复全部原变更章节，或补齐同一事务的全部候选；第三种状态须人工比较，不静默覆盖。未改文件也要与记录中的 `originalFiles` 核对。
4. 确认整个集合一致后，再手动移走本次锁，保留备份与失败候选供追溯。当前没有自动恢复命令，不声称强杀/断电恢复已验证。

### 旧制作与托管的保留边界

`tools/author_project.py` 只从新分章源组装旧制作所需的数据对象，不执行条件、动作或剧情流转，不写作者源。它恢复旧标签式目标及旧变量表示，仅供保留的 Python 导出、素材索引和旧制作服务静态投影；新 TS 本体不依赖它。旧 OP/Rust 托管导入与回放随后已[成组退役](<migration.md#retired>)，不再消费此投影。

- 旧本机服务原 `/vn/<作品>/game.js` 地址为内存生成的只读响应，设置 `no-store`，不再读取磁盘中的旧作者文件。
- 旧制作 HTML 模板、播放器、素材目录和导出工具保留。直接双击仓库旧 HTML 不再有嵌入剧情，应明确提示使用本机旧制作服务或新本体，不能悄悄打开空项目冒充当前作品。
- 外部独立旧项目与导出仍可使用自己的 `game.js`。它们不是本仓库作者源，不承诺自动回灌。新作者能力超出旧投影可表达范围时可拒绝，不将旧格式作为新格式的能力上限。
- `tools/game_data.py` 对原本仓库 `game.js` 地址的读取转入只读投影；对该地址或新作者目录的写入直接拒绝。旧浏览器制作工具也拒绝向带 `author-source.json` 标记的原目录或新作品清单目录导出覆盖。
- 历史生产批次脚本及其来源报告不重跑、不批量重写。新增采纳工作应直接面向分章源独立实施，而非恢复旧 JS 写回。

### 修订、兼容与迁移记录

迁移输入为 `c64a64b` 的原作者文件及原 `choices.json`。精确原文件摘要、来源提交、各组原起始下标和全部节点 ID 映射保存在 `origins.json`；基线文件继续保留为历史证据，但新读取/构建不再消费旧选项原文映射。

`haifeng.story/1`、检查点、进度、玩家成果及偏好载荷格式不变；内容修订算法不改。由于作者来源文件及节点定位已经改变，**内容修订会改变**，旧修订的检查点/预览补丁不能直接改哈希冒充匹配，仍由原校验拒绝。没有新增旧档兼容或进度迁移。

游戏来源产物将登记 `authorFiles`（完整作者文件相对路径/字节数/摘要），取代构建期的 `choiceIdentities` 摘要；随包清单协议不变。编辑器本机运行输入不再绑定基线选项映射，旧编辑产物须重新构建，不能混用新后台与旧清单。

## 内容编译与模型校验

### 手动生成内容

在仓库根、满足[环境要求](<README.md#commands>)后，由用户选择运行：

```powershell
npm run content:build
```

入口只读取作品清单登记的纯 JSON 章节、变量、设置、资源分类/顺序和来源，拒绝重复键、越界路径和作者事务锁存在期，不执行作者 JavaScript。失败输出真实章节/资源文件、节点和字段诊断。素材路径仍位于原本地作品目录，符号链接越界拒绝；不联网补资源。

成功时生成不可手改的 `dist/content/<内容修订>/story.json` 和 `resources.json`。读取全部登记资源并计算 SHA-256，登记不等于已安装；任一缺失资源会阻断此入口。相同修订目录已存在时不会覆盖，当前实现会报告写入失败并保留原目录。临时生成目录失败后清理，不删除作者文件。

这是**内容阶段产物**：资源文件尚未复制进该目录，manifest 明确标记源资源基址，不可直接作为 Windows/Android 游戏安装包。[游戏随包入口](<delivery.md#delivery>)复用同一来源读取器，另外装配前端并复制资源，不改变这条命令的内容阶段职责。

### 协议与来源

`haifeng.story/1` 是内部内容格式标识，不是产品版本号。作品 ID、节点 ID、资源 ID、中文变量名、节点顺序保留；入口显式来自作品清单的 `entryNodeId`，当前仍为原首章起点。没有给游戏编发售版本。

| 输入 | 发行模型 |
|---|---|
| 声明变量初值 | `name/type/initial` 明确固定类型并核对初值；迁移时原 `"0"` 已转数值 0 |
| 节点 `set` | 进入动作数组；表达式树不包含任意代码 |
| 稳定节点跳转 | 作者 `jump/target` 直接保存节点 ID；跨章引用先全局核对，缺失目标拒绝 |
| 显式选项 ID | 已迁入原固定身份；直接读取章节中的 `id`，不再按文字或位置查旧基线 |
| `ctime/cdef` | 毫秒时长和稳定默认选项 ID；不可用默认项明确报错，不暗选第一/最后项 |
| `bg/sprites/mood/bgm/ambience` | 完整目标场景；空音乐显式停奏；相同曲目继续意图独立于资源文件路径 |
| `trans/fx/acts/voice/seEvents` | 演出、语音和一次性声音与稳定场景分离 |
| `_musicCue/motionCount/amb*` | 明确保留为来源提示，不伪称已有表现消费者 |
| 资源附加字段、作品元数据与设置 | 原样 JSON 来源记录，不作为新核心指令 |

已知节点、选项、立绘、音效字段之外出现扩展字段会阻断转换，不能开了再存就丢失。根作品元数据及资源元数据作为来源保留。新的可写跨局变量、主线 Agent 节点尚未实现，出现时明确拒绝。

`packages/story-model/src/content.ts` 现提供 `readStoryContent(unknown, file?)`，读取规范化 `haifeng.story/1` JSON。它逐字段校验格式、变量及初值、受限表达式树及类型、可写动作、节点和选项身份、目标、限时默认项、媒体种类、完整场景、演出参数和来源；未知字段明确拒绝，不把外部 JSON 断言成 `StoryContent`。

表达式限制 128 层嵌套与每棵树 4096 项，复用已有表达式类型规则。数据读取保持节点、选项和资源数组顺序，不执行进入动作、不创建剧情核心、不加载媒体。表现枚举仍由具体表现适配器报告支持范围，不在读取时静默过滤作者指令。

`packages/story-model/src/package.ts` 提供随包清单读取和作品/资源身份核对；`integrity.ts` 提供共享的规范化序列化和内容修订输入。内容修订算法保持原有字段及排序，不把随包安装位置加入剧情修订；此次真实作者文件/节点定位改变会使修订改变。`loadSourceContent` 读取完整分章集合后调用 `compileSourceContent(project)`，额外返回 `authorFiles` 原文件摘要清单；[独立编辑入口](<editor.md#editor>)的候选预览和保存复用同一编译与资源读取，不增加另一套内容解释规则。

这些读取器已经编写；浏览器接入和游戏产物状态由[随包加载说明](<delivery.md#delivery>)维护，不由本页宣称已运行。内容阶段的 `resources.json` 仍不是随包游戏清单。

作者 `settings.uiSe` 仍在来源设置中保留；共享表现及会话创建时通过纯[提示音映射读取器](<player.md#feedback>)校验已配置资源身份及字段，显式 `favorVar/tailVar` 须指向声明的数值变量。当前接选择、限时循环、手动存档、变量/CG/话末、事务首次解锁结局及操作按钮反馈；不更改规范化剧情或内容修订格式。

作者 `showStats` 由独立[话末数值偏好](<player.md#readout>)读取为布尔默认，缺省关闭；原 uiSe/soul 中的显示变量绑定按实际优先序由纯读取器提供。只对原存档点正文构造表现副本，不改变作者文本、规范化内容、变量动作或核心插值；同一绑定也进入只读引用查询，不因此启动旧聊天或网络。

资源的 `audioCategory/auditionOnly/name/dur/playbackGain` 仍保留在原元数据中，由共享[声音收藏读取器](<player.md#audio-library>)消费实际标记和字段，目录/混音共用同一规则，不猜分类或改变内容格式。共享目录及独立试听已接开发主页。

作者 `settings.theme/cover` 仍在来源设置中原样保留，由纯[外观读取器](<player.md#appearance>)消费，检查字段、枚举、颜色、有限数值及图像资源种类。原鲸鱼 SVG 和图标已经拆至 `content/game-ui/`，新装配读取独立定义，不再从旧 HTML/播放器/CSS 提取；保留原字节及迁移来源，不新增剧情资源 ID 或第二剧情作者源，原 B38 装饰图片仍是实际输入。

`packages/story-model/src/references.ts` 已编写已校验内容的[只读结构索引](<editor.md#references>)，按带类型的稳定身份查节点/资源/变量/选项/立绘/结局使用位置，不执行条件或动作、不推断路线可达性；编辑页可附当前对白草稿及共享播放器实际消费的设置引用。`text.ts` 提取原对白占位规则，查询与唯一核心填充共用；未知名字仍保留原文，查询中标明未解析。没有改变内容格式、修订算法或作者写回范围。

`author-history.ts` 的纯 `AuthorDraftHistory` 已接编辑页，按同一源摘要、已有字符串和原值管理当前草稿及有界[撤销/重做](<editor.md#editor>)。单字段和导入沿用原修改协议，导出仍只有当前修改，不增加历史字段、磁盘写入或剧情接口。

### 受限表达式的有意差异

支持字面量、声明变量、只读 `周目/结局数`、括号、一元 `!/-`、四则运算、比较与逻辑组合；修改仅 `= / += / -=`。字符串加法只接受两侧字符串；数值运算不隐式转换字符串。未知变量、类型冲突、除零、非有限数值不会像旧实现那样默认零或警告后继续。

当前作品实际使用数值增减、赋值及简单比较，因此不靠旧导入器的整数正则限制新模型。新解析器使用常规一元运算优先级；未来若出现旧语法 `!x > y` 等歧义表达式，必须先显式加括号确认含义，不作为默认兼容承诺。运行中的表达式错误由核心保持旧状态并报告，不能部分执行。

内容修订由规范化内容与实际资源校验值共同生成；对象键顺序和源 JSON 空白不参与修订，节点/选项顺序参与。原文件 SHA-256 单独保留以追溯。元数据当前也参与保守修订，尚未提供跨修订兼容映射。

<a id="directories"></a>

## 内容目录职责

content/story 是唯一可编辑作者源；content/game-ui 保存独立图形定义；content/cards 是辅助聊天的角色卡输入。content/assets、原稿与 A素材库按真实消费者及来源保留。公开仓库不代表内容已经开源授权，作者内容不带玩家记录或机器配置。

<a id="game-ui"></a>

## 游戏界面资源

这里是新游戏界面的独立资源定义，不是另一份剧情作者源。剧情只读 `content/story/project.json` 登记的分章作者源。

- `whale.json`：原菜单、选择、对白三个 SVG 的完整 data URL，保留原 base64 载荷。
- `collection.json`：声音收藏和底部操作栏的 11 个原图标形状，以及原配乐装饰图的位置。只保存现有形状字符串，不加载或执行旧播放器。
- `origins.json`：迁移时的原提交、原文件/标记区摘要和新定义文件摘要。它是固定的迁移来源记录，`targets` 记录迁移当时的字节，不充当以后每次构建的当前摘要。当前字节由读取器和游戏包来源记录登记。保留来源不等于素材授权已核验。

新开发入口和游戏构建通过 `tools/content/appearance.ts`、`collection-appearance.ts` 读取这些定义。原鲸鱼 SVG 和图标只在本目录维护新链路，不再从旧 `index.html`、`player.js` 或 `game-polish.css` 同步提取；不改旧入口中的声明，也不建立双向写回或遇错回退。

原配乐装饰继续读取 `海风与布丁/assets/bg/scenes/B38.webp`，没有搬动、复制、改版或删除原图片。它与剧情目录中的 `assets/art-upgrade/B38.webp` 不可互换。封面、主题配置及剧情素材仍从唯一作者源和现有资源登记读取。

只读装配保留 SVG、图标、WebP 和路径校验。游戏包 `content/sources.json` 记录当前定义摘要及历史来源；运行端只使用前端内嵌字节，不请求这些制作定义或旧界面文件。
