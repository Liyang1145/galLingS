# 任务名称

> 新任务复制为独立文件，使用能辨认工作的文件名；不要让所有人修改这份模板。用户明确要求优先，不因填表增加额外审批。

- 负责人 / 执行 agent：
- 状态：未申报 / 进行中 / 待依赖 / 待集成 / 已集成 / 已验证
- 更新时间：
- 任务分支：
- 基线提交：
- 交付提交 / PR / 私有附件：

## 本次目标与影响范围

具体问题、预期行为、涉及的文件/资源ID/运行层。

## 兼容变化与交叉点

输入输出、接口、偏好项、存档、剧情定位、素材引用是否变化；哪些旧能力需继续可用；与谁的任务交叉。

## 依赖与尚未对齐的内容

列具体材料和问题。建议与已决定事项区分；缺依赖时继续独立部分，不把整个任务笼统标成已完成。

## 实际验证与交付

写测试包/基线、实际检查结果、局限和交付位置。明确是否仅本地、是否已入仓库、是否已集成、是否已验收。

## 下一位 agent 的接续点

已完成部分、待补部分、应保留的ID/原件、下一步需要什么证据。
