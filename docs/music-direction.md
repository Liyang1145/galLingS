# 《海风与布丁》音乐方向与制作约定

记录日期：2026-10-11。本文整理音乐负责人在配乐讨论中表达的理解、当前选曲和制作进度。音乐方向由音乐负责人主导；下文明确区分已表达的要求、剧本依据、他人反馈和待试听的建议。

## 1. 谁负责音乐

本次提供《翡翠1.1.mp3》并持续讨论配乐方向的项目成员负责音乐工作，当前提交账号为 [@Liyang1145](https://github.com/Liyang1145)。职责包括主曲探索与选择、变奏制作、配器和旋律方向、场景试听，以及音乐素材交付。开发协作负责按剧本接入播放、停奏、音量与循环设置。

音乐负责人已明确：“我是管音乐的。”配乐相关建议供其试听和判断，不因写入文档就自动成为最终规格。

## 2. 音乐负责人已表达的方向

- **先定两首主曲，再做衍生版本。**《翡翠之梦》作为鲸鱼小姐的角色主曲，《深海之光》作为另一首核心主题。先把主题本身做成立，再考虑大量场景变奏。
- **《翡翠之梦》需要有 Galgame 角色曲的感觉。**音乐负责人曾对 Suno 的结果不满意，并反复追问角色主曲、Gal 配乐的特征和约束。只有氛围描述不足以决定这首曲子，需要落实到音乐本身。
- **旋律要有展开，短动机不要出现得过于频繁。**曾尝试上传动机 demo，也尝试不上传动机直接生成。上传与否是探索方式，不能因此让同一个短句不断复现。
- **提示词少写剧情，多写音乐。**重点说明旋律、节奏、配器、结构、发展和动态；尽量简洁。英文版本用于 Suno 风格输入，既往尝试曾要求控制到 950 字符以内。
- **Suno 用于探索和选曲。**音乐负责人有 Suno 会员，正在通过多次生成寻找满意的版本。具体模型、滑块、是否上传参考音频等设置需随实际选曲记录，不在这里统一锁定。
- **结合实际场景听效果。**将探索中的《翡翠之梦》结合剧情试听，最终接入以 LarryE135 提供的最新 DEMO 为基础。
- **当前处于早期探索。**先在本地试听、比较，以改动内容区分探索稿；版本号与入库时机由音乐负责人决定，明确要求上传时再推送仓库。
- **尽量避免程序化感强的占位音效。**必要动作缺专用素材时先留白，再列制作需求；表情变化、比喻与回忆不要求逐句加提示声。

## 4. 两个主题的剧本分工

依据仓库的 [第一季全卷 v5.0](../content/scripts/haifeng-pudding_s1_v5.0_draft.md)，全卷有 89 处 `【BGM】` 标记：《翡翠之梦》23 处、《深海之光》27 处；其余包括环境音、停奏、渐弱、同前等，并有一处写作“深海之梦”的曲名待核对。标记数不是独立曲目数。

### 《翡翠之梦》：人物性格与共同生活

- 第一话已经标注“角色曲前奏”和“完整版”，建立她嘴硬、神气、偷偷关心人的第一印象（全卷 L96、L209）。
- 第二话黄昏明确使用钢琴 solo 变奏，涉及暗号和记忆的不安（L696）。
- 集市、搬家、开店、晨间等场景继续使用轻快、弦乐、日常等版本。
- 第十一话和解后使用变奏，承接她用自己的语气表达真心（L4109）。
- 第十六话厨房仍使用主曲，说明这个主题需要承载稳定、亲近的共同生活（L6298）。

这支持“角色主曲先成立、之后用同一主题覆盖不同情绪”的制作方式。主曲既需要可辨识的人物性格，也需要能在减配、放慢后保留温柔和脆弱的表达空间。

### 《深海之光》：记忆、深层亲密与关系受伤

- 第三话发光珊瑚礁首次出现，剧本明确称它为“本作最安静的 BGM”（L1082）。
- 此后钢琴、竖琴、吉他、单音等版本用于记忆、独处、亲密和关系危机。
- 第十六话浅滩夜使用完整版，承担季终的重要回收（L6353）。

曲名、出场和变奏类型来自剧本；具体音符、速度、拍号和配器并未由剧本规定。剧本或分析材料中的规范应按其实际用途阅读，不能替代音乐负责人的选曲判断。

## 5. 已收到的试听反馈

音乐负责人分享的聊天截图中，试听者对《翡翠1.1.mp3》《翡翠1.2.mp3》的反馈是：体验很好，音乐轻柔，适合平淡温馨的场景；同时指出争吵后的场景还需要紧张、忧郁、压抑的音乐。

这是他人的试听反馈，用于说明温馨部分目前得到认可、关系危机部分仍需关注。截图本身不提供可试听音频，不能据此进一步断言旋律、配器、主题发展或所有剧情音乐都已经验收完成。

### 争吵后的具体阶段

| 阶段 | 剧情与情绪 | 剧本已有音乐安排 |
|---|---|---|
| 第九话《电话》 | 搬家后第三天，男主说“换个听话的”“来个能写小说的”；她害怕被替换，争吵后离开 | 日常曲骤停；争执大量无音乐；黄昏《深海之光》钢琴单音（L3413、L3439、L3594） |
| 第十话《深水区》 | 当天深夜解释失败，她从生气转向心灰意冷；随后数日无消息 | 无音乐、骤停；其后数日《深海之光》单音极慢（L3695、L3734、L3813） |
| 第十一话《礁石与和解》前半 | 男主进入深水区，她救他上来；关系还未完全解冻 | 水下心跳、暴烈潮声；随后《深海之光》钢琴单音（L3933、L3949、L3983） |
| 第十一话后半 | 确认“现在的你”，重新定条款、和解与告白 | 《翡翠之梦》变奏回来（L4109） |

这段配乐的核心是害怕失去、关系断裂、等待与回温。可优先探索《深海之光》的压抑变奏和留白，不因这段需求就直接决定另写第三首主曲；是否新增独立曲由音乐负责人试听后决定。

## 6. 可以继续试验的音乐写法（尚未定案）

以下来自配乐分析，是供音乐负责人试验的方案，不是其已确认的硬性要求：

- 《翡翠之梦》以较轻巧、有神气的问句接柔软、连贯的回答，让乐句体现嘴硬心软。
- 使用可哼唱的完整主题，安排新的回答、对比段和有变化的主题回归，减少短钩子的机械重复。
- 从较明亮的和声出发，少量带出惆怅；保持旋律在钢琴独奏、慢速版中仍能辨认。
- 先试清楚的原声钢琴、轻木吉他和克制的小编制弦乐；视实际曲子决定是否增加打击和其他音色。
- 曾建议 92 BPM、4/4、16 小节主题和约 2 分半至 3 分钟，均只是新一轮生成的试验参数。当前选中的主曲约 2 分 13 秒，不能因这些建议否定已选版本。
- “梦幻”“海洋”“怀旧”等词可辅助气质，但不应挤占对旋律和编曲的描述。

配器多寡、旋律记忆点是否继续强化、明亮或忧郁的程度，仍需结合现有音频和实际剧情试听判断。Galgame 音乐不能被统一规定成某组乐器、拍号或固定速度。

## 7. 制作与交付进度

1. 当前先保存并试玩《翡翠之梦》选用主曲，后续衍生以它为基准。
2. 继续确定《深海之光》的主曲及其与《翡翠之梦》的分工。
3. 在两首主曲成立后，再按剧本制作钢琴、轻快、弦乐、晨间、单音极慢等版本；可合并用途相近的版本，数量待音乐负责人决定。
4. 单独检查第九至十一话的关系危机及回温，保留剧本中的骤停和沉默。
5. 游戏交付时记录素材 ID、用途、版本、来源和循环点。OGG、响度统一约 -16 LUFS 是 [PLAN §15](PLAN.md#15-音频) 的交付建议，不代表当前 MP3 已完成这些处理。

画面与交互 DEMO 由 LarryE135 更新，以作者提供的最新进度为后续配乐试听基础。此前代理基于旧本地包制作的整合试玩、处理副本、版本说明和旧 DEMO 缺失清单已撤出仓库；本地探索记录留作参考，需结合最新 DEMO 重新核对。

原主曲、15 个环境音、18 个剧情音效继续单独保存在素材库。素材状态与制作方向不等同于整合完成，具体场景映射、音量、循环和音效缺口待最新 DEMO 到位后再核对。

目前未对主曲做剪辑、响度处理或无缝循环编辑。《深海之光》与主题变奏仍待探索。“适合循环”是生成目标，准确循环点及剧情停奏需要由音频编辑和播放器落实。
