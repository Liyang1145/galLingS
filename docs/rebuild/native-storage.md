# Windows 试用原生记录后端

2026-10-24 从干净的 `17e7cf4` 接续 M5 已列出的原生存储缺口。当前只编写 Windows 文件后端，**尚未由宿主创建、未注册页面接口、未接 TypeScript 适配器、未选择为当前存储**。运行入口仍是原来的隔离 IndexedDB，不迁移、读取或修改旧播放器文件。没有执行 Cargo、准备、编译、类型检查、测试、启动或独立复核，尚未验收。

这是已有存储契约的后端实施片，不决定正式安装/卸载、数据目录、跨设备同步、旧档迁移、宿主统一或自动恢复策略。缩略图建议仍待确认，本片不实现该方案。

| 位置 | 已编写职责 |

| `desktop/src-tauri/src/rebuild_storage.rs` | 目录独占、读取/分页、进度替换、记录 CAS、完整容器提交、旧容器清理及错误/警告 |
| `desktop/src-tauri/src/rebuild_storage/address.rs` | 当前作品/范围的受限逻辑地址、槽位 JSON 字面量边界、UTF-16 排序及记录种类匹配 |

## 已登记的试用地址

原逻辑键和载荷格式均保持：

- `haifeng.save/1`：当前作品的 `development/normal-entry` 与 `preview/timed-choice:pm8x8v2h` 两个已有进度范围。
- `haifeng.player-records/1`：当前作品 `development/normal-entry` 的成果记录。
- `haifeng.audio-preferences/1`、`haifeng.reading-preferences/1`、`haifeng.button-preferences/1`、`haifeng.readout-preferences/1`：同一正常试用范围的四种独立偏好。

后端没有正式 `game`、其他作品、任意预览、缩略图、聊天、模型凭据或旧宿主地址。地址仅用于记录表查询，**不映射为文件名或相对路径**；不能借节点、槽位、斜杠或绝对路径请求任意文件。

槽位末段校验有界 JSON 字符串语法和 1～128 个 UTF-16 单元，保留 JSON.stringify 可表达的独立代理项转义，不将其损坏成 UTF-8 默认字符。应用仍须用原 `readSaveSlotId()` 及存档地址校验确认名称，原生边界不替代完整校验。分页按逻辑键的 UTF-16 单元排序，不用 Rust UTF-8 字节序重排含补充字符的名称。

## 内部物理容器与提交

内部文件格式为 `haifeng.native-record-table/1`，包含作品、存储提交代次和各独立逻辑键/值。它是物理提交容器，**不是一个游戏检查点、成果快照或可直接导出的存档**；不能用某个进度槽位的旧值整体覆盖它。内容修订、核心步骤、存档版本、宿主桥 ABI 与本容器代次互不混用。

受信任的原生装配须传入专用试用目录和作品身份，页面不能提供目录。本片没有选择正式落点或在现有 WebView 数据目录创建实例。根目录、记录文件须为普通目录/文件，重解析点及未知布局拒绝。`store.lock` 在后端生命周期内保持独占共享模式，另一个后端/宿主使用同一目录时报错；进程内再用互斥锁串行，锁异常不初始化空表。

每次提交按以下顺序：

1. 独占/串行范围内重新读取最新容器，核对格式、作品、代次及有界地址。最新提交损坏或不兼容时明确拒绝，**不自动取前一版本、不初始化空表**。
2. 进度仅替换指定地址，其他逻辑记录保持。成果/偏好先比较存储代次；冲突返回当前代次、不写文件，TypeScript 随后重新读取并运行原验证/合并。
3. 在内存中完整编码新容器后才创建独占、不可覆盖的 `pending-…tmp`，完整写入并 `sync_all()`，关闭文件句柄。
4. 使用同目录的 `MoveFileExW` 转为新的 `records-<20位代次>.json`；只设置 `MOVEFILE_WRITE_THROUGH`，不允许跨卷复制/删除或替换已有提交文件。成功返回后才报告提交，原已提交文件在此之前不被删除或重命名。
5. 提交后仅尝试清理已验证属于本作品/格式的较老完整容器，保留当前及上一提交。清理失败作为本次提交警告，不能改报写入失败；未提交临时文件保留并报告数量，不读取其内容作为存档。

读取选择最高提交文件名并核对内部代次；零代次仅是还没有任何提交的初始状态。只有临时文件而没有提交时，逻辑记录仍不存在，但返回未提交文件警告。未知文件、重复记录键、超限和损坏的最新容器都不是“无存档”。

损坏的单条领域载荷保留原 JSON 值，交给 TypeScript 仓库诊断，不猜字段或清空成果。无键与存在的 `null` 分别返回 `None`/`Some(Value::Null)`，后续页面适配必须保留区别。

以上为已编写顺序，未做故障或设备确认。不承诺断电物理落盘、磁盘/文件系统故障修复、网络盘语义、用户手改后的修复或系统回收自动恢复；临时文件和旧容器不是玩家槽位，不能据其存在宣称一次保存成功。

## 接口与试用限额

| 内部方法 | 行为 |
|---|---|
| `open(root, work_id)` | 受信任原生调用打开独立目录并持有独占锁，不读浏览器数据库/旧存档 |
| `read(key)` | 返回存储代次、存在/缺失的原值及临时文件警告，不采用到会话 |
| `scan(prefix, after, limit)` | 仅两个登记进度范围，1～100 条，返回原键/原值/续页地址及警告 |
| `replace_progress(key, value)` | 仅进度替换；核对地址/封装种类，保留其他逻辑记录，完整提交才返回 |
| `compare_exchange(key, expected, value)` | 仅成果/四组偏好；代次冲突不写，成功不执行剧情或合并规则 |

存储代次为 0～JavaScript 安全整数上限，耗尽拒绝。试用限额为单条 JSON 2 MiB、容器 32 MiB、4096 个逻辑地址、目录 4096 个文件；超限明确报错，不截断或清空旧槽位。这是未调优的实现边界，不是正式容量承诺。

错误带 `NATIVE_STORAGE_*` 类别和原因，警告不得由后续桥/UI 静默丢弃。接口不返回真实机器目录、句柄、通用操作或可写记录表；同步磁盘方法不得在 UI 线程直接执行。
