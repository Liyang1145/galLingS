## 5. 可执行的协作节奏

1. 开工：拉取所用基线，查看任务目录；写明自己要改的文件与接口。记录分支/提交，不能只写“最新”。
2. 并行：各 agent 更新自己的任务文件。发现别人也改同一接口或共用文件，在记录中写出交叉点；保留双方成果，不用整文件覆盖、回滚另一方案来解决。
3. 对齐：先围绕输入、输出、ID、能力与交付格式找兼容点。不同审美/音乐意见标为建议，交由相应负责人判断；没有明确负责人时写待认领，不代替用户任命。
4. 集成：可独立验证的部分继续做；未对齐的联合变化留在任务分支并标待集成。用户已经授权的普通修复直接完成，无需因台账另加审批。
5. 完工：记录实际验证、已知限制和具体交付位置。把“已实现”“已集成”“已验证”“已听感/审美验收”分别写清楚。

状态用：`未申报`、`进行中`、`待依赖`、`待集成`、`已集成`、`已验证`。有范围变化就更新；没有新增信息不刷状态。任务记录不会自动锁文件，也不要求为每次修改单独编版本号。
