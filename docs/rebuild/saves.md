## 一次捕获，分别持有

`packages/player/src/checkpoint.ts` 定义内部 `haifeng.game-checkpoint/1`；这是数据格式标识，不是游戏发行版本。

`GameSession.captureCheckpoint(token)` 进入会话现有串行队列。核对会话、呈现和核心步骤后，在同一个同步操作中捕获：

- 核心已经生效的逻辑快照，包括节点、当局变量、阶段和当时的只读玩家投影；投影只是校验上下文，不能覆盖独立的全局记录。
- 按相同内容修订和节点引用重建的完整目标场景，不保存动画对象、DOM 或进入音效。
- 限时选择剩余有效毫秒、当前推进等待、等待语音状态及自动/快进状态。
- 目标 BGM、环境声和当前对白语音的资源 ID、可取得的播放位置及语音状态。

存储只接收分离后的数据副本，异步写入期间不会再读取正在推进的会话。显示时间单独由调用者提供，不参与倒计时或回调身份。

本切片暂只支持场面就绪、文字完整显示后的 `ready/choosing` 阶段。呈现中、媒体阻断错误和结局检查点明确拒绝；这是本片覆盖范围，不是最终存档体验决定。菜单、后台暂停不阻止捕获，捕获本身不推进或解除暂停。

进度等待保留有效毫秒，不记录后台的墙钟时长。声音位置不可取得时记录 `null`，不补成零；已结束、跳过、不可用和仍活动的语音分别标记。正式语音默认体验尚未确定，当前由每次读档的调用者显式选择。转场只记录完整目标场景引用，不承诺动画帧级恢复。

## 独立读取与版本拒绝

`inspectStorySnapshot(content, unknown)` 由唯一剧情核心校验并描述外部快照。它不调用开局或当前节点进入动作、不发事实，也不修改任何正在运行的实例。

独立编辑器已复用上述捕获/检查/恢复能力提供[检查点初始条件预览](preview-checkpoints.md)，使用单独 `haifeng.editor-checkpoint/1` 本机封装，严格匹配草稿修订。预览显式采用保存时投影而不接玩家存储；这不改变游戏进度读档刷新当前全局投影的契约，也不增加正式槽位兼容承诺，未运行验收。

`inspectGameCheckpoint` 在此基础上检查媒体 ID、场景停奏、环境声列表、逻辑阶段、限时上界及等待状态。没有规范化内容时不能凭节点 ID、旧数组下标或类型断言猜测恢复位置。

`packages/player/src/saves.ts` 的 `SaveRepository` 包装 `haifeng.save/1`，保存范围、槽位、显示时间及检查点。写入前、读取后都校验完整封装；作品、修订、格式、命名空间、变量、阶段或音轨不符时报告错误。读取只返回经过校验的数据和详情，**不会采用到当前会话**。

存储键包含作品、`development/preview/game` 范围及其 ID、槽位；内容修订保存在载荷中。这样修订改变后旧槽位仍可定位并报告不兼容，不伪装成空槽位。本片不读取或修改旧存档，不实现旧格式迁移；这不等于已经决定正式产品的旧档兼容级别。

## 存储适配契约

`AtomicSaveStore` 提供 `read/replace/scan`。空槽位与存在但损坏的载荷分别表示，包括键存在而值为 `undefined` 的情况。`replace` 只能在完整提交后报告成功，失败须保留旧值；不能先删槽位再写新值。校验失败不调用写入。`scan` 按当前作品与范围的键前缀只读分页；`SaveRepository.list()` 逐条完整校验后返回摘要或诊断，目录不能替代读档时重读，详见[命名槽位目录](slots.md)。

浏览器实现位于 `packages/player/src/web/saves.ts`，通过 IndexedDB 数据库 `haifeng.rebuild.saves` 的 `slots` 仓库存放新记录。一次替换只在一个读写事务中执行 `put`，等待事务 `complete` 才返回；请求失败不阻止事务默认回滚。连接阻塞、权限/打开失败和事务中止分别报告可重试错误，连接在操作完成后关闭。没有访问旧 localStorage 或旧数据库。

单条读取及全局/偏好更新以同一事务内的游标区分键是否存在，不把损坏的 `undefined` 载荷视为空记录而初始化覆盖。目录读取同样只在只读事务完成后返回；数据库版本仍为 `1`，原有 `manual` 键和 `haifeng.save/1` 载荷不迁移。

这段失败保护是已编写的实现，尚未做故障注入或浏览器运行确认。事务提交也不等于承诺断电后物理落盘、任意浏览器的数据保留期限或原生宿主能力。站点清理、浏览器存储策略、主机/端口或浏览器配置变化均可能影响记录可见性。

## 独立试播接入与手动试用

`apps/game/` 的“试播存读档”面板提供命名槽位选择、每页 20 条的只读目录、当前入口保存、两个独立查看及读取进度按钮。第一话使用 `development/normal-entry`，限时样例使用 `preview/timed-choice:pm8x8v2h`；每个入口初始选择仍为 `manual`，原记录可直接访问。输入名称或从目录选择只改变操作目标，手动保存才创建或替换同名槽位；按钮显示各自选中的名称。没有写 `game` 正式范围、偏好、聊天或回退历史；进度槽位仍只手动保存。第一话的全局成果则按真实事实自动保存，见玩家记录说明。

“保存”捕获入口、选中槽位、当前步骤和显示时间后写入分离副本；第一话先等待必要全局事实提交，失败不写进度槽位。“查看”从数据库重读并校验，展示保存时的节点、变量、上下文投影、阶段、剩余时间和播放信息，不改变当前游玩。写入中的不可变检查点独立完成事务，之后选择别的名称或正常退出时重试，仍写原入口、原槽位、原检查点和时间，不读取新会话来拼档。

“读取进度”先暂停旧会话，准备并校验进度和当前已提交全局记录；准备失败保留旧游玩并解除本次准备暂停。准备成功才取消旧任务、分配新会话代次并创建从快照继续的核心，恢复目标场景、完整文字、当局变量和选择剩余有效时间。没有再次开局、执行进入动作或产生进入/结局事实。开始另一入口、返回标题或离开页面后，过时的读取请求不会替换新会话。

`prepareGameRestore(content, unknown, currentPlayer)` 由唯一核心校验原检查点后，显式刷新周目和结局数。若当前全局条件改变了可见选项，核心重新描述可选择阶段；已有开放限时选择保留剩余时间，新开放的限时选择使用作者完整时长，已经没有选择则不再倒计时。这不会再次计算节点进入动作。

`createGameSession` 的 `resume: {checkpoint, voice}` 接受准备后的进度，`voice` 必须显式为 `silent/replay/resume`，不设正式默认。试播页用选择框要求本次手动选择，不保存成偏好：

- `silent` 不播放当前句；`replay` 从头播放当前句。
- `resume` 仅续播保存时仍活动且位置可取得的语音；已结束/跳过/不可用则保持停止，缺少活动语音位置时显示提示。
- BGM/环境声恢复正确的目标轨道及停奏，存在位置时尝试续播；未知位置保留目标轨道的可用播放行为，不伪称位置一致。

恢复只使用稳定检查点，因此文字为保存时已经完整显示的状态；呈现中存档体验尚未扩大支持。一次性进入音效及转场动作不重放。自动/快进沿用旧读档时关闭的行为，强制演出等待保留对应剩余时间。媒体失败可重建同一已生效位置，不重新结算变量。

以下操作留待用户安排的重构末尾统一测试，不作为下一切片前置条件。沿用[可视试播](player.md#统一测试时的可视入口)命令，仓库根、Node `>=24.15.0 <25`：

```powershell
npm ci --ignore-scripts
npm run game:dev
```

本轮没有执行这些命令。供用户手动操作：

1. 从第一话开始，完整显示一段对白，在槽位面板选择 `manual` 或输入名称后使用，再点对应“保存”按钮，等待面板报告提交完成，记下节点和变量。
2. 继续几句，再点第一话对应槽位的“查看”按钮，应显示保存时的数据，当前游玩位置不受查看影响。目录选择只变更目标，实际读取仍需显式点击“读取”。
3. 返回标题，开限时样例，文字完成后等几秒，打开菜单保存，记下 `timing.choiceRemainingMs`。关闭菜单并作出选择，再选本次读档语音方式，读取限时样例进度；应回到保存的选择，恢复对应变量和剩余时间，不补成 15 秒。
4. 刷新同一浏览器的同一本地地址，分别读取两个入口，核对其来源、变量与剩余时间。第一话已读来自全局记录；限时样例的内存已读刷新即丢失。
5. 在第一话正常解锁一个 CG 或结局后返回主页，打开“鉴赏”，再读取更早进度并返回主页。解锁成果和通关次数不应被旧进度覆盖；鉴赏只查看，不播放剧情或新增结局事实。
6. 语音/转场中读取另一份进度，观察旧文字、声音、延迟和倒计时是否被取消，再尝试本次选择的语音恢复方式。图片或声音错误的诊断不代表进入动作已经再次执行。

多名称、分页、损坏记录及保存中换槽的待试用情景见[槽位目录](slots.md#留待统一测试)。没有安装、运行、类型检查、测试、构建、媒体听审、额外审查或子代理结果；以上均为待手动确认的预期行为。
