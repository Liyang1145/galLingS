## 检查点与恢复

### 一次捕获，分别持有

`packages/player/src/checkpoint.ts` 定义内部 `haifeng.game-checkpoint/1`；这是数据格式标识，不是游戏发行版本。

`GameSession.captureCheckpoint(token)` 进入会话现有串行队列。核对会话、呈现和核心步骤后，在同一个同步操作中捕获：

- 核心已经生效的逻辑快照，包括节点、当局变量、阶段和当时的只读玩家投影；投影只是校验上下文，不能覆盖独立的全局记录。
- 按相同内容修订和节点引用重建的完整目标场景，不保存动画对象、DOM 或进入音效。
- 限时选择剩余有效毫秒、当前推进等待、等待语音状态及自动/快进状态。
- 目标 BGM、环境声和当前对白语音的资源 ID、可取得的播放位置及语音状态。

存储只接收分离后的数据副本，异步写入期间不会再读取正在推进的会话。显示时间单独由调用者提供，不参与倒计时或回调身份。

本切片暂只支持场面就绪、文字完整显示后的 `ready/choosing` 阶段。呈现中、媒体阻断错误和结局检查点明确拒绝；这是本片覆盖范围，不是最终存档体验决定。菜单、后台暂停不阻止捕获，捕获本身不推进或解除暂停。

进度等待保留有效毫秒，不记录后台的墙钟时长。声音位置不可取得时记录 `null`，不补成零；已结束、跳过、不可用和仍活动的语音分别标记。正式语音默认体验尚未确定，当前由每次读档的调用者显式选择。转场只记录完整目标场景引用，不承诺动画帧级恢复。

### 独立读取与版本拒绝

`inspectStorySnapshot(content, unknown)` 由唯一剧情核心校验并描述外部快照。它不调用开局或当前节点进入动作、不发事实，也不修改任何正在运行的实例。

独立编辑器已复用上述捕获/检查/恢复能力提供[检查点初始条件预览](<editor.md#preview-checkpoints>)，使用单独 `haifeng.editor-checkpoint/1` 本机封装，严格匹配草稿修订。预览显式采用保存时投影而不接玩家存储；这不改变游戏进度读档刷新当前全局投影的契约，也不增加正式槽位兼容承诺。

`inspectGameCheckpoint` 在此基础上检查媒体 ID、场景停奏、环境声列表、逻辑阶段、限时上界及等待状态。没有规范化内容时不能凭节点 ID、旧数组下标或类型断言猜测恢复位置。

`packages/player/src/saves.ts` 的 `SaveRepository` 包装 `haifeng.save/1`，保存范围、槽位、显示时间及检查点。写入前、读取后都校验完整封装；作品、修订、格式、命名空间、变量、阶段或音轨不符时报告错误。读取只返回经过校验的数据和详情，**不会采用到当前会话**。

存储键包含作品、`development/preview/game` 范围及其 ID、槽位；内容修订保存在载荷中。这样新版本的内容修订改变后，原槽位仍可定位并报告不兼容，不伪装成空槽位。没有旧存档，不实现旧格式导入/迁移或数组下标兼容；新记录自身的格式、修订和损坏校验继续保留。

### 存储适配契约

`AtomicSaveStore` 提供 `read/replace/scan`。空槽位与存在但损坏的载荷分别表示，包括键存在而值为 `undefined` 的情况。`replace` 只能在完整提交后报告成功，已确认事务失败须保留旧值，不能先删槽位再写新值；[原生确认丢失](<delivery.md#native-storage>)单独报告 `NATIVE_STORAGE_UNCONFIRMED`，不视为成功或肯定未写入。校验失败不调用写入。`scan` 按当前作品与范围只读分页，目录不能替代读档时重读，详见[命名槽位目录](<storage.md#slots>)。

浏览器实现位于 `packages/player/src/web/saves.ts`，通过 IndexedDB 数据库 `haifeng.rebuild.saves` 的 `slots` 仓库存放新记录。一次替换只在一个读写事务中执行 `put`，等待事务 `complete` 才返回；请求失败不阻止事务默认回滚。连接阻塞、权限/打开失败和事务中止分别报告可重试错误，连接在操作完成后关闭。没有访问旧 localStorage 或旧数据库。

单条读取及全局/偏好更新以同一事务内的游标区分键是否存在，不把损坏的 `undefined` 载荷视为空记录而初始化覆盖。目录读取同样只在只读事务完成后返回；数据库版本仍为 `1`，原有 `manual` 键和 `haifeng.save/1` 载荷不迁移。

这段失败保护是已编写的实现，尚未做故障注入或浏览器运行确认。事务提交也不等于承诺断电后物理落盘、任意浏览器的数据保留期限或原生宿主能力。站点清理、浏览器存储策略、主机/端口或浏览器配置变化均可能影响记录可见性。

### 独立试播接入与手动试用

`apps/game/` 的“存档 / 读档”弹层提供命名槽位选择、每页 20 条的只读目录、当前入口保存、两个独立查看及读取进度按钮。[游戏界面迁移](<player.md#game-ui>)已接标题“读取进度”、底部“存读档”和暂停菜单入口；打开只刷新当前入口目录，关闭释放弹层自己的暂停，取消尚未采用的读档准备，已有写入仍按原目标完成。第一话使用 `development/normal-entry`，限时样例使用 `preview/timed-choice:pm8x8v2h`；每个入口初始选择仍为 `manual`，原记录可直接访问。输入名称或从目录选择只改变操作目标，手动保存才创建或替换同名槽位；按钮显示各自选中的名称。没有写 `game` 正式范围、偏好、聊天或回退历史；进度槽位仍只手动保存。第一话的全局成果则按真实事实自动保存，见玩家记录说明。

“保存”捕获入口、选中槽位、当前步骤和显示时间后写入分离副本；第一话先等待必要全局事实提交，失败不写进度槽位。“查看”从数据库重读并校验，展示保存时的节点、变量、上下文投影、阶段、剩余时间和播放信息，不改变当前游玩。写入中的不可变检查点独立完成事务，之后选择别的名称或正常退出时重试，仍写原入口、原槽位、原检查点和时间，不读取新会话来拼档。

目录现已接入[沿旧版迁移的摘要卡片](<storage.md#slots>)，保存与按入口分组的查看/读取分区展示；仍使用上述原操作、摘要与格式，不包含缩略图协议。仅显示迁移。

玩家投影明确标为保存时上下文，仍说明实际读档采用当前已提交成果；控制项明确为保存时的自动/快进值，读档关闭它们的原规则不变。等待文字是静态保存值，不增加本地倒计时。完整记录与校验视图收进默认折叠的只读技术诊断，展开不采用或写入进度。详情无动作回调、存储、会话或媒体位置读取能力；原请求代次/槽位绑定、失败状态及选择后清理仍由应用负责。

此片只改应用显示与 HTML/CSS，不修改进度/检查点/数据库格式、捕获阶段、保存触发或语音默认。显示构造失败单独提示，不能把已经提交的保存改报写入失败。

“读取进度”先暂停旧会话，准备并校验进度和当前已提交全局记录；准备失败保留旧游玩并解除本次准备暂停。准备成功才取消旧任务、分配新会话代次并创建从快照继续的核心，恢复目标场景、完整文字、当局变量和选择剩余有效时间。没有再次开局、执行进入动作或产生进入/结局事实。开始另一入口、返回标题或离开页面后，过时的读取请求不会替换新会话。

`prepareGameRestore(content, unknown, currentPlayer)` 由唯一核心校验原检查点后，显式刷新周目和结局数。若当前全局条件改变了可见选项，核心重新描述可选择阶段；已有开放限时选择保留剩余时间，新开放的限时选择使用作者完整时长，已经没有选择则不再倒计时。这不会再次计算节点进入动作。

`createGameSession` 的 `resume: {checkpoint, voice}` 接受准备后的进度，`voice` 必须显式为 `silent/replay/resume`，不设正式默认。存读档弹层用选择框要求本次手动选择，不保存成偏好；回退弹层及对白回看各有独立的本次语音选择：

- `silent` 不播放当前句；`replay` 从头播放当前句。
- `resume` 仅续播保存时仍活动且位置可取得的语音；已结束/跳过/不可用则保持停止，缺少活动语音位置时显示提示。
- BGM/环境声恢复正确的目标轨道及停奏，存在位置时尝试续播；未知位置保留目标轨道的可用播放行为，不伪称位置一致。

恢复只使用稳定检查点，因此文字为保存时已经完整显示的状态；呈现中存档体验尚未扩大支持。一次性进入音效及转场动作不重放。自动/快进沿用旧读档时关闭的行为，强制演出等待保留对应剩余时间。媒体失败可重建同一已生效位置，不重新结算变量。

以下操作留待用户安排的重构末尾统一测试，不作为下一切片前置条件。沿用[可视试播](<runtime.md#player>)命令，仓库根、Node `>=24.15.0 <25`：

```powershell
npm ci --ignore-scripts
npm run game:dev
```

本轮没有执行这些命令。供用户手动操作：

1. 从第一话开始，完整显示一段对白，在槽位面板选择 `manual` 或输入名称后使用，再点对应“保存”按钮，等待面板报告提交完成，记下节点和变量。
2. 继续几句，再点第一话对应槽位的“查看”按钮，应显示保存时的数据，当前游玩位置不受查看影响。目录选择只变更目标，实际读取仍需显式点击“读取”。
3. 返回标题，开限时样例，文字完成后等几秒，打开菜单保存，记下 `timing.choiceRemainingMs`。关闭菜单并作出选择，再选本次读档语音方式，读取限时样例进度；应回到保存的选择，恢复对应变量和剩余时间，不补成 15 秒。
4. 刷新同一浏览器的同一本地地址，分别读取两个入口，核对其来源、变量与剩余时间。第一话已读来自全局记录；限时样例的内存已读刷新即丢失。
5. 在第一话正常解锁一个 CG 或结局后返回主页，打开“鉴赏”，再读取更早进度并返回主页。解锁成果和通关次数不应被旧进度覆盖；鉴赏只查看，不播放剧情或新增结局事实。
6. 语音/转场中读取另一份进度，观察旧文字、声音、延迟和倒计时是否被取消，再尝试本次选择的语音恢复方式。图片或声音错误的诊断不代表进入动作已经再次执行。

多名称、分页、损坏记录及保存中换槽的待试用情景见[槽位目录](<storage.md#slots>)。没有安装、运行、类型检查、测试、构建、媒体听审、额外审查或子代理结果；平台编译与运行范围统一见项目总览。

### 存档面板的原操作重试

`PendingWrites.track(key, operation, label)` 返回瞬时 `TrackedWrite`：`result` 是首次操作 Promise，`view()` 返回冻结的名称、`pending/failed/completed/superseded` 及文字诊断，`retry()` 仅能重试仍在跟踪的同一失败实例。原 `run()` 签名保持并复用 `track()`；完成或同键的新显式操作替代后，旧句柄不能指向新操作。`completed` 只描述操作 Promise 完成，不能替代实际存储提交或退出就绪判定。普通 `view/subscribe` 仍只读、不返回键/操作/检查点。

退出 `retryFailed()` 复用同一写入实例，面板句柄因此能同步退出重试的 pending/失败/完成。面板只发单条原存档重试意图，不批量重试偏好、改变当前选择或采用进度；已有全局事实仍先按原规则提交。准备期间禁用本次保存/重试，开始/读档准备及退出沿原门控。返回标题或改选另一个入口不抹掉同页原失败请求，明确点击后仍只写其原范围与槽位；章节试阅本身不捕获玩家槽位数据。

`apps/game/src/pending-saves.ts` 只接只读状态/位置副本、应用的原重试回调和禁用判定，没有存储/会话/检查点能力。状态刷新保留已有按钮和焦点；完成或被新显式保存替代才移除条目，当前焦点在被移除条目时交给本弹层标题。未完成操作留在本页内存，关闭弹层不取消存储，刷新页面不承诺保留重试能力。订阅、条目监听及 UI 在页面销毁清理，既有写入仍按原生命周期完成。

原检查点捕获被拒绝、原槽位检查失败或确认取消时没有交付本次持久写入，面板明确报告准备未完成，不进入写入重试队列或替代同键已有失败项；要求在稳定位置向原槽位显式新保存，不重采旧请求或在退出时冒充已保存。已经提交后，目录刷新、详情呈现或提示音出错只报告显示/反馈问题，不能再把该操作留为“保存失败”或重复写入。异步反馈仍核对当前存储显示请求，新开/改选/查看之后旧结果不覆盖后来详情；显式重试只更新自己的这次显示请求。

存档、检查点、数据库、范围与原子替换格式不变；没有新增自动保存、删除、缩略图或正式读档语音默认。缩略图建议仍待用户确认，原目标重试不以该方案批准为前置。

### 存读档显示请求的打开期

“查看”开始捕获原信号、入口、所选槽位和存储显示代次。成功/失败都必须仍匹配当前打开信号及代次，且页面未关闭/退出，才能显示只读详情；关闭后读取可在存储适配器内完成清理，但不再改旧面板或重开后的内容。存储读取本身不被当成可撤销事务，不采用进度、写记录或新增暂停。

目录 `SaveSlots` 同样接收只读 `scope()`，每次分页读取绑定打开期、入口及目录代次；迟到成功、失败和 finally 不更新已关闭或重开的目录。目录控件在弹层外禁用。`browse()` 打开或切换入口时，经原 `changed()` 清理先前详情/显示代次；仅改选当前名称或查看/分页不采用进度，也不新增写入。

手动保存/原操作重试只在当前存档面板明确发起，反馈绑定这次打开期。覆盖确认尚未采用时，关闭使准备失效、不交付新写入；已经交付后原写入仍按原入口、槽位、检查点和时间提交。后台保存的完成/失败仍由同页跟踪摘要保留，不因原打开信号失效而撤销、丢弃或重采数据。旧操作不在后来重开的面板自动刷新目录/填入详情；用户重开后从原失败条目显式重试时，只重绑定这次显示归属，不改其持久载荷。提示音仍核对原显示代次/会话/表现和实际提交，不以新的打开期重播旧反馈。

只增加应用内生命周期信号与显示核对，不改进度/检查点/数据库/宿主协议或缩略图方案；成功开局/读档、返回标题和退出仍通过原关闭/暂停通道。

### 正式存储与后续边界

随包正常游玩使用 game/main，Windows/Android 普通启动默认原生文件，浏览器及开发入口使用各自 IndexedDB。原生错误不换源；确认丢失保留原队首和原载荷，显式重试不能重采。配套原生编译与设备通过范围统一见项目总览，旧运行参数/extra 试用方式已退出正式启动。

缩略图、呈现中存档体验、正式语音恢复默认、持久回退历史、槽位删除/改名和异常退出恢复均不因此实现或获批。全局成果不随进度恢复回滚，正常退出只等待已经发起的写入。

## 命名槽位与覆盖确认

### 手动选择与保存

`apps/game/src/slots.ts` 的 `SaveSlots` 只管理两个入口各自选中的名称和目录显示，不持有游戏会话、全局记录或写入/读档能力。第一话使用 `development/normal-entry`，限时样例使用 `preview/timed-choice:pm8x8v2h`；浏览目录的入口与当前游玩入口可以不同，保存按钮始终标明当前游玩入口及其选中名称。

两个入口在每次打开页面时初始选择 `manual`。原有键与载荷保持不变，无迁移或清空；名称只存于本页内存，不加入玩家偏好。输入名称后点击“使用此槽位名称”，或点击目录行的“选择此槽位”，只变更目标。页面输入会裁掉首尾空白，再按共享 `readSaveSlotId()` 检查非空及最多 128 个 UTF-16 单元；已有合法记录的名称按原值选择，不改写。

只有点击保存才准备创建或替换同名进度；重新读取发现已有记录时，还须明确确认覆盖，不在选择、翻页、刷新目录、返回标题或退出时新建进度。未增加槽位删除、改名、自动编号、缩略图或自动检查点规则。

### 原槽位覆盖确认

已占用时在同一存读档弹层内显示 `SaveOverwritePrompt`，明示原入口/名称、原进度摘要或诊断，以及这次捕获的节点/时间。初始焦点在“取消这次保存”，确认和取消均带原目标的可访问说明；长文字可换行，按钮保留触摸高度。提示只接只读摘要/位置和原准备信号，不取得会话、完整检查点、仓库或写入回调。

交付写入后，关闭弹层或更换名称不取消事务；实际保存、必要全局事实提交、同页/退出原载荷重试、存档反馈仍复用原流程。重试不再读取/询问当前选中槽位，也不重新捕获。提示/目录/详情失败不能将已提交操作改报失败。进度载荷、存储接口及原替换协议均不变，未新增保存触发、自动保存或缩略图。

`target()` 是一次只读观察，**不是槽位预留或跨页面检查/替换事务**。提示期间另一个页面仍可能更新同名槽位，确认授权替换该原地址，不承诺当前显示摘要是提交前最后一个版本；本片没有扩展进度 CAS 或默示决定冲突合并规则。

## 全局成果与通关事实

### 已编写的共享实现

`packages/player/src/records.ts` 提供 `PlayerRepository`、`PlayerRecordWriter`、只读投影和鉴赏目录。数据使用独立的 `haifeng.player-records/1`，按作品及 `development/preview/game` 范围保存，不嵌入某个进度槽位。

| 数据 | 归属与规则 |
|---|---|
| 当前节点、当局变量、阶段和剩余有效时间 | 进度检查点，随读档恢复 |
| 已读节点、已解锁 CG、已解锁结局 | 全局玩家记录，按稳定 ID 保留，不随进度覆盖 |
| 通关事实与周目 | 全局玩家记录；沿用旧规则：周目为通关次数加一 |
| 结局数 | 全局已解锁结局的种数，不是当前进度达到的结局数 |
| 音量、阅读及显示等偏好 | 不在以上两类中；[声音与阅读偏好](<player.md#preferences>)已独立接入，窗口/全屏等其余设置尚未迁移 |

核心快照中的 `player` 是捕获当时的只读求值上下文，不是全局记录的权威副本，不能用它覆盖当前成果。实际读档应显式传入当前已提交的全局投影。

### 事实、计次与失败保护

新记录只消费唯一核心实际产生的 `entered/ending` 事实；`chosen` 不单独增加成果。已读按节点 ID 合并；CG 依旧播放器的 `isCG` 规则从进入节点的背景取得，保留 `previewExcluded`、显式 `cg` 及名称前缀规则；结局按稳定结局 ID 去重，保留首次解锁时间。

通关计次延续旧播放器每次实际达成结局增加一次的行为：新核心每个被接受的结局转换记一条通关事实。同一批事实用固定交付 ID 重试，已提交的事实不会再次加次数；读档、检查点查看、主页和鉴赏重绘都不产生通关事实。读档后重新实际走到结局属于新的结局转换，不把它与一次存储重试混同。

浏览器存储适配器在同一个读写事务中读取、校验、合并并写入全局记录，避免多个标签页用旧副本覆盖彼此成果。结局解锁与对应通关事实一起提交。损坏数据明确拒绝，不退回空记录并覆盖。

`recordWithReceipt(batch)` 在同一事务中额外确定本批实际新加入的结局，提交完成后返回 `{records,receipt:{batchId,newEndingIds}}`；失败不返回回执。已提交批次重试及再次达成已有结局，首次解锁列表为空；通关计次仍按原事实 ID 幂等。同一批内多个相同结局只形成一次新解锁，跨页面以事务读到的当前记录为准。回执不持久保存，不改变 `haifeng.player-records/1`，既有 `record(batch)` 仍返回记录。

`PlayerRecordWriter` 保留未提交批次，失败后停止自动重试并报告，显式重试使用原交付 ID。它不是磁盘事务日志：浏览器未能写入时，待提交批次仍只在当前页面内存，不能冒充已持久化。

显式[Windows 文件试用](<delivery.md#native-storage>)与[Android 文件试用](<delivery.md#android-storage>)通过同一 TS 适配器的存储代次 CAS 调用原校验/合并，不在原生重做规则；原格式、范围和批次 ID 保持。`NATIVE_STORAGE_UNCONFIRMED` 表示可能已提交但尚未确认，不能宣称未写入或确认首次解锁；重试仍用原批次，已提交批次不会重复计次或补发首次解锁回执。默认 IndexedDB 不迁移，两端接线。

提交回调现为 `(records, receipt)`，应用将首次解锁结果与原结局批次的本页会话代次、表现身份及当前终态匹配，才尝试[新结局声音和显示反馈](<player.md#feedback>)。它不是新的剧情命令或第二次计次；静音、旧会话、页面离开和退出协调可以跳过反馈，不能回滚已保存成果。回执不构成持久通知或聊天解锁规则，也不承诺提交后崩溃仍能播放提示。

记录不按内容修订分槽，稳定 ID 的成果可跨修订保留；暂不在当前内容中的记录仍保留，鉴赏只展示当前目录中可定位的条目。这个保留行为不意味着进度检查点可以跨内容修订恢复。

## 会话内回退

### 有界历史与捕获时机

`packages/player/src/rollback.ts` 的 `RollbackHistory` 只保存当前会话的进度检查点及定位信息，没有持久化或全局成果写入权限。会话只有在调用者显式传入 `rollback: {capacity}` 时记录，未配置则不记录。当前试播传入 500，沿用旧播放器历史上限；本片允许 1～500，不据此决定正式产品容量。

会话在场面就绪、文字完整显示后的 `ready/choosing` 阶段首次捕获当前访问；实际离开节点前，在同一串行操作中刷新当局变量、声音位置、选择与强制等待的剩余有效时间。每次真实进入分配独立访问 ID，同一节点的循环访问不会混为一个历史位置。媒体重试不增加历史访问。

检查点与手动存档使用同一捕获实现。只持有目标场景所需的数据、资源 ID 和计时，不持有图片、缩略图、音频对象或另一份剧情解释器。自动捕获失败显示回退警告，保留此前历史并允许主线继续；不会用零值补造媒体或时间。若离开前刷新失败，保留的是先前成功捕获的稳定状态，不承诺它等于离开瞬间。

当前访问不列为回退目标；总容量包括已捕获的当前访问。容量满时丢弃最早历史，目标被淘汰后明确拒绝，不按数组位置猜测。

### 显式准备与采用

`GameSession.rollbackTargets()` 返回可选目标的文字定位副本及 `crossesChoice` 标记，不返回内部可写检查点。

`GameSession.rollback({token, targetId, currentPlayer, voice, crossChoices})` 进入现有串行队列，返回采用成功或拒绝原因：

1. 核对会话、呈现、核心步骤、稳定阶段及当前历史中的目标；结局后、加载未就绪或媒体阻断状态不在本片支持范围。
2. 本次调用必须明确 `crossChoices` 和 `silent/replay/resume` 语音方式。手动选择与超时选择都形成同样的选择边界；不跨选择时拒绝越界目标，不静默改选较近位置。
3. 复用 `prepareGameRestore` 校验整份检查点并刷新当前全局投影，再由唯一核心 `restore` 采用。准备或校验失败不截断历史、不修改当前进度。
4. 采用后更新核心步骤和呈现代次，取消旧任务，按同一恢复通道重建场景、音乐、语音和剩余有效时间。恢复不执行进入动作、一次性进入声音或结局事实，不反算变量。
5. 截断目标之后的检查点与当前路线对白，重新呈现目标句；全局已读、CG、结局和通关事实保留。若早期文字已超出 300 条回看容量，仅保留仍在内存的前缀与恢复的当前句，不补造历史。

回退在同一个会话内采用检查点，核心步骤与呈现代次同时更新；当前独立应用的读档仍创建新会话代次。这两条路径都拒绝恢复前的操作及延迟回调。菜单、后台、回看和宿主的暂停原因保持各自归属。

自动与快进在恢复时关闭。已开放限时选择保留检查点中的剩余有效时间，包括零；零剩余时间会在场面可用并解除暂停后按作者超时规则结算，不重新赠送完整时长。当前全局投影改变可见选择时，沿用[进度恢复](<storage.md#saves>)的阶段和计时规则。

逻辑采用后发生媒体错误，进度仍停在已恢复位置，界面显示错误并允许同一步骤重试；不伪称回退未发生，也不重新进入节点。

### 独立试播接入

[游戏界面迁移](<player.md#game-ui>)将“回退进度”接到暂停菜单的独立弹层，提供目标位置、是否跨选择及本次语音三个显式选择。语音不再依赖存读档弹层，均不设正式默认、不保存为偏好。弹层持有原会话的暂停归属及本次回退取消信号，关闭使尚未采用的准备失效；已经采用的进度不能因关闭撤回。这不决定正式回退边界。

操作开始先暂停当前会话。第一话先等待必要全局事实提交，再读取当前玩家记录生成投影；限时样例继续使用声明的周目 1、结局数 0，不写全局成果。失败解除本次准备暂停，其他暂停原因保持原值。异步准备期间新开、读档、返回标题或页面离开后，过期请求不能替换当前游玩。

回退只在内存中采用进度，不写手动槽位。采用后如需保存，应显式保存当前检查点。新开、读档、返回标题和页面离开会清理本片历史，两个入口互相隔离；正式退出后保留策略仍待确定。

条目请求绑定面板本次打开的取消信号；关闭、换会话及退出会拒绝尚未采用的结果。关闭回看立即释放该请求自己的 `operation` 暂停，迟到全局事务不继续恢复；已经采用的进度不被取消撤回。失败保留面板与原历史，成功才关闭回看，独立历史语音在准备开始即停止。独立回退弹层复用同一 `rollbackTo()` 准备通道并持有自己的取消信号，成功才关闭。下拉入口及条目入口都不改变正式默认或保存触发时机，

### 回退位置与长列表显示

选定位置后展示完整章节、说话人、节点、访问编号和未截断的对白。跨选择说明只读取原 `crossesChoice` 标记及用户本次范围，选择受限范围时明示原恢复通道将拒绝该目标；不隐藏目标、自动改选或放宽范围。列表只截短预览文字，完整正文以纯文字显示，不请求媒体或读取内部检查点，也不显示未提供的变量、媒体位置或剩余时间。

目标更新时仅保留仍存在的原访问选择，被淘汰或截断的目标回到“请选择”，不代选较近位置；新会话清空位置与详情。详情只随目标或范围变化重绘，主线状态通知不会不断重建相同正文。选择和浏览不采用进度，确认仍走原 `rollbackTo()`，准备期间禁用本弹层的位置、范围和语音控件；关闭取消、原会话令牌及成功才关闭的通道保持不变。

沿已有游戏弹层色调区分位置、完整对白与恢复方式，顶部返回和底部确认/结果区独立于内容滚动；窄屏恢复控件改为单列，小高度缩紧边距。这个游戏专用显示模块不进入共享播放器或编辑预览，不修改检查点、存档或宿主格式，不新增保存触发、正式默认或结局后边界。

### 后续边界

结局后回退、正式容量与跨选择默认规则、历史持久化、呈现中回退及手账归属仍待后续；用户已明确将回退扩展后置。历史语音及条目回退按钮已接入；没有旧存档，兼容/迁移取消。两端默认原生文件及正式 `game/main` 已按[正式运行配置](<delivery.md#run-profile>)接线，不改变本页现有恢复流程，生命周期/存储。

## 正常退出协调

### 已实现的边界

Windows 关闭按钮与 Android 标题页连按返回退出，现在先请求页面完成已有写入，再根据本次结果关闭。该过程只处理已经发起的手动存档、显式[音量/阅读/按钮声音偏好保存](<player.md#preferences>)及待提交全局事实，不另建当前剧情进度，不把全局记录提交当成节点已存档；未点击保存的设置调整也不会自动写入。

用户尚未决定自动检查点触发时机、正式读档语音和自动恢复体验，本片不设置这些默认。强制结束进程、系统回收、崩溃、断电、浏览器标签页关闭、页面重载和宿主投递整体失效均不属于正常退出保证；现有手动档仍是重开后可读取的位置。

### 应用准备过程

共享 `packages/player/src/writes.ts` 提供 `PendingWrites`，只追踪显式写入，不依赖 DOM、宿主或剧情核心，不是持久事务日志：

- 同一槽位尚在写入时拒绝叠加，完成后移除跟踪。
- 失败保留原操作，`settle()` 等待已有写入并报告失败，不把失败吞成成功。
- 玩家显式重试时使用原捕获的入口、槽位名称、检查点及显示时间，或原捕获的音量/阅读/按钮开关修改；[命名槽位](<storage.md#slots>)选择后来改变也不能重定向原写入，不在重试时读取后来进度或反算变量。偏好保存重试保留失败后新增的未保存调整。
- 捕获或原槽位检查未完成、覆盖确认取消时，本次进度尚未交付写入跟踪；需在稳定位置显式新保存，不凭空重试或把准备当已保存。

应用退出时先以独立 `exit` 原因暂停当前会话，禁止继续操作。使尚未采用的开局、读档、回退及鉴赏请求过期，关闭[通关后入口](<chat.md#chat>)并使旧上下文读取失效，解除被取代的 `operation` 原因；退出取消不能误解除菜单、后台或宿主暂停。

随后等待已发起的保存，再 `flush()` 全局事实队列，确认无待提交项才报告就绪。退出面板区分等待、失败、重试和取消；没有“写入失败仍假装完成”的关闭路径。取消只是撤回关闭请求，不能撤销已经开始的存储事务。已捕获的数据若继续提交，仍写原入口与原槽位。

终态表现也接续 `exit` 暂停及宿主声音许可。退出期间提交的首次结局回执仍保留成果，但不播放新结局提示，取消退出也不补播；这项反馈取舍不改变退出等待成功/失败的判断。

关闭对白回看时会先取消独立的历史语音试听，正常退出及取消退出都不会自动续播试听；主线的 `history/exit` 暂停原因继续分开管理。试听没有存储写入或全局事实，不加入退出等待队列，也不改手动检查点的主线语音位置。

正常退出就绪后，应用继续保持暂停和输入禁用，直到原生关闭或取消这张请求。窗口关闭前没有再推进、选择或新建事实。浏览器试播仍有 `pagehide` 清理，但不承诺浏览器允许异步等待存储。

玩家可在等待或失败期间取消；页面确认就绪后关闭取消按钮，不再接受玩家撤回，避免旧的就绪响应关闭一个已经恢复游玩的会话。原生超时或关闭失败仍能按票据撤回就绪状态，使页面恢复操作。

### 已有写入的只读状态与界面

游戏 `exit-status.ts` 只显示应用提供的当前阶段、只读写入摘要和全局待交付批数。面板将“本页已发起保存”“全局成果提交”“宿主关闭确认”分开；手动槽位名称来自原发起目标，偏好只标明各自类别，不随着后来选名改变。显示的是待处理操作和事实批数，不猜字节进度、百分比或剩余等待时长。全局就绪仍须原 `flush()` 成功且无待提交项，页面准备完成仍继续等待本张原生票据。

界面沿现有海绿色样式，说明/列表可滚动，重试和取消按钮独立留在下方，小高度缩紧留白。退出期间才订阅，取消、原生撤回及页面销毁释放原订阅并失效迟到更新；完成后尚未关闭的页面继续保持原暂停/输入禁用。渲染失败独立显示，不改变写入或退出结果。没有新增强制关闭、自动存档、偏好保存、进度捕获、宿主消息或持久格式。

### 本次请求与原生关闭

共享桥升级为 `haifeng.host-bridge/3`，新增退出处理器和按正整数标识的退出票据。包清单仍为 `haifeng.game-package/2`，明确登记新桥；Windows 准备记录 `/2`、Android 准备记录 `/3`（额外核对文件记录桥模板）均登记基础桥。旧桥 `/2` 的游戏包和 Android `/2` 准备输入须重新构建或准备，不修改剧情、内容修订算法、进度或全局记录格式。

`beginExit(id)` 对相同请求幂等，返回 `id/status`。处理器异步完成才进入 `ready`；取消通过该请求的 `AbortSignal` 撤回。旧请求、旧页面或旧 WebView 的结果不能用于关闭后来的页面。桥初始的无写入阶段允许退出，内容尚未载入时按钮保持禁用；应用安装正式处理器后，所有正常退出都经上述写入流程。

Windows 拦截 `CloseRequested`，单独任务轮询本次票据，确认 `ready` 后关闭该窗口；相同窗口的重复关闭不会叠加任务。Android 第二次标题页返回启动同样的请求，重复返回改为取消；游玩中返回仍只处理菜单与弹层。

两端等待上限均为 30 秒。超时、无效响应或消息失败保留窗口并尝试取消本次票据；超时不证明存储已失败或完成，也不授权强制关闭。Windows 原生错误当前记入诊断输出，Android 显示本地提示；页面收到取消后恢复本次关闭前的输入和暂停归属。若页面投递本身持续不可用，无法承诺取消及时送达，页面可能仍保持退出暂停。

不调用旧存档接口，不进入另一解释器，不上传玩家数据，没有改变系统退出/强制结束行为。未实现强制关闭时的磁盘日志、正常退出后文件级备份或系统回收后的自动恢复点。

## 结局卡片

### 旧行为与保留范围

旧 `海风与布丁/player.js` 的 `showEnding(name)` 在对白后达成结局，显示名称、新结局提示、收藏进度及返回标题，插件可追加按钮。旧卡片基础样式位于同目录 `index.html` 的 `#endcard`：黑色覆盖、居中内容、46px 标题、8px 字距、16px 状态、18px 按钮和 18px 间隔。

新实现保留名称、收藏进度、手动离开及上述基础外观关系。卡片使用舞台内受限覆盖，长内容和小窗口可滚动，标题随共享比例缩小并保留可读下限，按钮至少 44px 高；横竖屏及编辑预览共用同一样式。未新增美术、声音、自动回标题或结局音乐，也不决定最终框架或完整正式界面。

旧函数将显示、解锁写入和计次混在一起；当前由唯一核心产生结局事实、全局仓库幂等提交、卡片只显示结果。重绘卡片、重试记录、返回标题和鉴赏均不重新达成结局。原插件结局按钮、手账及正式聊天解锁尚未迁移，不据旧插件注册开放联网入口。

### 共享显示契约

`packages/player/src/web/ending.ts` 的 `EndingPanel` 挂在传入舞台，消费 `SessionView` 及显式 `EndingRecordState`：

| 输入 | 显示与边界 |
|---|---|
| 非终态或已销毁 | 清理隐藏卡片，不自行判断该节点是否结局 |
| `script-end` | 显示“本段结束”，明确没有新增结局记录；不能冒充作者结局 |
| `pending` | 显示结局已达成、全局记录正在保存，不显示解锁已保存 |
| `failed` | 显示失败信息；有应用重试能力时显示“重试保存结局记录” |
| `committed` | 显示已保存及当前内容目录中的已收集/总数；仅 `SessionView.newEnding` 已确认时显示新结局提示 |
| `preview` | 显示调用者提供的隔离说明，不称为玩家解锁或通关记录 |
| `unknown` | 明确未确认保存，不由旧缓存、当前投影或到达节点猜成功 |

卡片没有存储、剧情核心、全局仓库、模型供应或任意插件接口。显示使用 `textContent`，结局名与错误文本不执行 HTML。离开和重试回调只交付本次原 `SessionToken`，应用重新核对当前会话/呈现/步骤及终态；旧卡片监听在清理时取消。

相同终态更新只调整状态与禁用属性，不重建按钮、重置滚动或重复改写相同播报文字。准备读档/开局、正常退出及 `operation/exit` 暂停禁用卡片操作；菜单覆盖继续沿应用管理，不解除其他暂停。后台、声音焦点和终态声音生命周期仍由共享会话及原表现处理，卡片本身无计时器或声音。

### 第一话的事务关联

`apps/game/src/main.ts` 在接到真实结局事实时，为原批次记录会话代次、表现身份、结局 ID 和初始待提交状态。已有全局写入失败时，排在队列中的结局也明确显示未保存，不等待一个不会自动发生的提交。

`PlayerRecordWriter` 原提交回调提供该批次的回执及已提交记录，只有与本次结局关联的批次才能把卡片状态改为 `committed`。收藏进度按该已提交记录和当前内容结局目录计算；旧修订中暂时不在目录的解锁仍保存在全局数据，不因此删除，但不虚增本目录的分子或分母。

首次解锁继续沿原 `ending-unlocked` 路径核对当前终态和首次回执，不因卡片重绘再发声音或新增事实。再次真实达成已有结局依原规则记录本次通关，卡片显示已保存，但不称为首次解锁。退出期间提交可以更新已保存状态，原一次性声音反馈仍按退出门控跳过，不在取消退出后补播。

全局提交失败会保留原批次并更新当前未提交卡片。卡片重试与页面原“重试保存全局记录”共用 `flushRecords()`：先显示待提交，再重试原队列，成功后由原提交回调确认。没有重新推进结局节点、重新生成事实 ID 或另写进度档。开局、读档、回退、鉴赏及正常退出已有的事实等待也使用这个状态接线，原写入顺序不变。

“返回试播标题”可在记录等待或失败时使用；它只离开当前会话，待提交事实仍由原队列持有，标题页保留全局失败/重试状态。随后新开、读档、鉴赏和正常退出仍按原流程先处理必要事实。离开前未写成功的数据只在本页内存，不承诺强杀、刷新、崩溃或浏览器清理后的保留。

卡片不是持久通知：返回标题、换会话、读档及销毁会清理本次关联显示。旧批次迟到提交可更新全局成果，但不能把后来会话变成新结局或覆盖它的卡片。鉴赏仍从主页重读已提交全局记录；卡片不直接赋予聊天或角色权限。

### 样例与编辑预览

限时样例如继续走到结局，显示“本次游玩不写全局解锁或通关次数”的说明，不创建正常游玩的结局提交状态。它的初始条件仍是声明初值，不能据结局卡片认定真实第五话路线已验收。

`apps/editor/src/preview.ts` 复用同一 `EndingPanel` 和样式，只传 `preview` 状态，离开按钮为“停止预览”。按钮核对原预览令牌，停止/换预览清理卡片与旧监听，不写作者源、玩家成果、进度或聊天。普通脚本末尾仍与作者定义结局分开显示。

## 后置与待决事项

存档缩略图尚未实现。已讨论的方向是保存时从原检查点合成静态小图，绑定整份进度身份、允许图像生成失败而进度独立可存；持久化及联合提交方案仍未决定。不能直接向严格的 haifeng.save/1 塞 thumb 字段，也不能把两次独立写入声称为原子提交。历史完整方案可由迁移映射追溯。

正式回退容量、跨选择/跨结局体验、正式读档语音默认与异常退出自动恢复尚未确定。当前正常退出只协调已经发起的写入，不自动捕获新进度，不处理系统强杀后的自动恢复。
