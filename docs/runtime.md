## 纯剧情核心

### 终端试播

在仓库根，使用[规定的 Node 环境](<README.md#commands>)：

```powershell
npm run story:dev
```

入口读取同一个作者源和 M1 转换实现，资源缺项会报错，不回落到旧解释器。没有浏览器、媒体或开发后端；不会写正式存档/玩家记录，也不会生成内容发行目录。

简短试用：

1. 输入 `walk`，直到出现选项；它只提交核心的“呈现完成/继续”，不自行计算分支。
2. 输入 `save`，再 `choose 1`，查看变量及目标节点。
3. 输入 `again` 重发同一操作，应该拒绝旧步骤；不会再次结算。
4. 输入 `load`，应恢复保存的位置和变量，无进入/结局新事实；这是内存逻辑快照，不包含场景播放位置和选择剩余时间。
5. 在限时选择处可手动 `timeout`，核心选择内容中指定的默认项；终端不实际倒计时。

`next` 在呈现阶段只确认“呈现完成”，下一次才请求继续。`save` 的快照退出后丢失；`walk` 最多 10000 次操作就停止，避免内容无交互循环占住终端。

### 公开接口与状态归属

创建方式为 `createStoryRuntime(content, playerProjection)`，返回 `runtime` 和首次进入的 `initial` 结果。`content` 必须来自当前校验转换器；不接受用类型断言冒充已校验的外部规范化 JSON。

| 接口 | 含义 |
|---|---|
| `view()` | 返回可重读的状态副本；不产生事实，不允许修改内部变量 |
| `dispatch(command)` | 串行消费者提交 `presented/advance/choose/timeout`，每条带当前 `step` |
| `snapshot()` | 导出已执行进入动作的逻辑状态，不包括运行回调、计时器、音频句柄 |
| `restore(unknown, currentPlayer)` | 校验作品、格式、修订、节点、变量及保存时上下文，再显式采用当前全局投影；成功后整体采用，失败不部分改状态 |

M4 新增独立函数 `inspectStorySnapshot(content, unknown)`：用相同核心校验规则返回快照副本与描述，不执行任何节点进入动作、分配到现有运行实例或发事实，供[存档封装](<storage.md#saves>)读取外部数据。

`restoreStoryRuntime(content, snapshot, currentPlayer)` 创建从已生效快照继续的运行实例，初始结果为 `restore`、事实为空；不先开局再跳过去。两条恢复接口都必须由调用者传入当前[全局玩家投影](<storage.md#records>)。保存时的投影仍用于校验原快照，不作为全局权威；应用不从进度槽位写回周目或解锁记录。当前投影导致可见选项改变时，核心重新描述 `ready/choosing` 阶段，不重算进入动作。

阶段为 `presenting → ready/choosing → 下一节点/ended`。进入动作只在真实进入执行；选项动作在进入目标之前执行。命令采用候选状态计算，成功后才整体替换；内容错误不切换解释器。

对白填充现复用 `story-model/src/text.ts` 的 `fillDialogue()`，与[只读引用查询](<editor.md#references>)共享原 `{变量名}` 识别语法。仍只在对白中替换已生效剧情变量及显式玩家投影，未知名字保留原文；说话人和选项文字不插值。查询不持有运行实例或执行任何动作，本次提取不改变快照或内容格式。

每次接受命令或恢复都会换一个步骤编号；旧步骤回调与重复结算被拒绝。编号只保证**当前运行实例**内唯一，M3 游戏会话仍需代次取消，不能让旧运行实例的回调进入新实例。

结果分别提供可重读视图、本次 `entered/chosen/ending` 事实及 `enter/restore` 表现要求。恢复不发进入、选择或结局事实，不调用进入动作。事实尚未持久化，不承诺跨进程或跨存储“恰好一次”。

`RuntimeResult.variableChanges` 额外描述成功命令已经执行的动作分组：`origin: choice/enter`、原节点、每个变化变量的 `name/before/after`，选择组另有稳定选项 ID。先完成选项组，再完成目标进入组，分别记录净变化；不能以整个跳转的总差抵消这两个阶段。只有候选状态整体提交成功才提供分组；初始化、拒绝和恢复为空数组。这是给[剧情声音反馈](<player.md#feedback>)的只读结果，不是新动作、持久事实或逆向回退算法，不改快照/内容格式。终端成功操作也显示非空分组。

## 共享游戏会话

### 会话的公开接口

`createGameSession` 接收已校验内容、当前只读玩家投影、宿主单调时钟、表现适配器、按范围隔离的已读集合和结果回调，返回 `view / send / dialogueHistory / rollbackTargets / rollback / captureCheckpoint / dispose`。可选 `resume` 要求显式提供检查点与本次语音恢复方式，直接从已生效进度创建核心，不先进入开局节点。可选 `rollback: {capacity}` 显式开启当前会话的有界检查点历史。

- `send` 是点击、选项、菜单/后台暂停、自动和快进的统一串行入口。
- 自动与快进互斥：开启自动关闭快进，请求开启快进关闭自动；未读或选择仍能拒绝实际快进。按键临时所有权由浏览器输入层管理，不进入检查点。
- `auto-wait` 意图更新后续普通自动等待倍率，不重建当前计时；应用通过独立[阅读偏好](<player.md#preferences>)提供，未传初值时使用作者默认。
- 可选 `readoutEnabled` 和 `readout` 意图控制后续[话末存档点数值显示](<player.md#readout>)，缺省采用作者 `showStats`，未设为关闭；每次呈现固定显示正文，普通自动等待使用同一文字长度。只向表现传正文副本，核心、回看、槽位摘要不变；改变开关不重置当前或恢复剩余时间。
- 可选表现能力 `interaction(feedback)` 消费[选择与存档提示音](<player.md#feedback>)：选择出现按一次访问的首次就绪发出，确认/超时来自实际接受的核心事实；循环只跟随当前选择与暂停，不进入检查点或替代计时。
- 可选 `end(context)` 结束进入表现并保留终态反馈，终态通过表现的 `setPaused()` 接续生命周期；会话只在匹配的已提交通关回执下接受 `ending-unlocked`，更新本次 `SessionView.newEnding`，不重发结局事实或改写进度。
- 每个可推进操作携带 `{session, epoch, step}`，分别识别运行实例、当前呈现和核心步骤。应用用递增整数分配会话代次，不用墙钟。
- 表现只通知场面就绪、文字完成、语音结束或媒体问题，不持有核心的可写引用。场面资源未就绪时单独暂停有效时间，不能让重试消耗选择时间。
- 每次换节点或重建场面取消旧 `AbortSignal`、文字/选择/自动等待、播放句柄；无法取消的媒体加载仍须核对有效信号。
- 暂停原因分别记录，关闭菜单不会误解除后台或宿主暂停。有效时间不把后台时长补算进去。
- 可选 `initialPauses` 在首次呈现前采用当前宿主/后台状态。读档及回退准备使用 `operation` 原因，不能因准备完成而解除原生窗口的 `host` 暂停；[Windows 接线](<delivery.md#windows>)只更新生命周期，不发推进命令。
- [正常退出](<storage.md#exits>)使用独立 `exit` 原因，等待已有写入和全局事实；退出票据取消只解除本次暂停，重试不重新捕获进度。正常关闭、自动存档和系统回收恢复仍是不同能力。
- 媒体重试重建同一个已生效节点，不再次进入、加变量或发剧情事实；选择剩余时间沿用，不重置倒计时。
- [对白回看](<player.md#history>)返回当前会话最近 300 条文字/语音及 `visitId` 副本；独立 `history` 暂停不影响菜单、后台或宿主的暂停归属，打开与关闭对话框不推进剧情。条目回退须显式选择本次范围/语音，只按当次访问对应仍保留的检查点，继续交回相同的 `rollback()`。
- `rollback(request)` 通过同一队列校验目标、本次跨选择策略、语音方式和当前全局投影；采用后更新核心步骤及呈现代次，截断未来路线历史，保留全局成果。当前只支持稳定非结局阶段，捕获失败通过 `SessionView.rollbackIssue` 显示，不补造数据。

`ActiveTimer` 只依赖 `{now, schedule}`，用于可暂停的延迟和倒计时；剧情核心仍不读取时钟。文字首次点击只补全当前句，不顺带推进；自动不会代答，快进遇选择或未读停止。已读由应用接到独立全局记录，正式发行记录使用 game/main。

### 表现与存储的归属

共享表现只报告场面就绪、文字/语音完成和媒体问题，不决定分支或变量。持续配乐/环境声由混音器保持，同曲继续、换曲与停奏分别处理；单次语音、音效、文字与动画归本次呈现，取消或恢复不重新发进入事实。

输入、全屏、镜头/角色/氛围、偏好、收藏与回看详见[游戏表现](<player.md>)。检查点、槽位、全局事实与正常退出详见[存档与成果](<storage.md>)；随包读取、原生生命周期与声音许可详见[交付与平台](<delivery.md>)。任何一层读取或表现失败都不能切换解释器。

### M4 接续

会话现新增 `captureCheckpoint(token)`，通过同一串行队列捕获稳定检查点；`SessionView.canCheckpoint` 表示当前切片是否可捕获，`Playback.capture` 提供分离的声音数据。过时步骤、未就绪场面及结局明确拒绝。格式、覆盖范围和存储契约见[检查点与存储](<storage.md#saves>)。

试播页增加手动保存、按入口查看与实际读档，数据只进入各自开发/预览槽位，第一话全局成果另外保存。[命名槽位与目录](<storage.md#slots>)支持各入口独立选择、每页 20 条只读摘要及损坏/不兼容诊断，原 `manual` 继续保留；选择或浏览不恢复进度，保存及其重试固定原目标。读档与会话内回退采用当局变量与有效计时、刷新当前全局投影，不回滚已解锁结局、CG 和周目；只读查看、对白回看和鉴赏不产生新事实。回退不自动写手动槽位，也不跨新开、读档或页面离开保留历史。
