# 存档缩略图：现有接口与待确认边界

2026-10-24 从干净的 `8d9a280` 接续 M5。本片只读取相关源码并明确接口与兼容差异，没有实现缩略图、扩展协议、修改存档或运行验证。以下“建议”须经用户确认才能成为实施契约；不改变现有[存档](saves.md)与[槽位](slots.md)规则，也不是新的总体重构方案。

## 已有事实

| 实际来源 | 当前提供什么 | 对缩略图的限制 |
|---|---|---|
| `海风与布丁/player.js` 的 `makeThumb(l)` | 背景与立绘按作者坐标合成 320×180 JPEG，立绘带原滤镜/翻转；失败返回 null | 不是 DOM/全屏截图，不包含对白、选项、菜单、动态演出帧或声音 |
| 旧 `miniScene` / `showSlots` | 旧档有 `thumb` 则展示图片，否则按旧节点重建小场面 | 读取的是旧记录/节点，不能作为新档兼容实现直接调用，不能按旧数组下标补位置 |
| `GameSession.captureCheckpoint()` / `sampleCheckpoint()` | 同一串行操作捕获已生效核心快照、音轨位置与剩余有效时间 | 不含像素、DOM 或图像；捕获支持的稳定阶段不因缩略图扩大 |
| `WebPresentation` 的 `Playback.capture()` | 场面/文字就绪后捕获声音状态 | 不提供画布或截图，不能在新的异步图像流程中再读后来场面 |
| `inspectGameCheckpoint()` | 用同一核心校验同修订快照，并返回其完整目标场景 | 可以据原检查点描述静态目标；不能执行进入动作、采用进度或重新计算路线 |
| `SaveRecord` / `SaveRepository.inspect()` | 严格的 `haifeng.save/1`：范围、槽位、时间、检查点 | 未登记图像字段；`knownFields` 会拒绝额外字段，不能直接加 `thumb` 后声称旧读取器兼容 |
| `AtomicSaveStore` / `IndexedDbSaveStore` | 进度单条 `read/replace/scan`，同一事务提交进度替换 | 没有图像附属记录或图文联合提交接口；先后写两次不构成原子提交 |
| `SaveSlotSummary` / `SaveSlots` | 每页 20 条的文字定位、阶段/剩余选择时间及错误诊断 | 没有像素、图像身份或完整场面；目录摘要不够直接生成原版缩略图 |

内容构建将实际资源摘要纳入修订，但当前保存只接受匹配内容修订；这不授权更改旧档兼容范围。当前唯一作者源、资源 ID/顺序、新旧记录隔离及开发/正式/预览范围保持不变。

## 需要选定的持久化方向

| 方向 | 接口与兼容影响 | 使用代价 |
|---|---|---|
| 图像放入新的进度封装版本 | 扩展保存/校验/摘要与读档分派；新读取器须明确支持现有 `/1`，旧读取器拒绝新封装；键/目录迁移需同步决定 | 图文天然同一载荷，但进度协议及旧版本往返都受影响 |
| **保留 `/1`，增加同槽位图像附属记录（建议）** | 进度载荷、既有键、数据库版本及对象仓库保持；扩展联合写入/读取，附属图使用独立受限前缀并绑定整份进度身份 | 需要防止旧图配到后来进度，并管理附属数据的独立诊断与空间上限 |
| 浏览目录时从已校验进度重建静态小场面 | 不保存像素，但须扩展目录显示输入并按页加载实际素材；旧记录也可生成 | 展示的是本次重建结果，目录需要素材可用，不能宣称保存时图像已经留存 |

建议选择第二种，保留旧版“保存时合成一张小图”的用途，同时让现有 `/1` 进度仍可独立读取。它是新增捕获与持久化能力，当前没有据此新增格式标识、字段、存储键或模块。

## 建议确认后的交付行为

1. **捕获与画面内容。** 只随现有显式手动保存触发。在同一次请求捕获原入口、槽位、时间和检查点后，根据该分离检查点的已校验目标场景合成背景/立绘，沿旧 320×180 JPEG 用途；不截取屏幕上的菜单、正文、选择、玩家设置或过渡副本，不记录动态帧。合成过程不创建会话、播放器、音轨或网络请求，也不修改当前有效计时。
2. **图像可失败。** 图片不可用、解码、画布或编码失败时，本次进度仍可按原规则保存，并明确显示无缩略图及原因；不临时画入另一节点或使用当前舞台补图。存储事务本身失败则仍报告保存失败并保留旧记录，不能悄悄拆成部分成功或自动换一种载荷重写。
3. **图文一起提交。** 图像附属记录绑定作品/范围/槽位及整份原进度的确定身份，不能只用节点 ID 或显示时间匹配。浏览器继续使用当前数据库版本 `1` 和已有 `slots` 对象仓库，附属图通过独立受限前缀隔离；不新增对象仓库或升级数据库，否则原 `indexedDB.open(..., 1)` 读取器也会失去打开能力。进度和本次图像结果（含无图结果）在同一个读写事务提交；有图旧槽位被无图新进度覆盖时，也在同一事务替换旧图关联，不能保留一张看似属于新进度的旧图。
4. **重试不重采。** 持久化失败后的原操作重试复用首次捕获的检查点、时间、图像或无图结果，不读取后来会话、所选槽位、资源状态或屏幕重新合成。用户下一次显式“保存”才是一份新请求；不增加自动保存、翻页补图或离开补图。
5. **现有新档继续可用。** 已有 TypeScript `/1` 记录没有附属图时，显示无缩略图，照常选择/查看/读取；不批量补写或迁移。旧 TypeScript 读取器仍只读原进度键/载荷；若它后来覆盖进度、没有更新附属图，新读取器必须按整份进度身份识别不匹配，显示无匹配图诊断，不采用旧图。
6. **图像不授予恢复权限。** 目录仍先完整校验进度，再读取本页对应附属图并核对绑定；不兼容/损坏进度保留原诊断，不因为存在图像而放行。图像缺失、损坏或不匹配单独说明，不把可读进度变成损坏档，也不静默修复/删除它。图像字段、编码、尺寸和字节上限须校验，具体格式/限额在确认方向后的实现片登记，不接外部 URL。
7. **只读显示生命周期。** 保留分页与原选择边界，仅处理当前页图像；换页、切入口、关闭、重新打开和页面离开使原加载/解码失效并释放图像来源。看图不创建或采用剧情，不写成果、偏好、预览或聊天；图像也不进入核心/回退检查点。

这些建议适用于目前的隔离开发进度及限时样例；不切换正式 `game` 范围、不改变作者源或原生发行入口。旧 JS 存档仍按既有隔离规则处理，这里的“旧记录可读”只指当前已支持的 TypeScript `/1`，不承诺迁移旧播放器数据。未来原生文件存储须实现同样的图文提交/失败保护，不能把两个独立文件先后写完当成已满足该能力。

## 当前待确认项与后续切片

需要用户确认的产品行为集中为：**是否采用“保存时合成、同槽位附属持久化；生成失败仍存进度；已有 TypeScript 档无图继续可读”的方向。** 附属图格式与大小校验属于确认后的实现细节，不能把本页建议写成已经批准或已经接入。

确认后可依次实现捕获/校验、图文原子存储和分页显示，并在每次接口变化时维护对应说明；原检查点/玩家成果/偏好/聊天/宿主协议保持各自边界。测试仍按用户安排留到重构末尾，当前没有执行命令或产生运行结论。

统一测试需覆盖：同一原检查点与原目标绑定；异步合成期间继续/换会话；原图失败后无图保存；事务失败保留旧图与旧进度；原载荷重试；旧读取器覆盖后拒用旧图；旧 `/1` 无图可读；图像损坏与进度损坏诊断分开；换页/关闭的迟到解码；两端离线/存储故障及清理。列出这些情景不授予现在运行验证的权限。
