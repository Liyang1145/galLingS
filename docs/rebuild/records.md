# 全局玩家记录

2026-10-23 用户明确：周目、结局等解锁成果全局保存，解锁后从主页进入鉴赏；读档只恢复当次游玩的进度，不回滚全局成果。这是本页规则的产品依据，不是把原方案建议当成已确认决定。

## 已编写的共享实现

`packages/player/src/records.ts` 提供 `PlayerRepository`、`PlayerRecordWriter`、只读投影和鉴赏目录。数据使用独立的 `haifeng.player-records/1`，按作品及 `development/preview/game` 范围保存，不嵌入某个进度槽位。

| 数据 | 归属与规则 |
|---|---|
| 当前节点、当局变量、阶段和剩余有效时间 | 进度检查点，随读档恢复 |
| 已读节点、已解锁 CG、已解锁结局 | 全局玩家记录，按稳定 ID 保留，不随进度覆盖 |
| 通关事实与周目 | 全局玩家记录；沿用旧规则：周目为通关次数加一 |
| 结局数 | 全局已解锁结局的种数，不是当前进度达到的结局数 |
| 音量、阅读及显示等偏好 | 不在以上两类中；[声音与阅读偏好](preferences.md)已独立接入，窗口/全屏等其余设置尚未迁移 |

核心快照中的 `player` 是捕获当时的只读求值上下文，不是全局记录的权威副本，不能用它覆盖当前成果。实际读档应显式传入当前已提交的全局投影。

## 事实、计次与失败保护

新记录只消费唯一核心实际产生的 `entered/ending` 事实；`chosen` 不单独增加成果。已读按节点 ID 合并；CG 依旧播放器的 `isCG` 规则从进入节点的背景取得，保留 `previewExcluded`、显式 `cg` 及名称前缀规则；结局按稳定结局 ID 去重，保留首次解锁时间。

通关计次延续旧播放器每次实际达成结局增加一次的行为：新核心每个被接受的结局转换记一条通关事实。同一批事实用固定交付 ID 重试，已提交的事实不会再次加次数；读档、检查点查看、主页和鉴赏重绘都不产生通关事实。读档后重新实际走到结局属于新的结局转换，不把它与一次存储重试混同。

浏览器存储适配器在同一个读写事务中读取、校验、合并并写入全局记录，避免多个标签页用旧副本覆盖彼此成果。结局解锁与对应通关事实一起提交。损坏数据明确拒绝，不退回空记录并覆盖。

`recordWithReceipt(batch)` 在同一事务中额外确定本批实际新加入的结局，提交完成后返回 `{records,receipt:{batchId,newEndingIds}}`；失败不返回回执。已提交批次重试及再次达成已有结局，首次解锁列表为空；通关计次仍按原事实 ID 幂等。同一批内多个相同结局只形成一次新解锁，跨页面以事务读到的当前记录为准。回执不持久保存，不改变 `haifeng.player-records/1`，既有 `record(batch)` 仍返回记录。

`PlayerRecordWriter` 保留未提交批次，失败后停止自动重试并报告，显式重试使用原交付 ID。它不是磁盘事务日志：浏览器未能写入时，待提交批次仍只在当前页面内存，不能冒充已持久化。

显式[Windows 文件试用](native-storage.md)与[Android 文件试用](android-storage.md)通过同一 TS 适配器的存储代次 CAS 调用原校验/合并，不在原生重做规则；原格式、范围和批次 ID 保持。`NATIVE_STORAGE_UNCONFIRMED` 表示可能已提交但尚未确认，不能宣称未写入或确认首次解锁；重试仍用原批次，已提交批次不会重复计次或补发首次解锁回执。默认 IndexedDB 不迁移，两端接线未运行或验收。

提交回调现为 `(records, receipt)`，应用将首次解锁结果与原结局批次的本页会话代次、表现身份及当前终态匹配，才尝试[新结局声音和显示反馈](feedback.md#首次结局解锁与终态反馈)。它不是新的剧情命令或第二次计次；静音、旧会话、页面离开和退出协调可以跳过反馈，不能回滚已保存成果。回执不构成持久通知或聊天解锁规则，也不承诺提交后崩溃仍能播放提示。

记录不按内容修订分槽，稳定 ID 的成果可跨修订保留；暂不在当前内容中的记录仍保留，鉴赏只展示当前目录中可定位的条目。这个保留行为不意味着进度检查点可以跨内容修订恢复。

## 接入状态

共享记录与 IndexedDB 原子合并实现已编写，独立试播页已接入：

- 第一话使用 `development/normal-entry` 的全局记录，开始和读档前先提交本页待写事实，再读当前记录生成投影。已读跨重开、刷新和进度槽位保留。
- 限时样例固定使用声明初值、周目 1、结局数 0，只有隔离的内存已读，不产生全局鉴赏或计次成果。
- 第一话真实进入/结局事实自动排队保存；只有事务完成才显示全局记录已保存，失败显示重试入口。手动保存进度先等必要全局事实提交，再写进度槽位；两步不承诺跨事务天然“恰好一次”。
- [结局卡片](endings.md)把当次结局批次绑定原会话/表现/结局，待提交、失败、已保存分开显示；只有原批次的提交摘要能确认本次已保存和收藏进度，首次仍由原回执确认。重试原队列不重新结算，返回标题保留待写事实与原全局重试入口；限时样例和编辑预览只显示隔离说明。
- 第一话主页的“鉴赏”读取已提交全局记录，显示通关次数、周目、结局列表及可点开的大图；锁定条目不显示未解锁画面。打开鉴赏不会跳转剧情、重放结局或增加次数。
- [鉴赏图片生命周期](gallery.md)已接独立只读面板：缩略图/大图各有原资源失败重试，锁定条目不请求图片，关闭或换图使旧加载/解码失效。图片错误不改成果，重开重新读取当前记录；未运行或视觉验收。
- 从旧进度继续或[会话内回退](rollback.md)时只采用进度状态，周目和结局数来自当前全局记录，已经取得的成果保持原值。回退不删除全局已读，不产生进入或结局事实。
- [通关后入口](chat.md)通过 `readCompletions()` 只读获取已提交的作品/范围、解锁结局及每次通关引用，再按用户选择重新确认。待提交批次、进度快照及预览不能用来准备上下文；当前记录未保存当次路线变量、历史内容修订或每次通关时间，不补造这些信息。此接口不改变记录格式或计次，也不等于正式聊天已解锁。

代码编写及页面接线不代表已经运行或通过验收。没有新增提前解锁结局、跳过路线或修改成果的调试入口。

没有读取或迁移旧 localStorage，没有改正式入口、旧资源、原生宿主或 CI。旧档迁移、手账归属、正式回退容量和跨结局边界仍不由本模块决定。
